# 소크라테스식 인터뷰 스킬

## 핵심 원칙

- 답을 주지 마라. 답으로 이끄는 질문을 던져라
- "왜?" 대신 "무엇이 그렇게 생각하게 만드는가?"로 물어라 — 덜 대립적이고 더 깊다
- 구조(카테고리 채우기)보다 긴장 지점(모순·회피·가정)을 따라가라
- 불편한 질문을 두려워하지 마라

---

## 1단계: 진입 시 결정할 것

대화 맥락에서 파악하라:

1. **도메인** — 제품/기능, 아키텍처/코드, 개인적 결정, 기획, 리서치 중 어느 것인가
2. **렌즈 3~4개 선택** — `references/lenses.md` 참조. 도메인별 권장:

| 도메인 | 권장 렌즈 |
|--------|-----------|
| 제품/기능 | 이해관계자, 최소 버전, 중단 기준, 확신 수준 |
| 아키텍처/코드 | 의존성, 연쇄 효과, 시간 지평 충돌, 최소 버전 |
| 개인적 결정 | 누구의 욕망, 2차적 이득, 사전 부검, 과거 패턴 |
| 기획 | 기회비용, 의존성, 확신 수준, 기각된 대안 |
| 리서치 | 네거티브 공간, 사다리타기, 확신 수준 |

---

## 2단계: 질문 물결

### 형식 규칙
- 질문들을 **한 메시지에 번호 매겨** 제시
- 각 질문 앞에 카테고리 라벨: `[목표]`, `[리스크]`, `[가정]` 등
- 각 질문에 A) B) C) 선택지 + 마지막은 항상 **"기타(직접 입력)"**
- 부분 답변 허용: "1-B, 2-기타: …" 형식으로 자유롭게

### 물결 규모
| 물결 | 질문 수 | 초점 |
|------|---------|------|
| 1 | 3~5개 | 목표, 맥락, 제약 |
| 2 | 2~4개 | 엣지 케이스, 충돌, 의존성 |
| 3+ | 1~3개 | 모순, 암묵적 가정, 미탐색 시나리오 |

---

## 3단계: 물결 사이 중간 요약

물결마다 다음 구조로 요약하라:

```
### 이해한 것
- [핵심 사실 3~5개]

### 가정
- [검증됨] …
- [추정] …

### 리스크 → 다음 질문
- 리스크: [설명] → 다음 물결 질문: [구체적 질문]
```

**선택된 렌즈 적용**: 매 중간 요약에서 1단계에서 선택한 렌즈로 다음 질문을 생성하라.
렌즈 상세 내용은 `references/lenses.md` 참조.

---

## 4단계: 커버리지 점검 (최종 요약 전 필수)

```
주요 주제는 다룬 것 같다. 내가 다 물어봤나?
A) 다 다뤘어, 요약해줘
B) 안 다룬 주제가 있어 (무엇인지 알려줘)
C) 이미 다룬 것을 더 깊이 파고 싶어
```

B 또는 C → 해당 방향으로 물결 추가 → 다시 점검. A가 나올 때까지 반복.

---

## 5단계: 최종 요약

```markdown
## 수집된 그림: [주제]

### 핵심 사실
- [확실히 아는 것]

### 결정과 선호
- [사용자가 선택/결정한 것]

### 가정 (검증됨 / 미검증)
- …

### 리스크와 완화책
- 리스크: [설명] → 완화책: [행동]

### 미해결 질문
- …

### 다음 단계
- [지금 당장의 구체적 행동]
```

---

## 종료 기준

다음 중 하나이면 멈춰라:
- 이해를 바꿀 만한 질문을 더 이상 만들 수 없을 때
- 사용자가 "그만"이라고 할 때
- 모든 가정이 검증되고 리스크가 질문으로 전환되어 답변됐을 때

10~15개 질문이 정상. 사각지대가 있으면 20개도 괜찮다.

---

## 흔한 실수

| 실수 | 올바른 방법 |
|------|-------------|
| 1물결 후 멈춤 | 진짜 통찰은 2~3물결에 있다 |
| 한 메시지에 10개 덤프 | 물결당 규칙 개수 지켜라 |
| 선택지 없는 추상 질문 | A) B) C) + 기타 형식 필수 |
| 카테고리 채우기 | 긴장이 드러나면 카테고리 버리고 거기를 파라 |
| 리스크를 질문으로 안 바꿈 | 요약의 각 리스크 → 다음 물결 질문 |
| 답을 줌 | 발견하게 도와라, 알려주지 마라 |
| 커버리지 점검 없이 끝냄 | 최종 요약 전 반드시 확인 |
