# Chapter 29. 나만의 시스템 완성
> 개인화 · 진단 체크리스트 · 시스템 문서화

---

## 0) 연결 고리 (Bridge)

30일 챌린지를 완료한 여러분은 이제 옵시디언을 일상에서 사용하고 있을 것입니다.  
이 챕터에서는 지금까지 쌓은 시스템을 **진단하고, 정제하고, 문서화**하는 방법을 다룹니다.  
좋은 시스템은 완성이 없습니다. 지속적으로 개선됩니다.

---

## 1) 보관소 건강 진단 체크리스트

아래 항목을 점검하고 점수를 매기세요. (각 항목 1점, 총 30점)

### 구조 (Structure) — 10점
```
□ PARA 4계층 폴더가 명확하게 구분되어 있다
□ Inbox는 항상 5개 이하로 유지되고 있다
□ 모든 활성 프로젝트에 전용 폴더가 있다
□ 완료된 프로젝트는 Archives로 이동되어 있다
□ templates/ 폴더에 최소 5개 이상의 템플릿이 있다
□ 첨부 파일이 assets/ 폴더에 정리되어 있다
□ 폴더 깊이가 3단계 이하로 유지되고 있다
□ 이름 없는 "Untitled" 파일이 없다
□ 전역 속성 뷰에서 불일치 속성이 없다
□ .gitignore 또는 동기화 제외 파일이 설정되어 있다
```

### 연결 (Connection) — 10점
```
□ 모든 노트에 최소 1개 이상의 내부 링크가 있다
□ 허브 노트가 존재하며 주요 노트들과 연결되어 있다
□ 태그 계층 체계가 일관되게 적용되어 있다
□ 그래프 뷰에 고립된 노트가 거의 없다
□ 백링크 패널을 주기적으로 확인하고 있다
□ 독서 노트가 관련 개념 노트와 링크되어 있다
□ 프로젝트 노트에서 관련 자료 노트가 링크되어 있다
□ 링크 없는 언급(Unlinked Mentions)을 정기적으로 확인한다
□ 별칭(Aliases)이 필요한 노트에 적용되어 있다
□ 캔버스 또는 Excalidraw로 시각적 연결 지도가 있다
```

### 루틴 (Routine) — 10점
```
□ 매일 데일리 노트를 작성하고 있다
□ 주간 리뷰를 매주 실행하고 있다
□ GTD 다음 행동 목록을 매일 확인하고 있다
□ 새 정보는 즉시 Inbox에 캡처하는 습관이 있다
□ 독서 중 인상적인 내용을 즉시 기록하고 있다
□ 완료된 할일을 정기적으로 체크하고 있다
□ 보관소를 주기적으로 백업하고 있다
□ 플러그인을 정기적으로 업데이트하고 있다
□ 더 이상 사용하지 않는 노트를 Archive 또는 삭제하고 있다
□ 시스템을 개선할 필요가 생기면 즉시 반영하고 있다
```

**점수 해석:**
```
25~30점: 🏆 Expert — 완전히 자신의 것이 된 시스템
18~24점: ✅ Intermediate — 잘 작동하는 시스템, 세부 개선 필요
10~17점: 🔧 Beginner — 기초는 있지만 루틴이 불안정
0~9점:  🌱 Starting — 지금부터 하나씩 점검 시작
```

## 2) 개인화 전략

### 직군별 특화 설정

**개발자·엔지니어:**
```
강점 활용: Git 통합, 코드 블록, API 문서화
추천 조합:
  - Obsidian Git + GitHub 연동
  - 코드 스니펫 전용 폴더 (30-RESOURCES/code-snippets/)
  - Mermaid 다이어그램으로 아키텍처 문서화
  - Dataview로 기술 부채 추적
핵심 플러그인: Obsidian Git, Code Block Enhancer, Linter
```

**작가·콘텐츠 크리에이터:**
```
강점 활용: 아웃라인, 슬라이드, Publish
추천 조합:
  - 원고 초안 관리 폴더 구조 (draft/revision/final)
  - 슬라이드 플러그인으로 발표 자료
  - Obsidian Publish로 포트폴리오 공개
  - Excalidraw로 스토리보드
핵심 플러그인: Longform, Typewriter Scroll, Word Count
```

**연구자·학생:**
```
강점 활용: 제텔카스텐, Zotero 연동, PDF 주석
추천 조합:
  - 제텔카스텐 노트 번호 체계 (202401151200)
  - Zotero + Citations 플러그인으로 문헌 관리
  - PDF++로 PDF 직접 주석
  - 문헌 노트 → 영구 노트 파이프라인
핵심 플러그인: Zotero Integration, PDF++, Citations
```

**프로젝트 매니저·팀 리더:**
```
강점 활용: 캔버스 보드, Dataview, 팀 위키
추천 조합:
  - 프로젝트별 칸반 캔버스
  - 팀원 정보 데이터베이스 Dataview
  - Obsidian Publish로 팀 위키
  - 회의록 → 액션 아이템 자동 추출
핵심 플러그인: Tasks, Kanban, Projects
```

## 3) 시스템 문서화

모든 좋은 시스템은 문서화되어 있습니다. 내 보관소의 "사용 설명서"를 작성하세요.

**`시스템 안내서.md` 권장 구조:**
```markdown
# 나의 옵시디언 시스템 안내서

> 마지막 업데이트: {{date}}
> 작성자: {{name}}

## 보관소 구조
[PARA 폴더 설명]

## 태그 체계
[태그 계층 목록]

## 일일 루틴
1. 데일리 노트 열기
2. Inbox 확인
3. ...

## 주간 루틴
1. 주간 리뷰
2. PARA 업데이트
3. ...

## 노트 작성 원칙
[나만의 규칙 3~5가지]

## 사용 중인 플러그인
[플러그인 목록 + 용도]

## 주요 단축키
[자주 쓰는 단축키]

## 변경 이력
- 2024-01-15: 초안 작성
- 2024-02-01: PARA 구조 개선
```

## 4) 맺음말

> **"당신의 노트는 당신이 죽어도 살아있을 것이다."**  
> — 니클라스 루만 (제텔카스텐 창시자)

옵시디언은 단순한 노트 앱이 아닙니다. 당신의 생각, 배움, 통찰이 쌓이는 두 번째 뇌입니다.

오늘 작성한 노트 하나가 1년 후 전혀 다른 문제를 해결하는 열쇠가 될 수 있습니다. 10년 후의 나는 오늘의 내가 쌓은 지식 위에 서 있습니다.

이 책의 30챕터는 끝이 아닙니다. 시스템은 계속 진화합니다. 새로운 플러그인이 나오고, 더 나은 방법을 발견하고, 삶의 변화에 따라 시스템도 바뀝니다.

**중요한 것은 오늘도 계속한다는 것입니다.**
