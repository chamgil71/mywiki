## 0) 연결 고리 (Bridge)

Chapter 04에서 보관소의 뼈대(폴더 구조)를 완성했습니다.  
이제 그 안을 채울 차례입니다. 옵시디언의 모든 노트는 **마크다운(Markdown)** 으로 작성됩니다.  
마크다운을 모르면 노트를 쓸 수는 있지만, 구조를 만들고 강조하고 표를 넣는 것이 불가능합니다.

## 1) 개념 정의 및 필요성

### 마크다운(Markdown)이란?

> **마크다운은 일반 텍스트에 간단한 기호를 추가해 서식을 지정하는 경량 마크업 언어입니다.**

2004년 John Gruber가 만든 이 언어는 "사람이 읽기 쉬운 텍스트를 그대로 쓰면서도 HTML로 변환할 수 있다"는 철학에서 시작됐습니다. 현재 GitHub, Notion, Discord, Reddit 등 수많은 서비스가 채택하고 있어 한 번 익히면 어디서든 활용할 수 있는 범용 기술입니다.

**왜 마크다운인가:**

| 비교 항목 | 일반 워드 프로세서 | 마크다운 |
|---|---|---|
| 파일 형식 | .docx (바이너리) | .md (순수 텍스트) |
| 다른 앱 이전 | 어려움 (형식 손실) | 완전 자유 (어디서나 열기) |
| 버전 관리 (Git) | 불가 | 완전 지원 |
| 학습 시간 | 없음 (직관적 UI) | 약 15분 |
| 서식 안정성 | 앱마다 다름 | 표준화 |

> 📌 **NOTE:** 마크다운에는 표준(CommonMark)과 각 도구별 확장 문법이 혼재합니다. 이 챕터에서는 **옵시디언에서 작동하는 문법**을 기준으로 설명하며, 옵시디언 전용 확장 문법(내부 링크, 콜아웃 등)은 이후 챕터에서 다룹니다.

## 2) 핵심 원리 및 구조

### 마크다운의 동작 원리

마크다운은 **"기호 → 서식"** 의 단순한 변환 규칙으로 작동합니다.

```mermaid
flowchart LR
    A["#  제목 입력\n**굵게** 입력\n- 리스트 입력"]
    B["마크다운 파서\n(렌더링 엔진)"]
    C["🔠 큰 제목\n**굵은 텍스트**\n• 리스트 항목"]

    A -->|"원본 텍스트\n(.md 파일)"| B
    B -->|"렌더링 결과\n(화면 표시)"| C

    style B fill:#7C3AED,color:#fff
```

옵시디언의 **라이브 미리보기(Live Preview)** 모드에서는 기호를 입력하는 즉시 렌더링 결과로 바뀝니다. 원본 기호를 다시 보려면 해당 줄에 커서를 놓으면 됩니다.

## 3) 실습 예제 및 실행 환경

> **실습 방법:** `10-notes/마크다운 연습.md` 파일을 새로 만들고 각 문법을 직접 입력하세요.

### 3.1 제목 (Heading)

`#` 기호의 개수로 제목 크기를 지정합니다. `#`과 텍스트 사이에 **반드시 공백 한 칸**이 필요합니다.

```markdown
# 제목 1 (H1) — 가장 큰 제목, 문서 제목용
## 제목 2 (H2) — 주요 섹션 구분
### 제목 3 (H3) — 소섹션
#### 제목 4 (H4)
##### 제목 5 (H5)
###### 제목 6 (H6) — 가장 작은 제목
```

> 💡 **TIP:** 옵시디언에서 `#` 제목은 **아웃라인(Outline) 패널**과 **그래프 뷰 필터**에 활용됩니다. 문서 구조를 잘 잡을수록 나중에 노트 탐색이 편해집니다.

> ⚠️ **WARNING:** H1(`# 제목`)은 노트 한 개당 하나만 사용하는 것을 권장합니다. 옵시디언은 파일 이름을 제목으로 사용하므로, 본문에서 H1은 생략하거나 파일명과 동일하게 맞추는 것이 관례입니다.

---

### 3.2 텍스트 강조

```markdown
**굵게(Bold)** 또는 __굵게__
*기울임(Italic)* 또는 _기울임_
***굵게+기울임*** 또는 ___굵게+기울임___
~~취소선(Strikethrough)~~
==하이라이트(Highlight)==    ← 옵시디언 전용
```

**렌더링 결과:**
- **굵게** — 중요한 키워드, 핵심 개념
- *기울임* — 책·영화 제목, 외국어, 강조
- ***굵게+기울임*** — 최고 강조
- ~~취소선~~ — 완료된 항목, 수정 표시
- ==하이라이트== — 나중에 다시 볼 내용 표시

> 📌 **NOTE:** `==하이라이트==` 는 CommonMark 표준이 아닌 옵시디언 확장 문법입니다. GitHub 등 다른 플랫폼에서는 렌더링되지 않을 수 있습니다.

---

### 3.3 리스트

**순서 없는 리스트(Unordered List):**
```markdown
- 항목 1
- 항목 2
  - 하위 항목 2-1 (들여쓰기 2칸)
  - 하위 항목 2-2
- 항목 3

* 별표(*)도 동일하게 작동
+ 플러스(+)도 동일하게 작동
```

**순서 있는 리스트(Ordered List):**
```markdown
1. 첫 번째
2. 두 번째
3. 세 번째
   1. 하위 순서 항목
   2. 하위 순서 항목
```

> 💡 **TIP:** 순서 있는 리스트에서 모든 항목을 `1.`로 써도 옵시디언이 자동으로 번호를 매깁니다. 항목 순서를 자주 바꾸는 경우 유용합니다.

**체크박스 리스트 (Task List):**
```markdown
- [ ] 아직 완료 안 된 할일
- [x] 완료된 할일 (소문자 x)
- [ ] 장보기
  - [x] 우유
  - [ ] 달걀
```

> 💡 **TIP:** 옵시디언에서 체크박스를 클릭하면 `[ ]` ↔ `[x]` 가 즉시 전환됩니다. Dataview 플러그인과 결합하면 전체 보관소의 미완료 할일을 한 곳에서 모아볼 수 있습니다. (Chapter 22 참고)

---

### 3.4 인용문 (Blockquote)

```markdown
> 인용문은 이렇게 씁니다.
> 여러 줄에 걸쳐 쓸 수 있습니다.

> 첫 번째 인용
>> 인용 안의 인용 (중첩 인용)
>>> 3단계 중첩도 가능
```

**활용 사례:**
```markdown
> "글쓰기는 생각을 정리하는 가장 좋은 방법이다."
> — 어느 현자

> ⚠️ 주의: 이 방법은 옵시디언 v1.5 이하에서 작동하지 않습니다.
```

> 📌 **NOTE:** 옵시디언의 **콜아웃(Callout)** 기능은 인용문 문법을 확장한 것입니다. `> [!NOTE]`, `> [!TIP]` 같은 형태로 시각적으로 강조된 박스를 만들 수 있습니다. Chapter 06에서 다룹니다.

### 3.5 표 (Table)

```markdown
| 열 1 | 열 2 | 열 3 |
|---|---|---|
| 데이터 A | 데이터 B | 데이터 C |
| 데이터 D | 데이터 E | 데이터 F |
```

**정렬 지정:**
```markdown
| 왼쪽 정렬 | 가운데 정렬 | 오른쪽 정렬 |
|:---|:---:|---:|
| Left | Center | Right |
| 기본값 | 제목·날짜 | 숫자·금액 |
```

> 💡 **TIP:** 표 입력이 번거롭다면 명령 팔레트(`Ctrl/Cmd+P`) → "table" → [표 삽입] 을 사용하거나, Advanced Tables 커뮤니티 플러그인을 설치하면 Tab 키로 셀 간 이동이 가능해집니다.

> ⚠️ **WARNING:** 마크다운 표는 셀 내에 줄바꿈을 지원하지 않습니다. 셀 안에 긴 내용이 필요하다면 HTML `<br>` 태그를 사용하거나, 표 대신 콜아웃·리스트로 구조를 바꾸는 것을 권장합니다.

---

### 3.6 수평선 (Horizontal Rule)

```markdown
---
***
___
```

세 가지 모두 동일한 수평선으로 렌더링됩니다. 관례적으로 `---`를 가장 많이 사용합니다.

**활용:** 노트 내에서 섹션을 시각적으로 구분할 때 사용합니다.

> ⚠️ **WARNING:** 노트 최상단에 `---`로 시작하는 블록은 마크다운 수평선이 아닌 **YAML 프론트매터(Front Matter)** 로 인식됩니다. 반드시 본문 중간에서만 수평선으로 사용하세요. (YAML 프론트매터는 Chapter 13에서 다룹니다)

## 4) 실무 시나리오 (Best Practice)

### 노트 유형별 권장 마크다운 구조

**회의록 노트:**
```markdown
# 회의록 — 2024-01-15 주간 스탠드업

## 참석자
- 홍길동, 김철수, 이영희

## 논의 사항
### 1. 프로젝트 A 현황
> 현재 70% 완료. 이번 주 내 마무리 예정.

### 2. 이슈 사항
- [x] 서버 배포 오류 수정 완료
- [ ] 디자인 검토 미완료

---
다음 회의: 2024-01-22
```

**독서 노트:**
```markdown
# 『총균쇠』— 재레드 다이아몬드

## 핵심 주장
> 지리적 조건이 문명의 발전 격차를 결정했다.

## 인상 깊은 구절
> "역사는 지리를 따라 흐른다."

## 나의 생각
==이 주장은 인종 결정론을 반박하는 강력한 근거가 된다.==

## 연결 노트
- [[제텔카스텐 메모법]]
- [[지리와 문명 — 내 메모]]
```

**프로젝트 관리:**
```markdown
# 프로젝트: 옵시디언 가이드북

## 진행 상황
- [x] 기획 완료
- [x] Part 1 초고
- [ ] Part 2 작성 중
- [ ] 검토 및 교정

## 마감일
| 파트 | 마감일 | 상태 |
|---|---|---|
| Part 1 | 2024-02-01 | ✅ 완료 |
| Part 2 | 2024-02-15 | 🔄 진행 중 |
```

### 안티 패턴

- **모든 텍스트를 굵게 처리:** 모든 것이 강조되면 아무것도 강조되지 않은 것과 같습니다. 굵게는 전체의 10% 이내로 사용하세요
- **H1을 여러 개 사용:** 노트 한 개에 H1은 하나가 원칙입니다. H2~H4로 계층 구조를 만드세요
- **표를 과도하게 사용:** 2열 이하의 간단한 정보는 리스트가 더 읽기 쉽습니다. 표는 3열 이상 비교 정보에 적합합니다

## 5) 트러블슈팅 & 주의사항

### Q1. 굵게(`**`)가 렌더링이 안 돼요

`**텍스트**` 앞뒤에 공백이 있으면 렌더링되지 않을 수 있습니다. `**텍스트**` 바로 앞뒤에 공백 없이 붙여 쓰세요. 또는 `Ctrl/Cmd+B` 단축키로 선택 텍스트에 굵게를 적용하세요.

### Q2. 체크박스가 클릭이 안 돼요

편집 모드(Source Mode)에서는 체크박스 클릭이 되지 않습니다. 라이브 미리보기 또는 읽기 모드에서는 클릭으로 체크/해제가 됩니다. `Ctrl/Cmd+E`로 모드를 전환해보세요.

### Q3. 표 정렬이 맞지 않아요

마크다운 표는 `|` 구분자의 위치가 정확하지 않아도 렌더링은 됩니다. 원본 텍스트에서 정렬이 안 맞아 보여도 걱정하지 마세요. 깔끔한 정렬을 원한다면 Advanced Tables 플러그인을 사용하세요.

### Q4. `---`를 입력했더니 수평선이 아닌 YAML로 인식됩니다

노트 첫 번째 줄이 `---`이면 YAML 프론트매터 시작으로 인식됩니다. 수평선은 반드시 본문 중간, 빈 줄 다음 줄에 입력하세요.

```markdown
# 제목

본문 내용

---

다음 섹션
```

### Q5. 리스트 하위 항목 들여쓰기가 안 돼요

들여쓰기는 **정확히 2칸 또는 4칸 공백**이 필요합니다. Tab 키는 옵시디언 설정에 따라 다르게 작동할 수 있으니 스페이스바를 사용하는 것을 권장합니다. `설정 → 편집기 → 들여쓰기 크기`에서 확인하세요.
