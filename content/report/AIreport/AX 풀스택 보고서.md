## 1. AX 풀스택 개념 및 아키텍처 정의

### 1-1. AX 풀스택(AX Full-Stack) 개념 정리

- **ㅁ 정의: AX = AI Transformation Full-Stack 엔터프라이즈 아키텍처**
    
    - ㅇ 조직 전체가 AI 기반으로 비즈니스·공정을 재구성하기 위한 **레이어드 아키텍처**를 의미함
        
        - - HW/GPU·NPU 인프라, 데이터·피쳐·메타데이터, 모델·에이전트, 서비스·업무 프로세스, 거버넌스·보안·위험관리까지 전체 스택을 포함
    - ㅇ 기존 EA(Enterprise Architecture)에서 **AI 중심 레이어(AI Stack)**와 **데이터 지능 레이어(Data Intelligence)**가 강화된 버전으로 이해 가능
        
        - - Oracle, Lenovo, Databricks 등은 이미 엔터프라이즈용 생성형 AI 스택·산업별 AI 레퍼런스 아키텍처를 다층 구조로 제시하고 있음
    - ㅇ 2025년 이후 SOTA 실무에서는 **"모델 허브 + 데이터 인텔리전스 + AI 거버넌스"** 3축이 필수 레이어로 인식됨
        
    - ㅇ 레퍼런스 아키텍처가 **"모델 중심"에서 "데이터·맥락 중심"**으로 전환(RAG, 피쳐 스토어, 메타데이터/정책 연계)
        
    - ㅇ 산업별 LLM 파인튜닝·에이전트 도입이 본격화되며, **도메인 특화 AX 구조** 요구 증가

## 2. AX 풀스택 레이어 구조 (엔터프라이즈 기준 공통 참조)

### AX 풀스택(공통 EA 레퍼런스) 7계층
    
   1. **비즈니스·도메인 레이어**
        
        - ㅇ 산업별 가치사슬(제조: 설계–조달–생산–유통, 금융: 온보딩–여신–리스크, 헬스케어: 진단–치료–추적, 공공: 정책–집행–평가–민원 등)과 KPI 정의
   2. **서비스·프로세스 레이어**
        
        - ㅇ 챗봇, Copilot, 예측·최적화 서비스, RPA/워크플로 등 **AI가 개입하는 업무 단위** 정의
   3. **애플리케이션·에이전트 레이어**
        
        - ㅇ LLM 기반 에이전트, 도메인별 마이크로서비스, API 게이트웨이, LangChain/agent framework 등

   4. **모델·ML/MLOps 레이어**
        
        - ㅇ 파운데이션 모델 허브, 도메인 특화 LLM/모델, 피쳐 스토어, AutoML, MLflow/KServe 등 배포·모니터링
 
   5. **데이터·메타데이터 레이어**
        
        - ㅇ 데이터 파이프라인(메달리온 아키텍처: Bronze/Silver/Gold), 피쳐 스토어, 카탈로그, 계보(lineage), 품질·정책 메타데이터
   
   6. **플랫폼·인프라 레이어**
        
        - ㅇ GPU/NPU 클러스터, 컨테이너(K8s), 오브젝트 스토리지·데이터레이크, 엣지 디바이스, 네트워크·보안 인프라

   	7. **거버넌스·리스크·보안 레이어(수평 계층)**
        
        - ㅇ 모델 리스크 관리, AI 윤리·편향 점검, 규제 준수(EU AI Act/AI 기본법), 접근통제, 감사 로그, AI 카드·모델 카드·데이터 시트 등
 
> [!note] 
> ㅁ 시장·기술 동향과의 정합성
> ㅇ Oracle, Databricks, Lenovo 등 글로벌 레퍼런스 아키텍처에서 공통적으로 **애플리케이션/접근–AI/ML–데이터–인프라** 구조를 채택하고 있음

### AX 풀스택 7계층 상세 정의표

|레이어|레이어 정의|레이어 하부 내역(주요 구성요소)|비고|
|---|---|---|---|
|**L1 비즈니스·도메인 레이어**|산업·조직의 **가치사슬과 KPI**를 정의하는 최상위 비즈니스 구조|- 산업별 도메인: 제조(설계·조달·생산·품질·유지보수), 금융(여신·수신·리스크·채널), 헬스케어(진단·치료·보험·연구), 공공(정책·행정·민원·안전) 등 <br>- 비즈니스 목표·KPI(비용·매출·생산성·품질·안전·만족도) 정의|무엇을 위한 AX인지(목적·성과)를 규정하는 층. 정책·사업 기획서에서 **첫 페이지에 나와야 할 레이어**|
|**L2 서비스·프로세스 레이어**|비즈니스 도메인을 구성하는 **업무 프로세스와 AI 서비스(Use Case)** 정의|- 업무 프로세스: 민원처리, 여신심사, 생산계획, 진료·간호, 규제심사 등 <br>- AI 서비스: 챗봇/민원, Copilot(문서·코딩·업무보조), 예측·최적화 서비스, RPA/워크플로 자동화, 산업별 특화 서비스(예지보전, KYC/AML 모니터링, 진료기록 자동작성 등)|RFP에서 보통 "요구 기능·Use Case"로 표현되는 층. **산업별 AX 레퍼런스의 중심 레이어**|
|**L3 애플리케이션·에이전트 레이어**|L2의 서비스를 구현하는 **LLM 기반 에이전트·앱·마이크로서비스** 층|- LLM 에이전트: 상담/콜센터, 리서치·분석, 운영/관제, 개발자 Copilot, 정책분석 에이전트 등 <br>- 에이전트 오케스트레이션: 워크플로 엔진, 에이전트 레지스트리, Human-in-the-loop UI <br>- AI 내장 마이크로서비스·API 게이트웨이|사용자가 직접 만나는 층|
|**L4 모델·ML/MLOps (LLMOps) 레이어**|파운데이션 모델·도메인 모델과 이를 **학습·배포·운영하는 스택**|- 파운데이션 모델: LLM(텍스트·멀티모달), 비전, 음성, 시계열, 그래프 등 <br>- 도메인 특화 모델: 제조 예지보전, 금융 신용평가, 의료 영상·진단, 공공 정책분석 모델 등 <br>- Ops: 데이터→학습→검증→배포→모니터링→재학습 파이프라인, 모델 레지스트리, 피쳐 스토어, 실험관리(MLOps/LLMOps)|성능·비용·위험의 핵심 레이어|
|**L5 데이터·메타데이터 레이어**|AI·서비스에 활용되는 **데이터·메타데이터·카탈로그·품질관리** 층|- 데이터 소스: 업무시스템, IoT/OT 센서, 로그, 외부데이터, 공공데이터 등 <br>- 저장·처리: 데이터레이크/웨어하우스/레이크하우스, ETL/ELT·스트리밍 파이프라인, 메달리온(Bronze/Silver/Gold) 구조 <br>- 메타데이터: 카탈로그, 계보(lineage), 품질지표, 보존기간·민감도·위치, 규제·동의 정보 <br>- AI 특화: 벡터DB/RAG 인덱스, 레드팀/평가 데이터셋, Synthetic Data 관리 등|"데이터 없이는 AI 없다"의 구현 층. 공공에서는 국가 데이터 허브에 해당|
|**L6 플랫폼·인프라 레이어**|AI·데이터를 구동하는 **클라우드·GPU/NPU·스토리지·네트워크** 인프라 층|- 연산: GPU/NPU 클러스터(온프레미스·클라우드·하이브리드), 온디바이스/엣지 AI <br>- 플랫폼: 컨테이너(K8s), 서버리스, 배포·모니터링 인프라 <br>- 스토리지·네트워크: 오브젝트 스토리지, 고성능 스토리지, 고속 네트워크, 보안 인프라|CAPEX·OPEX가 집중되는 물리적 기반|
|**L7 거버넌스·리스크·보안·관측(수평)**|모든 레이어를 가로지르는 **규제·윤리·리스크·보안·모니터링** 공통 층|- 규제·윤리: EU AI Act, 한국 AI 기본법, 국가 AI 윤리지침 반영, 위험등급·고위험 시스템 관리 <br>- 거버넌스: 모델 카드, 데이터 시트, 정책 메타데이터, 승인·검토 워크플로 <br>- 리스크·보안: 편향·성능 드리프트, 프라이버시, IAM·접근통제, 감사로그 <br>- Observability: 로그/메트릭/트레이싱, 모델 성능 모니터링, SLA 관리|정책·법제와 직접 연결되는 레이어. 공공사업에서 반드시 별도 항목으로 요구해야 함|

### AX 풀스택 트리 구조 (텍스트 트리 표현)

```
AX Full-Stack (Enterprise AI Transformation)

├─ L1. Business & Domain Layer
│   ├─ 제조 도메인
│   │   ├─ 설계/개발
│   │   ├─ 조달/공급망
│   │   ├─ 생산/품질
│   │   └─ 유지보수/안전
│   ├─ 금융 도메인
│   │   ├─ 여신/수신
│   │   ├─ 리스크/준법
│   │   ├─ 자산관리/투자
│   │   └─ 고객채널
│   ├─ 헬스케어 도메인
│   │   ├─ 진단/치료
│   │   ├─ 간호/행정
│   │   ├─ 보험/청구
│   │   └─ 연구/임상시험
│   └─ 공공 도메인
│       ├─ 정책기획/분석
│       ├─ 행정집행
│       ├─ 민원/복지
│       └─ 안전/도시/교통
│
├─ L2. Service & Process Layer
│   ├─ 챗봇/민원/상담 서비스
│   ├─ Copilot(문서/코딩/업무보조)
│   ├─ 예측/최적화/리스크 분석 서비스
│   ├─ RPA/워크플로 자동화 서비스
│   └─ 산업별 특화 서비스(예: 예지보전, 여신심사, 진료기록 자동작성 등)
│
├─ L3. Application & Agent Layer
│   ├─ LLM 기반 도메인 에이전트
│   │   ├─ 상담/콜센터 에이전트
│   │   ├─ 분석/리포트 에이전트
│   │   ├─ 운영/관제 에이전트
│   │   └─ 개발/운영 Copilot
│   ├─ AI 내장형 마이크로서비스
│   └─ 에이전트 오케스트레이션/워크플로 엔진
│
├─ L4. Model & MLOps / LLMOps Layer
│   ├─ 파운데이션 모델 허브(LLM, Vision, Speech, Multi-modal)
│   ├─ 도메인 특화 LLM/모델(제조, 금융, 의료, 공공)
│   ├─ 피쳐 스토어/모델 레지스트리
│   ├─ 학습/파인튜닝/추론 파이프라인
│   └─ MLOps/LLMOps 도구(배포, 모니터링, 롤백, A/B 테스트)
│
├─ L5. Data & Metadata Layer
│   ├─ 데이터 소스(업무시스템, IoT/OT, 로그, 외부 데이터)
│   ├─ 데이터 파이프라인(ETL/ELT, 스트리밍, 메달리온 아키텍처)
│   ├─ 데이터레이크/웨어하우스/레이크하우스
│   ├─ 데이터 카탈로그/계보(Lineage)/품질관리
│   └─ 정책 메타데이터(보존기간, 민감도, 위치, 규제 등)
│
├─ L6. Platform & Infrastructure Layer
│   ├─ GPU/NPU 클러스터(클라우드, 온프레미스, 하이브리드)
│   ├─ 컨테이너 플랫폼(Kubernetes 등)
│   ├─ 오브젝트 스토리지/고성능 스토리지
│   ├─ 네트워크/보안 인프라
│   └─ 엣지/온디바이스 AI 인프라
│
└─ L7. Governance, Risk, Security & Observability (Horizontal)
    ├─ AI 윤리/편향/공정성 관리
    ├─ 규제 준수(EU AI Act, AI 기본법 등) 및 위험관리
    ├─ IAM/접근통제/감사로그
    ├─ Observability(로그/메트릭/트레이싱, 모델 모니터링)
    └─ 모델 카드/데이터 시트/AI 사용 정책 관리
```


### L3~L5 레이어 세부 컴포넌트

- **L3 애플리케이션·에이전트 레이어**
    
    - 에이전트 유형:
        
        - 상담·지원 에이전트, 리서치 에이전트, 운영/관제 에이전트, 개발자 Copilot, 정책분석 에이전트 등
    - 공통 컴포넌트:
        
        - 에이전트 레지스트리, 워크플로 엔진, Human-in-the-loop UI, 정책·보안 훅(프롬프트 필터링, 권한 체크)
- **L4 모델·MLOps/LLMOps 레이어**
    
    - 모델 포트폴리오:
        
        - 파운데이션 LLM (국산·글로벌), 도메인 특화 DSLM(제조·금융·의료), 비전·음성 모델, 시계열 예측, 그래프 모델 등
    - Ops 계열:
        
        - DataOps, MLOps, ModelOps, LLMOps를 통합한 **AI Engineering** 개념으로, 실험 추적, 버전관리, CI/CD, 모니터링, 재학습 자동화 구성.
- **L5 데이터·메타데이터 레이어**
    
    - 데이터 구조:
        
        - 데이터레이크+웨어하우스를 통합한 **레이크하우스 구조**(예: Databricks Lakehouse AI)
    - 메타데이터:
        
        - 카탈로그, 계보(lineage), 품질 지표, 규제·보존기간, 민감도, 위치(국내/국외), 활용 동의 정보 등
    - AI용 데이터 기능:
        
        - RAG용 인덱스(벡터/그래프 DB), 프롬프트 데이터 셋, 레드팀·평가 데이터 셋, Synthetic Data 생성 및 관리

## 3. 글로벌·국내 시장 동향

### 3-1. 현황 요약

- ㅇ AI 소프트웨어 시장 2024년 1,220억 달러 → 2030년 4,670억 달러(연 25%) 전망
    
- ㅇ 생성형 AI는 2024년 246억 달러 → 2032년 4,004억 달러(연 41.7%)로, 전체 AI 성장의 핵심 엔진
    
- ㅇ 엔터프라이즈 생성형 AI 시장은 2024년 약 29억 달러 → 2030년 198억 달러(연 38.4%) 전망
    
- ㅇ 산업별로 금융, 제조, 리테일, 헬스케어가 선도 도입군이며 금융·제조는 실시간·규제·안전 요구로 풀스택 아키텍처 수요가 특히 큼
    

### 3-2. 주요 변화 (최근 1년 내)

- ㅇ **클라우드-네이티브 AI 스택**과 **데이터 인텔리전스 플랫폼**(예: Databricks, Snowflake 기반) 중심으로 아키텍처가 수렴
    
- ㅇ 레퍼런스 아키텍처가 **"모델 중심"에서 "데이터·맥락 중심"**으로 전환(RAG, 피쳐 스토어, 메타데이터/정책 연계)
    
- ㅇ 산업별 LLM 파인튜닝·에이전트 도입이 본격화되며, **도메인 특화 AX 구조** 요구 증가
    

### 3-3. 핵심 통계 수치

### 3-4. 주요 플레이어별 동향 (AX 관련)

- ㅇ **빅테크**: OpenAI·MS, Google, Meta, Amazon, Apple – 대형 모델·에이전트 플랫폼과 함께 **엔터프라이즈 AI 스택(Infra–Data–Model–App)**를 통합 제공
    
- ㅇ **클라우드·플랫폼**: Oracle OCI, Databricks, Lenovo, NVIDIA 등은 **풀스택 레퍼런스 아키텍처** 문서를 통해 HW–Data–Model–MLOps–App 레이어를 제안
    
- ㅇ **도메인 특화 스타트업**: 헬스케어, 금융, 제조 특화 LLM·에이전트 스타트업이 급증, 산업별 AX를 사실상 정의하는 주체로 부상
    

### 3-5. 시사점·전망 및 국내 영향도

- ㅇ 향후 1년 내, **"엔터프라이즈 AX 레퍼런스 아키텍처"를 누가 장악하느냐**가 플랫폼 패권 핵심이 될 전망 → 국내도 국가 차원의 공통 참조 아키텍처 필요
    
- ㅇ 국내 영향도는 **High**: 한국 AI 시장이 연 25% 이상의 성장 궤도에 있고, 글로벌 벤더 아키텍처에 종속될 경우 장기 기술·데이터 종속 리스크 큼

## 4. 주요 정책·규제 동향과 AX 연계

### 4-1. 현황 요약

- ㅇ **EU AI Act**: 위험 기반(금지·고위험·제한·저위험) 분류 체계, 2024~26년 단계적 발효, 고위험 시스템에 데이터·문서화·거버넌스 의무 부과
    
- ㅇ **미국 EO 14110**: 안전·보안·신뢰성, 프라이버시, 노동·공정성, 경쟁 촉진 등 8대 원칙 제시, 고위험 모델의 학습·레드팀 테스트 정보 제출 요구
    
- ㅇ **한국 AI 기본법("인공지능의 개발 및 이용 촉진과 신뢰 확보 등에 관한 법률")**: 2024년 제정, 2026년 1월 시행 예정. AI 컨트롤타워, 안전연구소, 인프라·중소기업 지원, 고위험/생성형 AI에 대한 투명성·안전 의무 부과
    

### 4-2. 국내 정책·전략

- ㅇ **국가 AI 전략 정책방향 (AI G3)**:
    
    - - '국가 AI 컴퓨팅 센터' 구축, GPU 용량 15배 확대, 국산 AI칩 상용화 지원
    - - 2024~27년 민간 65조 원 AI 투자, 산업 70%·공공 95% AI 도입률 목표(2030년)
- ㅇ **국가 AI 윤리 기준·체크리스트**: MSIT·KISDI의 국가 AI 윤리기준 및 KATS의 AI 윤리 체크리스트로 투명성·공정성·무해성·책임성 등을 제시
    

### 4-3. 규제·정책과 AX 트리의 레이어 매핑

- **EU AI Act**: 위험기반(금지·고위험·제한·저위험) 분류, 고위험 및 생성형 모델에 대해 데이터·문서화·리스크 관리 의무 부과.  
    → AX 트리의 **L7 거버넌스·리스크 레이어**에 "위험등급, 적합성평가, 기술문서, 로그, 투명성" 항목으로 직접 매핑.
    
- **미국 EO 14110**: 안전·보안·신뢰성, 프라이버시, 노동, 공정성, 경쟁 촉진 등 8대 원칙과 고위험 모델의 테스트·보고 의무 명시.  
    → **L4 모델·MLOps 레이어**의 테스트·검증, **L7 레이어**의 평가·보고 체계를 정책 요구사항에 맞게 설계.
    
- **한국 AI 기본법(2026년 시행 예정)**: AI 컨트롤타워, AI 안전연구소, 인프라·중소기업 지원, 고위험·생성형 AI에 대한 의무 규정 등 포함.  
    → 공공사업 RFP에서 **L7 레이어의 '국내 법령 준수 컴포넌트'**를 명확하게 요구할 수 있음.
    
- **국가 AI 윤리 기준·체크리스트**: 투명성·공정성·무해성·책임성 등을 원칙으로 제시.  
    → AX 트리에서 **모델 카드, 데이터 시트, AI 사용정책**을 L7 컴포넌트로 명시.
    

### 4-4. AX에 대한 함의

- ㅇ **거버넌스·리스크 레이어를 "옵션"이 아닌 "기본 계층"으로 편입**
    
- ㅇ 모델·데이터의 **출처·리스크·정책 메타데이터를 아키텍처 수준에서 관리** → 정책사업에서 이를 표준 스펙으로 요구해야 함

## 5. 산업분야별 AX 풀스택 레퍼런스 아키텍처

이제 위 공통 7계층을 **제조·금융·헬스케어·공공** 4대 분야에 적용해, 정책사업 설계에 바로 쓸 수 있는 수준의 구조를 제시함.

### 5-1. 제조(Industrial AX 풀스택)

- **ㅁ 동향·시장**
    
    - ㅇ 한국 Industrial AI 시장: 2024년 1.529억 달러 → 2035년 5.345억 달러, 연 12.05% 성장 전망
        
    - ㅇ 글로벌 제조업은 OEE 향상, 예지보전, 품질검사, 공급망 최적화 등에 AI·엣지·OT 통합 아키텍처 도입 가속
        
- **ㅁ 레퍼런스 AX 구조 (요약)**
    
    - ㅇ 비즈니스·도메인: 설비 OEE, 불량률, 에너지 효율, 안전지표 중심 KPI
        
    - ㅇ 서비스·프로세스: 예지보전, 품질검사, 생산 스케줄링, 안전 모니터링 서비스
        
    - ㅇ 애플리케이션·에이전트:
        
        - - 생산 관리 Copilot(작업지시·이상 상황 요약), 설비 엔지니어용 Root Cause Analysis 에이전트, 공급망 계획 에이전트
    - ㅇ 모델·MLOps:
        
        - - 시계열 예측 모델, 비전 기반 결함 탐지 모델, LLM 기반 작업지침 Q&A, OT 데이터용 RAG 파이프라인
    - ㅇ 데이터·메타데이터:
        
        - - 센서/PLC/SCADA 데이터 → Industrial DataOps → 메달리온 구조(Bronze: 원시, Silver: 정제, Gold: KPI/도메인 뷰)
    - ㅇ 플랫폼·인프라:
        
        - - 공장 엣지서버(경량 추론), 클라우드 GPU 트레이닝, OT/IT 통합 네트워크, 안전·실시간 요구조건 반영
    - ㅇ 거버넌스·리스크·보안:
        
        - - OT 보안, 안전기준(산업안전보건), 품질 규격(ISO, IATF 등)과 모델 검증 체계 연계
- **ㅁ 정책·투자 시사점**
    
    - ㅇ **"Industrial AX 레퍼런스 센터(제조혁신센터+AI센터 통합)"**를 권역별로 구축, 레퍼런스 스택·샘플 코드·데이터셋 제공
        
    - ㅇ 산업단지 단위로 **OT–클라우드 연계 실증(데이터 상호운용 표준 포함)**를 지원해, 중소 제조사가 그대로 복제·확장 가능하도록 설계

### 5-2. 금융(BFSI AX 풀스택)

- **ㅁ 동향·시장**
    
    - ㅇ 글로벌 금융권은 AI 도입률 80% 이상, 문서 처리·KYC/AML·사기 탐지·신용평가·프론트 오피스 Copilot 중심으로 확대
        
    - ㅇ 규제 환경(바젤, KYC/AML, 금융소비자보호법 등) 때문에 **설명가능성·감사 가능성·실시간성** 요구가 매우 높음
        
- **ㅁ 레퍼런스 AX 구조 (요약)**
    
    - ㅇ 비즈니스·도메인: 여신·수신·투자·보험 가치사슬 + 리스크 관리·규제보고
        
    - ㅇ 서비스·프로세스:

### 6-2. 레이어별 시사점·분석 (정책·사업 기획 관점)

**L1–L2 비즈니스·서비스: 전략·컨설팅 레이어**

- 글로벌은 **Accenture–McKinsey–Deloitte 3대 축**이 산업 전반 GenAI/AX 전략을 사실상 표준화하고 있습니다. Accenture는 2024 회계연도 기준 GenAI 배치 매출이 9억달러, 관련 신규 수주가 30억달러에 달하는 등, 이미 "AX 컨설팅 산업"을 형성했습니다. McKinsey QuantumBlack과 Deloitte도 AI 전략·거버넌스·조직 변혁까지 포함된 풀스택 컨설팅을 제공하고 있습니다.
    
- 국내에선 **LG CNS·Samsung SDS·SKT 컨소시엄**이 유사한 역할을 수행하고 있으나, **"K-AX 참조 아키텍처 + 산업별 레퍼런스"를 국가 차원에서 명시**하고, 이들 기업이 공공·민간을 아우르는 **표준 AX 파트너**로 동원되는 구조를 설계할 필요가 있습니다.
    

**L3 애플리케이션·에이전트: Copilot·도메인 에이전트**

- Microsoft 365 Copilot, AWS Bedrock Agents, Google Vertex Agent Builder는 **"업무 툴에 녹아든 에이전트" 생태계의 글로벌 표준**이 되고 있습니다.
    
- 국내는 **KT AICC(컨택센터), HyperCLOVA X 기반 네이버 서비스, SKT A./AIX**가 대표적인 에이전트형 서비스입니다.
    
- 정책사업 측면에서는,
    
    - 공공·금융·제조·헬스케어별로 **"표준 에이전트 유형"(민원 Copilot, 여신심사 Copilot, 예지보전 Copilot 등)**을 정의하고,
        
    - 사업자 선정 시 L3에서 **기성 플랫폼(M365 Copilot, HyperCLOVA X, Mi:dm 등)과 연계한 아키텍처**를 요구하는 것이 효과적입니다.
        

**L4 모델·MLOps/LLMOps: 파운데이션 모델 경쟁**

- **OpenAI·Anthropic·NVIDIA**는 각각 엔터프라이즈급 LLM과 운영 스택(Enterprise 제품, NIM/NeMo 등)을 제공하며, 글로벌 기업의 AX 스택에서 사실상 **"모델 레이어의 기본 옵션"**이 되고 있습니다.
    
- 국내는 **HyperCLOVA X, A.X K1, Mi:dm, KoGPT** 등이 존재하며, 특히 A.X K1은 519B 파라미터급 국가 주권 모델로 정부 프로젝트와 연동되고 있습니다.
    
- 정책·투자 관점에서:
    
    - **"국가 AX 풀스택"의 L4에는 최소 2~3개의 국산 파운데이션 모델**(NAVER, SKT, KT/카카오)을 **공공 조달에서 동등하게 활용할 수 있는 구조**를 마련해, 특정 글로벌 SaaS에 대한 종속을 피하는 것이 중요합니다.
        
    - 동시에 OpenAI·Anthropic·Google 등 글로벌 모델과의 **하이브리드·멀티모델 전략**을 전제로, 규제·데이터 현지화 요구에 맞춘 **모델 라우팅·게이트웨이**를 L4 표준 컴포넌트로 정의해야 합니다.
        

**L5 데이터·메타데이터: 레이크하우스·데이터 인텔리전스**

- Databricks·Snowflake는 **데이터+AI 통합 플랫폼**(Lakehouse AI, AI Data Cloud)으로 전 세계 엔터프라이즈의 표준이 되고 있으며, Unity Catalog·Cortex AI 등으로 데이터–모델–거버넌스를 하나의 계층에서 관리합니다.
    
- 국내에선 **LG CNS DAP, NAVER Cloud 데이터 인프라, Samsung SDS의 데이터 분석 플랫폼**이 L5 역할을 수행하고 있습니다. 다만 글로벌 레이크하우스 수준의 **"국가 공통 데이터 인텔리전스 플랫폼"**은 아직 부족합니다.
    
- 정책사업 설계 시,
    
    - "부처·지자체별 데이터 플랫폼"을 늘리는 대신, **국가 차원의 레이크하우스+카탈로그(예: 공공 Databricks/Snowflake에 준하는 구조)**를 구축하고,
        
    - 산업별 AX 프로젝트는 이 위에 **데이터 도메인·피쳐 스토어·메타데이터 스키마만 얹는 구조**로 유도하는 것이 예산 효율 측면에서 유리합니다.
        

**L6 플랫폼·인프라: GPU·클라우드·하이브리드**

- NVIDIA·AWS·Google Cloud는 **GPU+클라우드+AI 플랫폼**을 통합 제공하며, 엔터프라이즈 AI 인프라 시장의 핵심 축입니다.
    
- 국내에서는 **NAVER Cloud(각 세종), KT Cloud, Samsung SDS**가 주권형·전용 인프라를 표방하며, GPUaaS와 기업 전용 클라우드 팜 등을 제공하고 있습니다.
    
- 정책적으로는,
    
    - 국가 AI 컴퓨팅 인프라를 설계할 때 **NVIDIA·클라우드 하이퍼스케일러 레퍼런스 아키텍처**를 벤치마킹하되,
        
    - **국산 클라우드 2~3개(NAVER, KT, Samsung SDS 등)를 '공공 AX 인프라'의 기본 사업자군으로 고정**하고, 글로벌 클라우드는 멀티클라우드·재해복구·특수 워크로드에 보완적으로 활용하는 구조가 현실적입니다.
        

**L7 거버넌스·리스크·보안·관측: 규제 대응의 핵심**

- IBM watsonx.governance는 **모델·프롬프트 메타데이터, 편향·드리프트·품질 모니터링, 리스크·규제 대응 워크플로**를 제공하는 대표적인 AI 거버넌스 제품입니다. Databricks·Snowflake도 각각 Unity Catalog·Cortex를 통해 데이터와 모델 거버넌스를 플랫폼 수준에서 통합합니다.
    
- 국내는 아직 **독립된 상용 AI 거버넌스 제품**보다는, NAVER Cloud·SKT·KT가 자체 풀스택 내에서 거버넌스를 구현하는 형태입니다.
    
- 한국은 EU AI Act·미국 EO 14110·AI 기본법의 영향을 동시에 받는 위치에 있기 때문에,
    
    - L7에 대해 **"국가 공통 AI 거버넌스 툴킷"(모델 카드, 데이터 시트, 리스크 지표, 규제 매핑, 감사 API 등)**을 **공공재 형태로 개발·배포**하고,
        
    - 국내 클라우드·SI·컨설팅사가 이를 **모듈 형태로 조립**해 쓸 수 있는 구조를 만드는 것이 중요합니다.
        

### 6-3. 정리 – AX 풀스택과 기업·정책 전략 연결

1. **각 레이어마다 글로벌 리더와 국내 기업이 존재**하며, 다수 기업이 여러 레이어에 걸쳐 "풀스택"을 표방하고 있습니다.
    
2. 정책·사업 기획에서는 **"레이어별로 누가 표준 역할을 할지"를 명확히 정의**하고,
    
    - L1–L2: 전략·컨설팅(Accenture/McKinsey/Deloitte ↔ LG CNS/SDS/SKT),
        
    - L3–L4: 에이전트·모델(Microsoft/AWS/Google/OpenAI/Anthropic ↔ HyperCLOVA X/A.X K1/Mi:dm/KoGPT),
        
    - L5–L6: 데이터·인프라(Databricks/Snowflake/NVIDIA/AWS/GCP ↔ Naver Cloud/KT Cloud/SDS/LG CNS),
        
    - L7: 거버넌스(IBM watsonx.governance·글로벌 플랫폼 ↔ 국가 공통 툴킷+국내 풀스택 사업자),  
        와 같이 역할 분담 및 조합 전략을 세우는 것이 핵심입니다.
        
3. 투자·재테크 관점에서는, **L4(모델)·L5(데이터)·L7(거버넌스)** 레이어의 기업들이 구조적으로 높은 진입장벽과 장기 성장잠재력을 가지므로, 중장기 포트폴리오에서 비중을 어떻게 가져갈지 따로 검토해 볼 만합니다.

    - LG CNS DAP·NAVER Cloud·Samsung SDS·KT Cloud가 **이 위에 도메인별 데이터 모델·피쳐 스토어·RAG 인덱스**를 얹는 구조로 참여.

    - (공공) 데이터 중복 구축·마이그레이션 비용 절감,
        
    - (민간) 동일한 데이터·형식 위에 AX 서비스만 얹어 빠르게 롤아웃 가능.

    - L4 모델·L5 데이터 각각에 **모델 카드·데이터 시트·계보(lineage)·접근통제** 메타데이터를 필수로 붙이게 하고,
        
    - 이를 공통 거버넌스 툴킷(IBM watsonx.governance 유사 구조)로 관리하는 표준을 수립.

    - 삼성전자 – Gauss/ Gauss2가 Galaxy·가전·車 등 모든 디바이스에 퍼질 경우 **온디바이스 AI 플랫폼**의 최대 수혜.
        
- **투자 관점 시사점**
    
    - L4는 **연산비·데이터비·인력비**가 커서 자본력이 약한 곳은 중장기에서 버티기 어렵습니다.
        
    - 이미 L4에 **수천억 단위 CAPEX를 집행 중인 대형사(NAVER, SKT, 삼성, LG)** 위주로 보고,
        
    - 개별 모델 "기술 성능"보다 **①데이터 소스 파워(검색·커머스·통신·디바이스), ②수직 통합 능력(L5~L6), ③정책·규제와의 접점(주권 AI, 공공 사업)**을 보시는 것이 합리적입니다.
        

**(2) L5 – 상대적으로 안정적인 캐시플로우, 구조적 수혜 섹터**

- L5(데이터레이크·카탈로그·플랫폼)는 **기업·정부가 한번 구축하면 장기간 유지/확장**되므로, 프로젝트성보다는 **유지보수·운영·업그레이드**에서 꾸준한 매출이 발생하는 영역입니다.
    
- 국내에서는
    
    - LG CNS(DAP),
        
    - Samsung SDS,
        
    - NAVER Cloud, KT Cloud  
        가 핵심 플레이어이며, 중장기적으로 **"국가 데이터 인텔리전스 플랫폼" 사업 수혜** 가능성이 높습니다.
        
- **투자 관점 시사점**
    
    - L4 대비 성장률은 낮을 수 있지만, **현금흐름이 안정적**이고, 공공·대기업 장기 계약 비중이 커서 **방어적 성격**을 가집니다.
        
    - AI 붐이 꺼지더라도 "데이터 플랫폼" 자체는 필수 인프라이기 때문에, **리세션·규제 국면에서도 덜 흔들리는 축**이 될 가능성이 큽니다.
        

**(3) 포트폴리오 아이디어 (매우 거칠게)**

- 공격적: L4 비중 확대 – NAVER, SKT, 삼성전자, (카카오·KT는 소량 스파이스).
    
- 방어·인프라: L5 비중 확대 – 대형 SI·클라우드(LG CNS 상장 시 참여, Samsung SDS, KT/KT Cloud, NAVER).
    
- 정책·공공 프로젝트 수혜: **"주권 AI+데이터 인프라"** 양쪽에 모두 발을 담근 기업(SK Telecom, NAVER, KT, 삼성, LG CNS)을 중장기로 분산 보유하는 전략이 합리적입니다.
    

### 9-3. 정리 – L4·L5 관점에서의 협력 로드맵 제언

1. **정부/공공**
    
    - L4: HyperCLOVA X, A.X K1, EXAONE(필수) + Mi:dm/KoGPT/Gauss2(보완)을 "국가 AX 파운데이션 모델 풀(pool)"로 지정.
        
    - L5: Databricks/Snowflake형 국가 레이크하우스를 구축하고, LG CNS·Samsung SDS·NAVER Cloud·KT Cloud가 도메인별 서브플랫폼을 올리는 구조.
        
    - L7: IBM watsonx.governance 유사 툴킷을 국산화·공통 프레임으로 개발, 모든 공공·대형 사업에 의무 적용.
        
2. **민간·개인 투자자**
    
    - L4에서는 **데이터·디바이스·통신**을 동시에 가진 플레이어(삼성전자·NAVER·SKT·LG 계열)에 중장기 비중을 두고,
        
    - L5에서는 **대형 SI·클라우드·데이터 플랫폼 사업자**를 "방어적 성장주"로 인식하는 접근이 유효합니다.

                - _**참고자료/부연설명**_: NIA의 AI 트렌드 보고서 및 OECD 디지털 정부 리뷰를 활용해 공공부문 AI 활용 프레임을 정렬하고, IITP·SPRi의 인공지능산업 실태조사 결과를 산업별 AX 우선 영역 선정 근거로 활용 가능

    - 국가 차원의 **AX 트리 표준(본 문서의 7계층 트리)을 공식 가이드로 제정**.
        
    - 4대 산업별로 각 1~2개 **"AX 레퍼런스 사이트"(공장·병원·은행·지자체)** 구축.
        
    - 공공·민간 사업 RFP 템플릿에 **"AX 트리 매핑 표"**를 필수 항목으로 삽입.

    - 중소기업·지자체는 **"AX 레퍼런스 as-a-Service"** 모델로 저비용·고속 도입.

## 13. 핵심 포인트 정리 (정책사업 기획 관점)

1. **AX 풀스택을 "인프라+데이터+모델+서비스+거버넌스" 통합 EA로 정의하고, 국가 차원 참조 아키텍처를 공식화**
    
2. **제조·금융·헬스케어·공공 4대 분야별 레퍼런스 AX를 마련해, 공공사업·민간투자 모두 이 구조를 기본으로 설계하도록 유도**
    
3. **국가 GPU·데이터·모델 허브와 AI 거버넌스 툴킷에 공공재성 예산을 집중**하고, 산업별 특화 영역은 민관 합동으로 투자
    
4. **AI 기본법·국가 AI 전략·윤리기준과 AX 거버넌스 레이어를 정합적으로 설계**해, 규제 대응 비용을 줄이고 글로벌 신뢰 확보
    
5. **3단계 로드맵(레퍼런스 정의 → 전국 확산·AX 센터 구축 → K-AX 수출)**으로 정책사업을 구조화해, 단기 가시성과 장기 글로벌 전략을 동시에 달성
