# 제12장. Obsidian — 프롬프트와 작업 아카이빙

> *"AI와의 대화는 휘발된다. 좋은 프롬프트는 자산이다. Obsidian은 그 자산을 쌓는 곳이다."*

---

### 0) 연결 고리 (Bridge)

11장에서 코드를 GitHub로 관리하는 방법을 배웠습니다. 그런데 AI와 협업하다 보면 코드만큼 중요한 자산이 하나 더 생깁니다. 바로 **잘 작동한 프롬프트, 프로젝트 맥락, AI와의 대화 로그**입니다. 이것을 관리하지 않으면 같은 삽질을 반복하게 됩니다. 12장에서는 마크다운 기반 지식 관리 도구 **Obsidian**으로 AI 작업 자산을 체계적으로 쌓는 방법을 다룹니다.

---

### 1) 개념 정의 및 필요성

#### Obsidian이란?

**Obsidian**은 마크다운(.md) 파일 기반의 로컬 지식 관리 도구입니다. 모든 노트가 로컬 파일로 저장되고, 노트 간 양방향 링크와 그래프 뷰로 지식의 연결을 시각화합니다.

**웹:** obsidian.md  
**설치:** 데스크톱 앱 (Windows / macOS / Linux)  
**저장 방식:** 로컬 마크다운 파일 (클라우드 의존 없음)  
**무료 플랜:** 로컬 사용 완전 무료

#### AI 프로젝트에서 Obsidian이 필요한 이유

```
AI 협업 없이 일할 때:
  작업 맥락이 내 머릿속에 있음
  → 다음 날 다시 열면 바로 이어서 작업 가능

AI 협업으로 일할 때:
  작업 맥락이 AI 대화창에 있음
  → 대화창 닫으면 AI가 모든 맥락을 잊음
  → 매번 처음부터 설명 반복 → 시간 낭비

Obsidian 도입 후:
  작업 맥락이 Obsidian 노트에 영구 저장
  → 새 대화 시 노트를 첨부하면 즉시 맥락 복원
  → 검증된 프롬프트를 재사용하여 품질 유지
```

### 3) 프롬프트 아카이빙 시스템

#### 프롬프트 노트 템플릿

검증된 프롬프트를 다음 형식으로 저장합니다.

```markdown
---
tags: [프롬프트, Python, PDF파싱]
생성일: 2026-04-15
마지막사용: 2026-05-01
성공률: ⭐⭐⭐⭐⭐
도구: Claude Code
---

# PDF 병합 셀 파싱 프롬프트

## 사용 상황
pdfplumber로 표를 파싱할 때 병합 셀이 있는 경우

## 프롬프트 본문
```
[역할]
너는 Python PDF 파싱 전문가야.

[작업]
pdfplumber로 아래 PDF를 파싱해줘.
병합 셀(merged cell)이 있는 표 처리 포함.

[제약]
- pdfplumber 사용
- 병합 셀은 상위 셀 값으로 하위 셀을 채울 것
- 금액 필드: 문자열 → 정수 (쉼표·원화기호 제거)
- 주석 한국어
- 오류 시 페이지 번호 포함 로그
```

## 결과 품질
- 일반 표: 완벽 처리
- 2단계 병합: 완벽 처리
- 3단계 이상 병합: 추가 처리 필요 (이슈 #23 참조)

## 관련 노트
- [[KAIB2026-pipeline]]
- [[pdfplumber-tips]]
```

#### 프롬프트 재사용 흐름

```
신규 작업 시작
  ↓
Obsidian에서 유사 프롬프트 검색
(Ctrl+O → 키워드 검색)
  ↓
기존 프롬프트 발견 → 복사 후 수정
  ↓
AI에게 적용 → 결과 확인
  ↓
개선사항 Obsidian에 업데이트
  ↓
다음 사용자(또는 미래의 나)가 더 나은 프롬프트로 시작
```

### 4) 프로젝트 작업 로그 관리

#### 작업 일지 템플릿

```markdown
# 2026-05-01 작업 로그

## 오늘 목표
- [ ] json_structurer.py 병합 셀 버그 수정
- [ ] 단위 테스트 5개 추가
- [ ] SKILL.md 업데이트

## AI 대화 요약

### 세션 1 — 오전 10:00 (Claude Code)
**목표:** 병합 셀 처리 로직 개선
**사용 프롬프트:** [[병합셀-파싱-프롬프트]] 참조
**결과:** parse_merged_cells() 함수 개선 완료
**이슈:** 3단계 이상 중첩 케이스에서 여전히 실패
**다음 세션 시작점:**
  "3단계 이상 중첩 병합 셀 처리가 아직 안 됨.
   중첩 구조를 재귀적으로 처리하는 방식으로 변경 필요."

### 세션 2 — 오후 2:00 (Claude.ai)
**목표:** 테스트 케이스 작성
**결과:** pytest 테스트 8개 작성 완료
**파일:** tests/test_merged_cells.py

## 오늘 발견한 인사이트
- pdfplumber의 bbox 좌표를 이용하면 병합 여부를 더 정확히 감지할 수 있음
- 관련 StackOverflow 답변: [링크]

## 내일 시작점
json_structurer.py 라인 847의 재귀 처리 로직 구현 시작.
SKILL.md의 "현재 이슈" 섹션 업데이트 필요.
```

#### 핵심 원칙: "다음 세션 시작점" 기록

AI와의 대화는 창을 닫으면 맥락이 사라집니다. 매 세션 종료 전 **"다음 세션 시작점"**을 메모해두면, 다음 번에 AI에게 이 한 문단을 붙여넣는 것만으로 즉시 이어서 작업할 수 있습니다.

```
좋은 "다음 세션 시작점" 예시:

"json_structurer.py의 parse_merged_cells() 함수에서
 3단계 이상 중첩 병합 셀 처리가 실패함.
 현재 반복문 방식을 재귀 함수로 변경하려고 함.
 SKILL.md v3.0 첨부 참조."
```

### 5) 양방향 링크 — 지식 연결하기

Obsidian의 가장 강력한 기능은 노트 간 **양방향 링크([[노트명]])**입니다. AI 작업 자산이 서로 연결될수록 검색과 재사용이 쉬워집니다.

```markdown
# KAIB2026-pipeline SKILL.md

## 현재 이슈
- [ ] 병합 셀 3단계 이상 처리 → [[병합셀-재귀처리-연구]] 참조
- [x] PDF 파싱 기본 완성 → [[2026-04-15 작업로그]] 참조

## 사용한 프롬프트
- [[PDF 병합셀 파싱 프롬프트]]
- [[SQLAlchemy 모델 생성 프롬프트]]

## 관련 결정사항
- base_year 동적 처리 방식: [[2026-03-20 아키텍처 결정]] 참조
```

그래프 뷰에서 노트 간 연결이 시각화되면, "이 프로젝트가 어떤 프롬프트와 결정들 위에 세워졌는지"를 한눈에 볼 수 있습니다.

### 6) Obsidian + Claude 직접 연동

Obsidian의 **Local REST API 플러그인**을 설치하면 Claude나 n8n에서 Obsidian 노트를 직접 읽고 쓸 수 있습니다.

```
활용 시나리오:

n8n 워크플로우:
  1. 매일 오전 Claude에게 전날 작업 로그 요약 요청
  2. 요약 결과를 Obsidian Daily Note에 자동 저장

또는:

Claude Code 세션 종료 시:
  "오늘 작업한 내용을 요약해서
   Obsidian의 /04-Daily/2026-05-01.md 에 추가해줘"
  → Local REST API로 파일 직접 업데이트
```

### 7) 실무 시나리오 — AI 프로젝트 지식 베이스 구축

**상황:** 3개월간 진행한 PDF 파싱 프로젝트의 지식을 체계화

```
[구축 순서]

1단계 — 프로젝트 노트 생성:
  "KAIB2026-pipeline" 프로젝트 폴더 생성
  → 작업일지, 이슈추적, 결정사항 파일 생성

2단계 — 프롬프트 아카이빙:
  지금까지 잘 작동한 프롬프트들을 01-Prompts/에 저장
  → 각 프롬프트에 태그, 성공률, 관련 노트 링크 추가

3단계 — SKILL.md 버전 관리:
  00-SKILL-MD/ 에 프로젝트 SKILL.md 저장
  → 버전 변경 시 Obsidian에서도 업데이트

4단계 — 인사이트 기록:
  작업 중 발견한 패턴, 팁, 주의사항을 Tools/ 노트에 추가
  → "pdfplumber에서 bbox를 이용한 병합 셀 감지"

5단계 — 재사용:
  새 프로젝트 시작 시 관련 노트 검색
  → 기존 프롬프트 + SKILL.md 재활용
  → 첫 날부터 이전 프로젝트의 노하우 활용
```

### 8) 안티 패턴 (Anti-Pattern)

**① 정리하려고 너무 완벽한 구조를 만들려 함**
처음부터 완벽한 폴더 구조를 설계하려다 정작 노트를 하나도 못 씁니다. 일단 Daily 폴더에 자유롭게 기록하고, 나중에 옮기는 방식이 현실적입니다.

**② 프롬프트만 저장하고 결과 품질을 기록 안 함**
같은 프롬프트라도 상황에 따라 결과가 다릅니다. 언제, 어떤 조건에서, 어떤 결과가 나왔는지를 함께 기록해야 재사용 가치가 있습니다.

**③ Obsidian을 너무 많은 용도로 사용**
Obsidian은 AI 작업 자산 관리에 집중하세요. 개인 일정, 쇼핑 목록 등과 섞이면 작업 관련 노트를 찾기 어려워집니다.

### 9) 트러블슈팅 & 주의사항

**Q. 노트가 많아질수록 검색이 느려집니다.**
→ Obsidian은 로컬 파일 기반이라 노트 수만 개도 빠르게 검색합니다. 느려진다면 불필요한 첨부 파일(이미지, PDF)이 볼트 안에 너무 많은 경우입니다. 첨부 파일은 별도 외부 폴더에 저장하세요.

**Q. 팀원과 Obsidian 노트를 공유하고 싶습니다.**
→ 볼트 폴더를 GitHub에 올리거나 Obsidian Sync(유료) 또는 iCloud/Dropbox로 동기화할 수 있습니다. GitHub 방식이 버전 관리도 되어 가장 권장합니다.

**Q. 모바일에서도 접근하고 싶습니다.**
→ Obsidian 모바일 앱(iOS/Android)을 설치하고 iCloud 또는 Obsidian Sync로 동기화하면 됩니다.

> **TIP:** Obsidian의 **Daily Notes 플러그인**을 활성화하면 `Ctrl+Shift+D`로 오늘 날짜 노트가 자동 생성됩니다. 매일 작업 시작 시 Daily Note를 열고 그날의 AI 세션을 기록하는 습관이 가장 빠르게 지식 베이스를 쌓는 방법입니다.

### 10) 한 줄 요약

> 💡 **Key Takeaway:** Obsidian은 AI와의 모든 작업 자산 — 프롬프트, 맥락, 인사이트 — 을 **연결된 지식으로 축적**하여 다음 프로젝트를 처음보다 훨씬 빠르고 높은 품질로 시작하게 해주는 지식 안전망입니다.
