# 제17장. SKILL.md 실전 — 재사용 가능한 AI 지시서 만들기

> *"같은 설명을 AI에게 반복하는 것은 낭비다. SKILL.md는 그 낭비를 없앤다."*

---

### 0) 연결 고리 (Bridge)

4장에서 SKILL.md의 개념과 기본 구조를 소개했고, 7장에서 Claude Code 전용 CLAUDE.md를 다뤘습니다. 12장에서는 Obsidian으로 SKILL.md를 버전 관리하는 방법을 배웠습니다. 이제 17장에서는 SKILL.md를 **실제로 어떻게 설계하고, 발전시키고, 팀과 공유하는지** 실전 수준에서 다룹니다. 잘 만들어진 SKILL.md 하나는 수백 번의 반복 설명을 대체합니다.

---

### 1) 개념 정의 및 필요성

#### SKILL.md가 해결하는 4가지 문제

```
문제 1 — 맥락 소실:
  새 대화를 시작할 때마다 프로젝트 배경을 처음부터 설명
  → SKILL.md 첨부 한 번으로 즉시 해결

문제 2 — 일관성 없는 코드:
  "지난번엔 이렇게 했는데 이번엔 왜 다르게 했지?"
  → 코딩 스타일, 네이밍 규칙, 금지 패턴을 SKILL.md에 명시

문제 3 — 반복 설명:
  "httpx 써줘, requests 말고" → 10번 반복
  → SKILL.md의 "금지 사항"에 한 번만 기록

문제 4 — 온보딩 비용:
  새 팀원이 합류할 때 AI 작업 관례를 처음부터 설명
  → SKILL.md = 팀의 AI 작업 가이드북
```

---

### 2) SKILL.md 설계 원칙

#### 5가지 설계 원칙

**원칙 1 — 짧고 핵심만**  
500줄 이하를 목표로 합니다. AI가 SKILL.md를 읽는 데 컨텍스트를 너무 많이 소비하면 실제 작업에 쓸 컨텍스트가 줄어듭니다.

**원칙 2 — 행동 지향 문장**  
"~한다" 형태의 명확한 지시로 작성합니다.

```markdown
# 나쁜 예:
금액 필드는 정수형이 바람직할 수 있습니다.

# 좋은 예:
금액 필드는 항상 정수(int) 타입으로 처리한다. float 금지.
```

**원칙 3 — 부정 규칙 명시**  
"하지 말아야 할 것"을 명시하면 AI가 잘못된 방향으로 가는 것을 방지합니다.

```markdown
## 금지 사항
- requests 라이브러리 사용 금지 → httpx 사용
- print() 디버깅 금지 → logging 모듈 사용
- 하드코딩된 경로 금지 → 환경 변수 또는 config 파일 사용
```

**원칙 4 — 예시 포함**  
규칙보다 예시가 더 강력합니다. 한 줄의 코드 예시가 세 줄의 설명보다 명확합니다.

```markdown
## 함수 작성 규칙
모든 함수에 타입 힌트와 한국어 docstring을 작성한다.

예시:
def calculate_total(items: list[dict]) -> int:
    """금액 목록의 합계를 계산한다.

    Args:
        items: 금액 딕셔너리 목록. 각 항목에 'amount' 키 필요.
    Returns:
        전체 금액의 합계 (원 단위 정수)
    """
    return sum(item['amount'] for item in items)
```

**원칙 5 — 살아있는 문서**  
SKILL.md는 프로젝트 시작에 한 번 쓰고 끝나는 문서가 아닙니다. 새로운 결정, 해결된 이슈, 발견한 패턴을 지속적으로 업데이트해야 합니다.

### 3) SKILL.md 유형별 템플릿

#### 유형 1 — Python 파이프라인 프로젝트

```markdown
# [프로젝트명] SKILL.md
버전: v2.0 | 업데이트: 2026-05-01

## 1. 프로젝트 개요
- **목적**: [한 문장으로 무엇을 만드는지]
- **언어**: Python 3.11
- **현재 단계**: [개발/테스트/운영]

## 2. 폴더 구조
```
/src/
  step1_collect.py   ← 1단계: 데이터 수집
  step2_parse.py     ← 2단계: 파싱·정제
  step3_store.py     ← 3단계: DB 저장
/data/               ← 원본 파일 (수정 금지)
/output/             ← 처리 결과물
/tests/              ← pytest 단위 테스트
```

## 3. 코딩 규칙
- 타입 힌트 필수 (모든 함수 매개변수·반환값)
- docstring 필수 (한국어)
- HTTP 요청: httpx 사용 (requests 금지)
- 로깅: logging 모듈 (print 금지)
- 예외 처리: 빈 except 금지, 구체적 예외 명시

## 4. 데이터 규칙
- 금액: 항상 int (쉼표·원화기호 제거 후 변환)
- 날짜: YYYY-MM-DD 문자열 (datetime 객체는 DB 저장 시만)
- None 처리: 함수 입력에서 항상 검사

## 5. 금지 사항
- /data/ 폴더 파일 직접 수정 금지
- 하드코딩된 파일 경로 금지 (환경 변수 사용)
- magic number 금지 (상수로 분리)

## 6. 용어 사전
| 한국어 | 코드 표현 | 설명 |
|--------|----------|------|
| 기준연도 | base_year | int, 예: 2026 |
| 세입 | revenue | 정부 수입 |
| 세출 | expenditure | 정부 지출 |
| 병합 셀 | merged_cell | PDF 표의 spanning cell |

## 7. 현재 이슈
- [ ] 3단계 이상 중첩 병합 셀 처리 (step2_parse.py:847)
- [x] 기본 파싱 로직 완성
- [x] 단위 테스트 작성

## 8. 의존성
```

pandas==2.2.0
sqlalchemy==2.0.0
pydantic==2.6.0
httpx==0.27.0

```markdown
- 마크다운 형식 사용 금지 (# ** 등)

- 모호한 수식어 금지 ("다양한", "여러")

1. 개요 (□)

3. 향후 계획 (□)
```

### 5) SKILL.md를 AI에게 전달하는 방법

#### 방법별 비교

| 방법 | 장점 | 단점 | 추천 상황 |
|------|------|------|----------|
| **파일 첨부** | 가장 확실 | 매번 첨부 필요 | 일반 대화 |
| **Claude Projects** | 자동 포함 | Projects 내에서만 | 반복 프로젝트 |
| **CLAUDE.md** | 자동 인식 | Claude Code 전용 | 터미널 에이전트 |
| **시스템 프롬프트** | 항상 적용 | API 사용 시만 | 자동화 파이프라인 |

#### Claude Projects에 SKILL.md 등록

```
1. claude.ai → 좌측 사이드바 → "+ New Project"
2. 프로젝트 이름 설정 (예: KAIB2026 파이프라인)
3. "Project Instructions" 편집
4. SKILL.md 내용 붙여넣기 (또는 핵심 요약만)
5. 파일 첨부: SKILL.md 파일 직접 업로드도 가능

결과:
해당 Project 내 모든 대화에 SKILL.md 자동 적용
→ 매번 첨부 불필요
→ 팀원을 Project에 초대하면 같은 컨텍스트 공유
```

### 8) 안티 패턴 (Anti-Pattern)

**① 너무 길게 만들기**
500줄을 초과하는 SKILL.md는 AI가 중간 내용을 무시합니다. 핵심 규칙만 남기고 상세 내용은 별도 문서로 분리하세요.

**② 업데이트 없이 방치**
프로젝트가 발전했는데 SKILL.md는 초기 상태 그대로면 AI에게 잘못된 컨텍스트를 주는 것과 같습니다. 중요한 결정이 생길 때마다 바로 업데이트하세요.

**③ 모든 프로젝트에 동일한 SKILL.md 사용**
Python 파이프라인과 React 웹앱은 전혀 다른 규칙이 필요합니다. 프로젝트 유형마다 별도 SKILL.md를 만드세요. 공통 부분은 "팀 공통 SKILL.md"로 분리해서 참조하는 방식을 권장합니다.

### 9) 트러블슈팅 & 주의사항

**Q. SKILL.md를 첨부해도 AI가 규칙을 무시합니다.**
→ 중요한 규칙은 SKILL.md 상단에 배치하세요. AI는 프롬프트 앞부분을 더 주의깊게 읽습니다. "## 절대 규칙"처럼 강조 섹션을 만들고 핵심 3가지만 최상단에 배치하는 방법도 효과적입니다.

**Q. SKILL.md가 길어질수록 AI 응답이 느려집니다.**
→ SKILL.md의 내용은 컨텍스트 윈도우를 소비합니다. 500줄 이내로 유지하고, 프로젝트 단계에 맞게 필요 없어진 내용은 과감히 삭제하세요.

**Q. 팀원마다 다른 SKILL.md를 쓰고 있습니다.**
→ GitHub에 팀 공통 SKILL.md를 올리고, 개인 커스터마이즈는 별도 "개인 추가 규칙" 섹션에만 허용하는 정책을 만드세요.

> **TIP:** 새 프로젝트를 시작할 때 Claude에게 "이 프로젝트의 SKILL.md 초안을 만들어줘"라고 요청하세요. 프로젝트 목적과 기술 스택만 알려주면 Claude가 기본 구조를 잡아줍니다. 이후 작업하면서 내용을 채워가는 것이 가장 효율적입니다.
