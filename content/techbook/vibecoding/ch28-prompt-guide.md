# 제28장. 좋은 프롬프트 쓰는 법

> *"AI에게 잘 말하는 것은 기술이다. 그 기술은 배울 수 있다."*

---

### 0) 연결 고리 (Bridge)

4장에서 프롬프트 설계의 기본 구조(역할·맥락·작업·조건·형식)를 배웠습니다. 28장에서는 실제로 프롬프트 품질을 높이는 **구체적인 기법들**을 다룹니다. 같은 목적이라도 어떻게 말하느냐에 따라 AI의 결과물 품질이 크게 달라집니다. 이 장은 독립적으로 참고 자료처럼 활용할 수 있습니다.

---

### 1) 프롬프트 품질이 결과를 결정하는 이유

```
AI는 입력에 충실합니다.
모호한 입력 → 모호한 출력
구체적인 입력 → 구체적인 출력

실험:
같은 작업, 두 가지 프롬프트

[프롬프트 A]
"보고서 요약해줘"

[프롬프트 B]
"다음 보고서를 3문장으로 요약해줘.
 대상: 비전문가 관리자
 포함할 것: 핵심 수치, 가장 중요한 인사이트 1가지
 제외할 것: 기술적 세부사항
 문체: 평어체"

프롬프트 B의 결과가 A보다
훨씬 목적에 맞는 요약이 됩니다.
```

---

### 2) 핵심 기법 10가지

#### 기법 1 — 역할 부여 (Role Prompting)

AI에게 전문가 역할을 부여하면 해당 도메인의 관점과 용어로 답합니다.

```
[역할 없음]
"Python 코드를 최적화해줘"

[역할 부여]
"너는 10년 경력의 Python 성능 최적화 전문가야.
 다음 코드의 병목 지점을 찾고, 각 최적화의 이유를 설명해줘."

→ 더 전문적이고 설명이 풍부한 결과
```

#### 기법 2 — 입출력 명세 (I/O Specification)

```
[명세 없음]
"이 데이터를 정리해줘"

[명세 있음]
"다음 데이터를 정리해줘.

 입력: CSV 형식, 컬럼: 날짜(YYYY-MM-DD), 부서명, 금액(쉼표 포함)
 출력: JSON 형식
   {
     'department': '부서명',
     'monthly_total': {'2026-01': 1234567, ...}
   }
 조건: 날짜를 YYYY-MM 단위로 그룹화"
```

#### 기법 3 — 예시 제공 (Few-Shot Prompting)

```
원하는 출력 형식의 예시를 1~3개 포함하면
AI가 그 패턴을 파악하고 동일한 형식으로 생성합니다.

"다음 형식으로 공고 요약을 작성해줘.

예시 입력:
  [AI 바우처 2026년 2차 공고 — NIPA — 마감: 2026.06.30]

예시 출력:
  📌 AI 바우처 2차 | NIPA | D-45
  → 중소기업 AI 솔루션 도입 지원, 최대 1억 원
  → 신청: nipa.kr

이제 다음 공고들을 같은 형식으로 작성해줘:
[공고 목록]"
```

#### 기법 4 — 단계별 사고 유도 (Chain of Thought)

```
복잡한 분석이나 추론이 필요할 때,
"단계별로 생각해줘"라는 지시가 정확도를 높입니다.

"다음 예산 배분 문제를 단계별로 분석해줘:
 1. 각 부서의 현재 상황 파악
 2. 제약 조건 확인
 3. 배분 원칙 적용
 4. 최종 배분안 도출
 5. 예상 문제점 검토

각 단계의 근거를 명확히 제시해줘."
```

#### 기법 5 — 부정 지시 (Negative Constraints)

```
원하지 않는 것을 명시하면 AI가 그 방향을 피합니다.

"보고서 요약을 작성해줘.
 ✅ 포함: 핵심 수치, 결론, 권고사항
 ❌ 제외: 방법론 설명, 기술적 세부사항
 ❌ 금지: '다양한', '여러', '등' 같은 모호한 표현
 ❌ 금지: 글머리표 없는 산문 형식"
```

#### 기법 6 — 출력 형식 고정 (Format Locking)

```
자동화 파이프라인에서 AI 출력을 파싱해야 할 때,
출력 형식을 엄격하게 고정합니다.

"분석 결과를 반드시 다음 JSON 형식으로만 출력해줘.
 다른 설명이나 마크다운 없이 JSON만:

 {
   'importance': '상/중/하 중 하나',
   'summary': '2줄 이내 요약',
   'deadline': 'YYYY-MM-DD 또는 null',
   'tags': ['태그1', '태그2']
 }"
```

#### 기법 7 — 컨텍스트 최소화 (Context Scoping)

```
길고 복잡한 배경을 모두 제공하는 것보다
현재 작업에 필요한 맥락만 정확히 제공하는 것이 효과적입니다.

[나쁜 예 — 너무 많은 컨텍스트]
"우리 회사는 2003년에 설립된 ICT 기업으로... (3페이지)
 이 배경하에 이 함수를 수정해줘."

[좋은 예 — 필요한 것만]
"다음 함수는 PDF 표를 파싱하는 코드야.
 입력: list[list[str | None]]
 문제: 3단계 이상 중첩 병합 셀에서 IndexError
 해결: 재귀 방식으로 리팩터링해줘."
```

#### 기법 8 — 확인 요청 (Verification Request)

```
중요한 작업에서 AI에게 스스로 검토를 요청합니다.

"코드를 작성한 후, 작성 전에 다음을 확인해줘:
 □ 존재하지 않는 라이브러리/메서드를 사용하지 않았는가?
 □ None 처리가 필요한 모든 지점에 처리가 있는가?
 □ SKILL.md의 모든 규칙을 지켰는가?

 확인 완료 후 코드를 제시해줘."
```

#### 기법 9 — 반복 개선 (Iterative Refinement)

```
완벽한 프롬프트를 처음부터 만들려 하지 않습니다.
빠르게 결과를 받고, 부족한 부분을 피드백하며 개선합니다.

라운드 1:
  "PDF 파싱 코드를 만들어줘."
  → 결과 확인

라운드 2:
  "좋아. 근데 병합 셀 처리가 빠졌어. 추가해줘."
  → 결과 확인

라운드 3:
  "금액 파싱에서 (△123) 패턴을 처리 못 해. 수정해줘."
  → 결과 확인

→ 3라운드 후 완성된 결과가
  첫 번째 완벽한 프롬프트보다 더 나은 경우가 많습니다.
```

#### 기법 10 — 메타 프롬프트 (Meta Prompting)

```
더 좋은 프롬프트를 AI에게 만들게 합니다.

"내가 다음 작업을 위한 프롬프트를 만들려고 해.
 작업: PDF 병합 셀 처리 Python 코드 생성
 나의 초안: '병합 셀 처리 코드 만들어줘'
 
 이 프롬프트를 더 구체적이고 효과적으로
 개선해줘. SKILL.md 스타일로."

→ AI가 개선된 프롬프트를 제안
→ 그 프롬프트를 사용해서 다시 요청
```

### 3) 상황별 프롬프트 패턴

#### 코드 생성

```
[기본 패턴]
역할: "Python [분야] 전문가로서"
작업: 함수명, 입력, 출력 명세
제약: 사용 라이브러리, 금지 패턴
품질: "타입 힌트, 한국어 docstring, 방어 코드 포함"
검증: "사용한 라이브러리가 실제 존재하는지 확인"
```

#### 문서 작성

```
[기본 패턴]
독자: "비전문가 [직군]을 위해"
분량: "A4 N페이지 수준, 총 M단어 이내"
구조: "목차: 1.개요 2.현황 3.시사점"
문체: "공문서체 / 평어체 / 논문체"
금지: "모호한 표현, 수동태 남발"
```

#### 데이터 분석

```
[기본 패턴]
데이터: "첨부 파일의 [컬럼명] 컬럼들을 분석해줘"
관점: "전월 대비 변화, 이상값 감지에 초점"
출력: "수치 기반 인사이트 3가지 + 시각화 코드"
주의: "상관관계를 인과관계로 표현하지 말 것"
```

#### 번역·문체 변환

```
[기본 패턴]
원문: [원문 첨부]
목표 독자: "한국 공무원, 50대"
목표 문체: "격식체, 공문서 스타일"
유지: "수치, 고유명사, 날짜는 그대로"
금지: "직역, 어색한 표현"
```

### 4) 흔한 프롬프트 실수 10가지

```
실수 1: 목표가 없는 질문
  ❌ "이 코드 좋아?"
  ✅ "이 코드에서 성능 개선 가능한 부분을 찾아줘"

실수 2: 형식 미지정
  ❌ "장단점 알려줘"
  ✅ "장점 3가지, 단점 3가지를 표로 정리해줘"

실수 3: 한 번에 너무 많이
  ❌ "파싱하고 정제하고 저장하고 보고서도 만들어줘"
  ✅ 작업을 분리해서 순서대로 요청

실수 4: 수정 시 원본 재제시 안 함
  ❌ "아까 그 코드에서 None 처리 추가해줘"
  ✅ [코드 다시 붙여넣기] + "None 처리를 추가해줘"

실수 5: 부정적 피드백만 제공
  ❌ "이거 틀렸어"
  ✅ "3번째 함수에서 병합 셀이 2배로 집계돼.
      예상: 1234567, 실제: 2469134"

실수 6: 컨텍스트 없는 전문 용어
  ❌ "KAIB 기준으로 처리해줘"
  ✅ "KAIB(한국인공지능예산) 2026 기준, 즉 base_year=2026으로"

실수 7: 출력 형식 미지정 (자동화 시)
  ❌ "중요도를 분류해줘"
  ✅ "중요도를 '상', '중', '하' 세 값 중 하나로만 반환해줘"

실수 8: 검증 요청 생략
  → 항상 "존재하지 않는 함수 있으면 알려줘" 추가

실수 9: 대화가 길어져도 SKILL.md 재첨부 안 함
  → 20번 이상 대화 후에는 SKILL.md를 다시 첨부

실수 10: AI 출력을 그대로 신뢰
  → 수치, 날짜, 고유명사는 반드시 원본 확인
```

### 5) 프롬프트 개선 전후 비교

#### 사례 1 — 코드 생성

```
[Before]
"엑셀 자동화 코드 만들어줘"

[After]
"Python 3.11로 다음 Excel 자동화 코드를 작성해줘.

 입력: data.xlsx (A열: 날짜 YYYY-MM-DD, B열: 부서명, C열: 금액 정수)
 출력: summary.xlsx (부서별 월간 합계, 시트명: '월간요약')
 
 규칙:
 - openpyxl 사용
 - 헤더 행: 파란색 배경, 흰색 글씨, 굵게
 - 금액 셀: 쉼표 형식 (1,234,567)
 - 타입 힌트, 한국어 docstring 필수
 - 파일 없으면 FileNotFoundError, 메시지: 한국어"
```

#### 사례 2 — 문서 요약

```
[Before]
"이 보고서 요약해줘"

[After]
"다음 AI 정책 보고서를 요약해줘.

 독자: 비IT 배경의 정부 관리자
 분량: 5문장 이내
 필수 포함: 핵심 정책 목표, 예산 규모, 기대 효과
 문체: 격식체, 명사형 종결
 금지: 기술 용어, 약어 (풀어서 설명)"
```

### 6) 프롬프트 아카이빙 — 좋은 프롬프트는 자산이다

```
검증된 프롬프트를 Obsidian에 저장하는 템플릿:

---
tags: [프롬프트, 코드생성, Python]
생성일: 2026-05-01
성공률: ⭐⭐⭐⭐⭐
도구: Claude Sonnet 4.6
---

# [프롬프트 이름]

## 사용 상황
[어떤 작업에 쓰는 프롬프트인지]

## 프롬프트 본문
```
[프롬프트 전문]
```

## 결과 품질
[어떤 결과가 나왔는지, 주의사항]

## 수정 이력
- v1.0: 초안
- v1.1: 출력 형식 JSON으로 고정
```

### 7) 한 줄 요약

> 💡 **Key Takeaway:** 좋은 프롬프트는 **역할·입출력 명세·예시·부정 지시·출력 형식 고정** 다섯 가지를 갖추며, 완벽한 첫 번째 프롬프트보다 빠른 피드백으로 반복 개선하는 것이 더 효과적입니다.
