# 제2장. 러버블 시작하기

> _환경 설정부터 첫 앱 배포까지 — 손으로 직접 해보며 익히는 러버블 입문_

---

## 0) 연결 고리

> 🔗 1장에서 러버블이 무엇이고 왜 등장했는지를 이해했습니다. 이제 직접 계정을 만들고, 인터페이스를 살펴보고, 첫 번째 앱을 손으로 만들어 볼 차례입니다. 이 장을 마치면 러버블의 전체 워크플로우를 한 번씩 체험하게 됩니다.

---

## 2.1 계정 생성 및 플랜 선택 가이드

### 1) 계정 생성

러버블 계정 생성은 매우 간단합니다. 다음 단계를 따라 진행합니다.

**① 러버블 홈페이지 접속**

브라우저에서 [https://lovable.dev](https://lovable.dev/)에 접속합니다. "Start building for free" 버튼을 클릭합니다.

**② 회원가입 방법 선택**

러버블은 두 가지 회원가입 방법을 제공합니다:

- **Google 계정으로 로그인**: 가장 빠른 방법입니다. Google 계정이 있다면 클릭 한 번으로 가입이 완료됩니다.
- **이메일/비밀번호**: 이메일 주소와 비밀번호를 직접 입력합니다.

> 💡 **TIP**
> 
> 개발 관련 작업에는 **GitHub 계정과 연결된 Google 계정**을 사용하는 것을 권장합니다. 이후 GitHub 연동 설정 시 동일한 계정을 사용하면 권한 관리가 훨씬 간편해집니다.

**③ 워크스페이스(Workspace) 설정**

가입 후 워크스페이스 이름을 설정합니다. 워크스페이스는 여러 프로젝트를 담는 상위 컨테이너입니다. 개인 사용자라면 자신의 이름이나 브랜드명을 사용하고, 팀이라면 조직명을 사용합니다.

---

### 2) 플랜 선택 가이드

러버블은 **Free, Pro, Business, Enterprise** 네 가지 플랜을 제공합니다. 각 플랜의 특징을 정확히 이해하고 자신의 용도에 맞는 플랜을 선택해야 합니다.

|구분|**Free**|**Pro**|**Business**|**Enterprise**|
|---|---|---|---|---|
|**가격**|무료|$25/월~|$50/월~|협의|
|**연간 결제**|—|$21/월~|$42/월~|협의|
|**월 크레딧**|없음|100개~|100개~|맞춤형|
|**일일 크레딧**|5개/일 (최대 30개/월)|5개/일 (최대 150개/월)|5개/일 (최대 150개/월)|—|
|**비공개 프로젝트**|✅|✅|✅|✅|
|**커스텀 도메인**|❌|✅|✅|✅|
|**코드 편집(Dev Mode)**|❌|✅|✅|✅|
|**Lovable 배지 제거**|❌|✅|✅|✅|
|**SSO 지원**|❌|❌|✅|✅|
|**팀 협업**|무제한 초대|무제한 초대|역할/권한 관리|고급 거버넌스|
|**데이터 학습 제외**|❌|❌|✅|✅|
|**재사용 디자인 템플릿**|❌|❌|✅|✅|
|**추천 대상**|입문·탐색|1인 창업자·프리랜서|팀·스타트업|대기업|

> 📝 **NOTE**
> 
> **2025년 말 업데이트 기준**: 이전에는 비공개 프로젝트가 유료 플랜 전용이었지만, 현재는 **Free 플랜도 비공개 프로젝트**를 사용할 수 있습니다. 또한 팀 협업(무제한 멤버 초대)도 Free와 Pro 플랜 모두 지원합니다. 자세한 내용은 [공식 요금제 페이지](https://lovable.dev/pricing)에서 확인하세요.

**플랜 선택 가이드:**

- **처음 러버블을 탐색하는 경우** → Free 플랜으로 시작 (일 5크레딧으로 기본 기능 체험)
- **개인 프로젝트나 MVP를 빠르게 만들려는 경우** → Pro 100 ($25/월)
- **클라이언트 프로젝트 또는 프리랜서** → Pro 200~400 ($50~100/월)
- **팀 단위 협업, SSO 필요** → Business 플랜
- **학생** → Pro 플랜 50% 할인 (대학 이메일로 인증)

> ⚠️ **WARNING**
> 
> Pro 플랜으로 업그레이드 시 주의사항: 예를 들어 현재 100 크레딧 플랜에서 200 크레딧 플랜으로 업그레이드하면, **추가로 200 크레딧이 생기는 것이 아닙니다.** 총 크레딧이 200으로 설정되므로, 이미 100을 사용했다면 100 크레딧만 추가됩니다. 업그레이드 타이밍을 고려하세요.

## 2.2 크레딧(Credit) 시스템 완전 이해

러버블의 크레딧 시스템은 처음에는 다소 복잡하게 느껴질 수 있습니다. 그러나 구조를 이해하면 효율적으로 활용할 수 있습니다.

### 1) 크레딧의 두 가지 종류

러버블에는 두 종류의 크레딧이 동시에 존재합니다:

```
┌─────────────────────────────────────────────┐
│              크레딧 구성                      │
├─────────────────┬───────────────────────────┤
│  월 구독 크레딧  │ 플랜에 따라 매달 지급      │
│                 │ (Free 제외, 사용 후 이월)   │
├─────────────────┼───────────────────────────┤
│  일일 크레딧    │ 매일 5개 지급 (전 플랜)     │
│                 │ 당일 미사용분 소멸 (이월 X) │
└─────────────────┴───────────────────────────┘
```

**월 구독 크레딧(Monthly Credits)**

- 유료 플랜 구독 시 매월 부여되는 크레딧입니다.
- 미사용 크레딧은 **다음 달로 이월**됩니다 (구독 유지 시).
- 월간 플랜: 다음 달까지 이월 / 연간 플랜: 연간 구독 기간 동안 이월

**일일 크레딧(Daily Credits)**

- **모든 플랜** 사용자에게 매일 5개씩 지급됩니다.
- 당일 자정(UTC)에 리셋되며, **미사용분은 소멸**됩니다 (이월 불가).
- Free 플랜: 일일 크레딧만 사용 (최대 30개/월)
- 유료 플랜: 일일 크레딧 + 월 구독 크레딧 동시 사용 가능

> 💡 **TIP**
> 
> 러버블은 일일 크레딧을 먼저 소비하고, 소진되면 월 구독 크레딧을 사용합니다. 따라서 **매일 5개의 일일 크레딧을 최대한 활용**하는 것이 크레딧 절약의 핵심입니다. 하루를 건너뛰면 5 크레딧이 그냥 사라집니다.

---

### 2) 크레딧 소비 방식 — 복잡도 기반 과금

러버블은 메시지 하나당 1 크레딧이 아니라, **요청의 복잡도**에 따라 크레딧이 소비됩니다:

|요청 유형|작업 내용|크레딧 소비|
|---|---|---|
|간단한 스타일 변경|버튼 색상을 회색으로 변경|0.5 크레딧|
|컴포넌트 삭제|푸터 제거|0.9 크레딧|
|기능 추가|로그인·인증 기능 추가|1.2 크레딧|
|복잡한 페이지 생성|이미지 포함 랜딩 페이지 전체 생성|2.0 크레딧|
|Chat Mode 메시지|코드 변경 없이 질문만|1.0 크레딧|

> 📝 **NOTE**
> 
> 각 메시지의 정확한 크레딧 소비량을 확인하려면 채팅 기록에서 해당 메시지에 마우스를 올린 후 **세 점(···) 아이콘**을 클릭하면 됩니다. 이 기능을 활용하면 자신의 사용 패턴을 파악하고 프롬프트를 최적화할 수 있습니다.

---

### 3) 크레딧 추가 구매(Top-up)

유료 플랜 사용자는 구독 변경 없이 일회성으로 크레딧을 추가 구매할 수 있습니다:

- **구매 단위**: 50 크레딧 단위 (최소 50, 최대 1,000)
- **가격**: Pro 플랜 $15 / 50 크레딧, Business 플랜 $30 / 50 크레딧
- **유효기간**: 최근 구매일로부터 12개월

> ⚠️ **WARNING**
> 
> Top-up 크레딧의 단가($0.30/크레딧)는 **월 구독 크레딧의 단가($0.25/크레딧)보다 비쌉니다.** Top-up을 반복적으로 구매하게 된다면 상위 플랜으로 업그레이드하는 것이 경제적입니다.

---

### 4) 크레딧 잔액 확인 방법

1. 대시보드에서 **워크스페이스 이름 클릭** → 크레딧 잔량 표시
2. 프로젝트 에디터 내에서 **프로젝트 이름 클릭** → 크레딧 바(Bar) 확인
    - **회색 부분**: 이번 결제 주기에 이미 사용한 크레딧
    - **파란색 부분**: 남은 크레딧 (유형별로 구분 표시)

## 2.3 인터페이스 완전 투어

러버블의 인터페이스는 크게 **좌측 패널**과 **우측 미리보기 영역**으로 구성됩니다.

### 1) 전체 레이아웃 구조

```
┌──────────────────────────────────────────────────────────┐
│                     상단 메뉴바                            │
│  [프로젝트명]  [Publish]  [Share]  [GitHub]  [설정]        │
├────────────────────┬─────────────────────────────────────┤
│                    │                                     │
│   좌측 패널         │         우측 미리보기 영역            │
│                    │                                     │
│  ┌──────────────┐  │   ┌───────────────────────────────┐ │
│  │ 채팅 입력창  │  │   │                               │ │
│  │ (프롬프트)   │  │   │     앱 실시간 미리보기          │ │
│  └──────────────┘  │   │                               │ │
│                    │   │                               │ │
│  채팅 히스토리      │   └───────────────────────────────┘ │
│  (메시지 기록)      │                                     │
│                    │   [Preview] [Code] 탭 전환           │
└────────────────────┴─────────────────────────────────────┘
```

---

### 2) 주요 영역별 상세 설명

**① 채팅 입력창 (Chat Input)**

화면 좌측 하단에 위치한 프롬프트 입력 영역입니다. 여기서 러버블 AI에게 원하는 것을 설명합니다.

입력창 하단의 아이콘들:

- **Edit 버튼 (✏️)**: Visual Edit 모드 전환 — 클릭 후 미리보기의 요소를 직접 선택하여 수정
- **Chat 버튼**: Chat Mode — 코드를 수정하지 않고 AI와 대화만 (크레딧 1 소비)
- **Add 버튼 (+)**: 파일, 이미지, URL 등을 첨부하여 컨텍스트로 제공

**② 미리보기 패널 (Preview Panel)**

우측에 앱의 실시간 미리보기가 표시됩니다. 코드가 생성되는 즉시 반영됩니다.

- **Preview 탭**: 앱의 시각적 결과물 확인
- **Code 탭 (Dev Mode)**: 생성된 소스 코드를 에디터에서 직접 수정 (유료 플랜)
- **Diff 뷰**: 최근 변경 사항을 이전 코드와 비교 (유료 플랜)

**③ 상단 메뉴바**

|버튼|기능|
|---|---|
|**Publish**|앱을 lovable.app 도메인에 배포 / 업데이트|
|**Share**|프로젝트 공유 링크 생성|
|**GitHub**|GitHub 저장소 연동 설정|
|**설정(⚙️)**|프로젝트 설정, Knowledge 설정, Supabase 연동 등|

> 💡 **TIP**
> 
> **Knowledge 설정**은 AI에게 프로젝트의 고정 컨텍스트를 제공하는 매우 유용한 기능입니다. 예를 들어 "이 앱은 한국어 사용자를 대상으로 합니다", "배색은 `#2563EB` 블루와 화이트를 기본으로 합니다"와 같은 내용을 Knowledge에 설정해 두면, 매 프롬프트마다 이를 반복할 필요가 없습니다. 자세한 활용법은 **3.4절**에서 다룹니다.

### 3) 세 가지 모드 완전 비교

러버블 2.0 기준으로 세 가지 작업 모드가 있습니다:

|구분|**Chat Mode**|**Visual Edit Mode**|**Dev Mode (Code Mode)**|
|---|---|---|---|
|**주요 기능**|AI와 대화로 기능 구현|클릭으로 UI 요소 직접 수정|소스 코드 직접 편집|
|**크레딧 소비**|있음 (복잡도 기반)|**없음** (크레딧 소비 없음)|**없음** (크레딧 소비 없음)|
|**코드 수정 여부**|AI가 코드 생성|AI 없이 즉시 반영|직접 코드 수정|
|**사용 대상**|모든 플랜|모든 플랜|**유료 플랜만**|
|**적합한 작업**|기능 추가·버그 수정|텍스트·색상·여백 수정|세밀한 코드 수정|

> 📝 **NOTE**
> 
> **Visual Edit Mode는 크레딧을 소비하지 않습니다.** 텍스트 수정, 색상 변경, 버튼 크기 조정 같은 디자인 트윅(Tweak)은 Visual Edit으로 처리하고, 새로운 기능 구현이나 로직 변경만 Chat Mode로 요청하면 크레딧을 크게 절약할 수 있습니다.

## 2.4 첫 번째 앱 실습 — 할 일 목록(Todo App) 10분 완성

이제 직접 첫 번째 앱을 만들어 보겠습니다. 이 실습의 목표는 러버블의 전체 워크플로우(프롬프트 → 생성 → 미리보기 → 수정 → 배포)를 한 번씩 경험하는 것입니다.

### STEP 1: 새 프로젝트 생성

대시보드에서 **"+ New Project"** (또는 "Start building") 버튼을 클릭합니다. 빈 에디터가 열리면 준비 완료입니다.

---

### STEP 2: 초기 프롬프트 입력

채팅 입력창에 다음 프롬프트를 입력합니다:

```
할 일 목록(Todo) 앱을 만들어 주세요.

기능 요구사항:
- 할 일 항목 추가 (입력창 + 추가 버튼)
- 각 항목 체크박스로 완료 처리 (완료된 항목은 취소선 표시)
- 항목 삭제 버튼
- 완료된 항목 수 / 전체 항목 수 표시

디자인 요구사항:
- 깔끔하고 미니멀한 디자인
- 주요 색상: 파란색 (#2563EB)
- 모바일에서도 잘 보이는 반응형 레이아웃
```

입력 후 **Enter** 키 또는 전송 버튼을 클릭합니다.

> 📝 **NOTE**
> 
> 러버블 AI가 코드를 생성하는 데 보통 **20~60초** 정도 소요됩니다. 생성 중에는 좌측 패널에 AI가 어떤 작업을 하는지 단계별로 표시됩니다. 기다리는 동안 이 내용을 읽어 보면 AI가 어떤 파일을 어떻게 수정하는지 대략 파악할 수 있습니다.

---

### STEP 3: 생성 결과 확인

코드 생성이 완료되면 우측 미리보기 패널에 즉시 앱이 표시됩니다. 다음 항목을 확인해 보세요:

- [ ] 입력창과 추가 버튼이 표시되는가?
- [ ] 샘플 할 일 항목이 몇 개 생성되었는가?
- [ ] 체크박스를 클릭하면 완료 처리가 되는가?
- [ ] 삭제 버튼이 작동하는가?
- [ ] 하단에 진행 상황 카운터가 표시되는가?

---

### STEP 4: 수정 요청 (반복 프롬프트)

잘 생성되었지만 몇 가지를 더 다듬어 보겠습니다. 다음 프롬프트를 입력합니다:

```
몇 가지를 수정해 주세요:
1. 완료된 항목의 배경을 연한 초록색으로 변경
2. 빈 상태일 때 "할 일이 없습니다 🎉" 메시지 표시
3. Enter 키로도 항목 추가 가능하게 수정
```

> 💡 **TIP**
> 
> 수정 요청 시 **한 번에 너무 많은 항목을 변경하지 마세요.** 3~5가지 이내의 관련된 수정을 묶어서 요청하는 것이 가장 효율적입니다. 변경 사항이 너무 많으면 AI가 일부를 놓치거나 예상치 못한 곳을 수정하는 경우가 있습니다.

---

### STEP 5: Visual Edit으로 세부 디자인 조정

이번에는 크레딧 없이 Visual Edit으로 디자인을 조정해 봅니다.

1. 입력창 하단의 **Edit(✏️) 버튼** 클릭
2. 미리보기에서 수정하고 싶은 요소(예: 제목 텍스트)에 마우스를 올리면 파란색 테두리가 표시됨
3. 요소를 클릭하면 좌측에 수정 옵션 패널이 나타남
4. 텍스트 변경, 색상 조정, 여백 수정 등을 원하는 대로 조정
5. **Save** 버튼 클릭 → 즉시 미리보기에 반영됨

---

### STEP 6: 1클릭 배포

앱이 마음에 든다면 배포해 봅니다.

1. 상단의 **Publish** 버튼 클릭
2. 처음 배포하는 경우 서브도메인 이름을 입력하라는 창이 나타남
    - 예: `my-todo-app` → `my-todo-app.lovable.app`
3. **Publish** 클릭 → 수 초 내에 전 세계에서 접속 가능한 URL 생성

> 📝 **NOTE**
> 
> 배포된 URL은 **즉시 공유 가능**합니다. 스마트폰에서도 접속해 반응형 레이아웃이 잘 작동하는지 확인해 보세요. 이후 수정 → Publish를 반복할 때마다 동일한 URL에 새 버전이 즉시 반영됩니다.

### 2) 핵심 파일 살펴보기

**`src/pages/Index.tsx` — 메인 페이지**

```typescript
// 러버블이 생성한 Index.tsx 예시 (단순화)
// React 18 + TypeScript 기준

import { useState } from "react";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Checkbox } from "@/components/ui/checkbox";

// Todo 항목의 타입 정의
interface Todo {
  id: string;
  text: string;
  completed: boolean;
}

const Index = () => {
  // 상태(State) 정의: Todo 목록과 입력값 관리
  const [todos, setTodos] = useState<Todo[]>([]);
  const [inputValue, setInputValue] = useState("");

  // 새 항목 추가 함수
  const addTodo = () => {
    if (!inputValue.trim()) return; // 빈 입력 방지
    setTodos([...todos, {
      id: crypto.randomUUID(), // 고유 ID 생성
      text: inputValue,
      completed: false,
    }]);
    setInputValue(""); // 입력창 초기화
  };

  // 완료 상태 토글 함수
  const toggleTodo = (id: string) => {
    setTodos(todos.map(todo =>
      todo.id === id ? { ...todo, completed: !todo.completed } : todo
    ));
  };

  // 항목 삭제 함수
  const deleteTodo = (id: string) => {
    setTodos(todos.filter(todo => todo.id !== id));
  };

  return (
    <div className="min-h-screen bg-gray-50 flex items-center justify-center p-4">
      {/* 앱 컨테이너 */}
      <div className="bg-white rounded-xl shadow-lg p-6 w-full max-w-md">
        <h1 className="text-2xl font-bold text-blue-600 mb-6">할 일 목록</h1>

        {/* 입력 영역 */}
        <div className="flex gap-2 mb-4">
          <Input
            value={inputValue}
            onChange={(e) => setInputValue(e.target.value)}
            onKeyDown={(e) => e.key === "Enter" && addTodo()} // Enter 키 지원
            placeholder="새 할 일을 입력하세요..."
          />
          <Button onClick={addTodo} className="bg-blue-600 hover:bg-blue-700">
            추가
          </Button>
        </div>

        {/* 진행 상황 표시 */}
        <p className="text-sm text-gray-500 mb-3">
          {todos.filter(t => t.completed).length} / {todos.length} 완료
        </p>

        {/* Todo 목록 */}
        {todos.length === 0 ? (
          <p className="text-center text-gray-400 py-8">할 일이 없습니다 🎉</p>
        ) : (
          <ul className="space-y-2">
            {todos.map(todo => (
              <li
                key={todo.id}
                className={`flex items-center gap-3 p-3 rounded-lg ${
                  todo.completed ? "bg-green-50" : "bg-gray-50"
                }`}
              >
                <Checkbox
                  checked={todo.completed}
                  onCheckedChange={() => toggleTodo(todo.id)}
                />
                <span className={`flex-1 ${todo.completed ? "line-through text-gray-400" : ""}`}>
                  {todo.text}
                </span>
                <button
                  onClick={() => deleteTodo(todo.id)}
                  className="text-red-400 hover:text-red-600 text-sm"
                >
                  삭제
                </button>
              </li>
            ))}
          </ul>
        )}
      </div>
    </div>
  );
};

export default Index;
```

> 📝 **NOTE**
> 
> 위 코드는 러버블이 생성하는 실제 코드와 유사한 구조입니다. **`useState`** 는 React의 상태 관리 훅으로 데이터가 변경될 때 화면을 자동으로 다시 그려줍니다. **`className`** 에 나열된 `flex`, `bg-blue-600`, `rounded-xl` 등은 모두 Tailwind CSS 유틸리티 클래스입니다.

## 2.6 러버블 앱 배포 — 서브도메인과 커스텀 도메인

### 1) lovable.app 서브도메인 배포 (전 플랜)

기본 배포 방법으로, `[프로젝트명].lovable.app` 형태의 URL이 생성됩니다.

- **무료**: 모든 플랜에서 사용 가능
- **자동 HTTPS**: SSL 인증서 자동 적용
- **즉시 반영**: Publish 클릭 시 수 초 내에 전 세계 배포

### 2) 커스텀 도메인 연결 (유료 플랜)

Pro 플랜 이상에서는 구매한 도메인을 러버블 앱에 연결할 수 있습니다.

**러버블 내에서 도메인 구매 (2025년 신기능)**

1. 프로젝트 에디터 상단 **Publish → Custom Domain** 클릭
2. 원하는 도메인 이름 검색 (`.com`, `.dev`, `.io` 등)
3. 도메인 구매 → 자동으로 DNS 설정 완료

**이미 보유한 도메인 연결**

1. 러버블 설정에서 커스텀 도메인 입력
2. 도메인 등록업체(가비아, 카페24, Namecheap 등)의 DNS 설정에서 **CNAME 레코드** 추가:
    - 레코드 타입: `CNAME`
    - 이름(Name): `www` 또는 `@`
    - 값(Value): 러버블이 제공하는 대상 주소
3. DNS 전파 완료까지 최대 24~48시간 소요

> ⚠️ **WARNING**
> 
> DNS 변경 후 즉시 반영되지 않는 것은 정상입니다. 전 세계 DNS 서버에 변경 사항이 전파되는 데 최대 **48시간**이 소요될 수 있습니다. 급하게 확인하려면 `nslookup [도메인]` 명령어로 현재 DNS 상태를 확인할 수 있습니다.

## 2.7 로컬 개발 환경 미리보기 (선택)

러버블에서 GitHub로 코드를 내보낸 후 로컬 컴퓨터에서 실행하는 방법을 간단히 살펴봅니다. 이 내용은 제6장에서 자세히 다루므로 지금은 흐름만 파악합니다.

```bash
# 1. GitHub에서 프로젝트 클론
git clone https://github.com/[사용자명]/[프로젝트명].git
cd [프로젝트명]

# 2. 의존성 설치 (Node.js 18+ 필요)
npm install

# 3. 개발 서버 실행
npm run dev
# → http://localhost:8080 에서 앱 실행됨
```
