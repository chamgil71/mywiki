## 12.1 프로덕션 배포 전 보안 체크리스트

### 1) Supabase 공식 프로덕션 체크리스트

## 12.2 RLS 완전 정복 — 프로덕션 패턴

### 1) RLS의 핵심 원칙

RLS는 모든 쿼리에 암묵적인 WHERE 절을 추가합니다. RLS 없이는 anon API 키를 가진 누구든 public 스키마의 모든 데이터를 읽고 수정할 수 있습니다. 규칙은 간단합니다: public 스키마의 모든 테이블에 예외 없이 RLS를 활성화하세요.

> ⚠️ **WARNING**
> 
> Supabase 대시보드의 Table Editor로 생성한 테이블은 RLS가 기본으로 활성화됩니다. 하지만 SQL 에디터나 마이그레이션으로 테이블을 생성한 경우에는 직접 RLS를 활성화해야 합니다. 러버블이 자동 생성한 테이블도 SQL로 생성된 경우 RLS가 비활성화 상태일 수 있으므로, 배포 전에 반드시 Supabase → Authentication → Policies에서 확인하세요.

---

### 2) RLS 성능 최적화 패턴

RLS 정책에 사용된 컬럼에 반드시 인덱스를 추가하세요. 또한 `auth.uid() in (select user_id from team_user where team_user.team_id = table.team_id)` 형태보다 `team_id in (select team_id from team_user where user_id = auth.uid())` 형태가 훨씬 빠릅니다. 항상 'authenticated' 역할을 승인된 역할에 추가하여 anon 사용자를 명시적으로 제외하세요.

```sql
-- ❌ 느린 RLS 패턴 — 모든 행을 순회하며 검사
CREATE POLICY "slow_policy" ON tasks FOR SELECT
USING (
  auth.uid() IN (
    SELECT user_id FROM team_members
    WHERE team_members.team_id = tasks.team_id  -- 행마다 서브쿼리 실행
  )
);

-- ✅ 빠른 RLS 패턴 — 인덱스 활용
CREATE POLICY "fast_policy" ON tasks FOR SELECT
TO authenticated  -- anon 역할 명시적 제외
USING (
  team_id IN (
    SELECT team_id FROM team_members
    WHERE user_id = auth.uid()  -- 사용자 ID로 먼저 필터링
  )
);

-- ✅ 더 빠른 패턴 — Security Definer 함수로 캐싱
CREATE OR REPLACE FUNCTION user_team_ids()
RETURNS SETOF UUID
LANGUAGE SQL SECURITY DEFINER STABLE  -- STABLE: 트랜잭션 내 결과 캐싱
AS $$
  SELECT team_id FROM team_members WHERE user_id = auth.uid();
$$;

CREATE POLICY "fastest_policy" ON tasks FOR SELECT
TO authenticated
USING (team_id IN (SELECT user_team_ids()));

-- RLS 정책 컬럼에 인덱스 추가 (필수)
CREATE INDEX idx_tasks_team_id ON tasks(team_id);
CREATE INDEX idx_team_members_user_id ON team_members(user_id);
```

### 3) 스토리지 버킷 RLS 설정

Supabase Storage는 RLS와 완벽하게 연동됩니다. 기본적으로 RLS 정책 없이는 버킷에 어떤 업로드도 허용하지 않습니다. `storage.objects` 테이블에 RLS 정책을 생성하여 접근을 선택적으로 허용해야 합니다.

```sql
-- Storage 버킷 RLS 정책 예시

-- 인증된 사용자만 자신의 폴더에 업로드 허용
CREATE POLICY "auth_users_upload"
ON storage.objects FOR INSERT
TO authenticated
WITH CHECK (
  bucket_id = 'documents'
  AND (storage.foldername(name))[1] = auth.uid()::text
);

-- 본인 파일만 조회 허용
CREATE POLICY "auth_users_select_own"
ON storage.objects FOR SELECT
TO authenticated
USING (
  bucket_id = 'documents'
  AND (storage.foldername(name))[1] = auth.uid()::text
);

-- 본인 파일만 삭제 허용
CREATE POLICY "auth_users_delete_own"
ON storage.objects FOR DELETE
TO authenticated
USING (
  bucket_id = 'documents'
  AND (storage.foldername(name))[1] = auth.uid()::text
);
```

### 4) RLS 테스트 자동화

RLS 정책은 Supabase CLI로 로컬에서 테스트하세요. 테스트 사용자와 데이터를 만들고 올바른 데이터에 접근하는지 격리된 환경에서 검증하세요. 마이그레이션은 반드시 스테이징 환경에서 먼저 테스트한 후 프로덕션에 적용하세요.

```typescript
// tests/rls.test.ts — RLS 정책 자동화 테스트 (Vitest + Supabase 로컬)

import { createClient } from '@supabase/supabase-js';
import { describe, it, expect, beforeAll } from 'vitest';

// 테스트용 사용자 A, B (서로 다른 팀)
const userA = createClient(LOCAL_URL, ANON_KEY);
const userB = createClient(LOCAL_URL, ANON_KEY);

describe('tasks 테이블 RLS 정책', () => {
  beforeAll(async () => {
    // 사용자 A로 로그인
    await userA.auth.signInWithPassword({ email: 'a@test.com', password: 'test1234' });
    // 사용자 B로 로그인
    await userB.auth.signInWithPassword({ email: 'b@test.com', password: 'test1234' });
  });

  it('사용자 A는 자신의 팀 태스크만 조회 가능', async () => {
    const { data, error } = await userA.from('tasks').select('*');
    expect(error).toBeNull();
    // 모든 결과가 사용자 A의 팀 소속인지 확인
    data?.forEach((task) => expect(task.team_id).toBe(USER_A_TEAM_ID));
  });

  it('사용자 A는 사용자 B의 태스크를 조회할 수 없음', async () => {
    const { data } = await userA
      .from('tasks')
      .select('*')
      .eq('team_id', USER_B_TEAM_ID);
    // RLS로 인해 빈 배열 반환 (오류 아님)
    expect(data).toHaveLength(0);
  });

  it('인증되지 않은 사용자는 태스크 조회 불가', async () => {
    const anonClient = createClient(LOCAL_URL, ANON_KEY);
    const { data, error } = await anonClient.from('tasks').select('*');
    // 빈 배열 또는 권한 오류
    expect(data?.length ?? 0).toBe(0);
  });
});
```

### 1) 3단계 환경 구성

프로덕션 안정성을 위해 개발·스테이징·프로덕션 환경을 분리합니다:

```
[환경 분리 전략]

├── Supabase 별도 프로젝트 (무료 플랜 가능)

├── Supabase Pro 플랜
```

### 2) 데이터베이스 마이그레이션 전략

마이그레이션은 항상 up(적용)과 down(롤백) 스크립트를 모두 작성하세요. 마이그레이션은 작고 집중적으로 유지하고 버전 관리에 저장하세요. 프로덕션에서는 절대 직접 마이그레이션을 실행하지 말고, 항상 스테이징에서 먼저 실행하세요.

```bash
# Supabase CLI 마이그레이션 워크플로우

# 새 마이그레이션 파일 생성
supabase migration new add_notifications_table

# 생성된 파일: supabase/migrations/20250308000000_add_notifications_table.sql
# up 마이그레이션 작성 후...

# 로컬에서 테스트
supabase db reset  # 로컬 DB를 마이그레이션 순서대로 재구성

# 스테이징에 적용
supabase db push --db-url postgresql://[스테이징 DB URL]

# 스테이징 검증 후 프로덕션 적용
supabase db push --db-url postgresql://[프로덕션 DB URL]
```

## 12.4 에러 모니터링 — Sentry 완전 연동

### 1) Sentry란?

Sentry는 실시간 에러 추적과 성능 모니터링에 특화된 개발자 우선 애플리케이션 모니터링 서비스입니다. 오픈소스 에러 로깅 도구로 시작하여 100,000개 이상의 조직이 사용하는 종합 모니터링 플랫폼으로 성장했습니다.

러버블 앱에 Sentry를 연결하면 사용자가 오류를 경험하는 순간 Slack이나 이메일로 즉시 알림을 받고, 어떤 코드에서 문제가 발생했는지 스택 트레이스와 함께 확인할 수 있습니다.

---

### 2) Sentry 설치 및 초기 설정

```bash
# 패키지 설치
npm install @sentry/react
```

**러버블 채팅 프롬프트로 자동 설정:**

```
Sentry 에러 모니터링을 연동해 주세요.

- 패키지: @sentry/react
- DSN: 환경변수 VITE_SENTRY_DSN에서 로드
- 기능:
  1. 프로덕션 환경에서만 활성화 (개발 환경 제외)
  2. 에러 발생 시 사용자 정보(ID, 이메일) 함께 전송
  3. 전체 앱을 ErrorBoundary로 감싸서 앱 크래시 방지
  4. 라우트 변경 성능 추적
  5. 트랜잭션 샘플링: 프로덕션 20%, 개발 100%
- main.tsx와 App.tsx 두 파일을 수정해 주세요.
```

**`src/main.tsx` — Sentry 초기화:**

```typescript
// src/main.tsx
import * as Sentry from '@sentry/react';
import { createRoot } from 'react-dom/client';
import App from './App';

// 프로덕션 환경에서만 Sentry 활성화
Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  enabled: import.meta.env.PROD,  // 개발 환경에서는 비활성화

  integrations: [
    // 페이지 로드·라우트 변경 성능 추적
    Sentry.browserTracingIntegration(),
    // 에러 발생 직전 사용자 세션 재현 (영상 녹화)
    Sentry.replayIntegration({
      maskAllText: true,       // 개인정보 마스킹
      blockAllMedia: false,
    }),
  ],

  // 트랜잭션(성능) 샘플링 비율
  tracesSampleRate: import.meta.env.PROD ? 0.2 : 1.0,

  // 에러 발생 시 세션 재현 100% 캡처
  replaysOnErrorSampleRate: 1.0,
  // 일반 세션 10% 샘플링
  replaysSessionSampleRate: 0.1,

  // 환경 태깅 (Issues 화면에서 필터 가능)
  environment: import.meta.env.MODE,

  // 무시할 에러 목록 (노이즈 제거)
  ignoreErrors: [
    'ResizeObserver loop limit exceeded',
    'Non-Error promise rejection captured',
    /Network request failed/i,
  ],

  // 에러 전송 전 처리 (PII 제거 등)
  beforeSend(event) {
    // 광고 차단 등 서드파티 오류 무시
    if (event.request?.url?.includes('ads')) return null;
    return event;
  },
});

createRoot(document.getElementById('root')!).render(<App />);
```

### 3) ErrorBoundary — 앱 크래시 방지

```typescript
// src/App.tsx — Sentry ErrorBoundary로 전체 앱 보호

import * as Sentry from '@sentry/react';
import { BrowserRouter, Routes, Route, useLocation, useNavigationType } from 'react-router-dom';
import { useEffect } from 'react';

// 에러 발생 시 표시할 폴백 UI
const ErrorFallback = ({ error, resetError }: {
  error: Error;
  resetError: () => void;
}) => (
  <div className="min-h-screen flex items-center justify-center bg-gray-50">
    <div className="max-w-md w-full bg-white rounded-2xl shadow-lg p-8 text-center">
      <span className="text-5xl mb-4 block">😵</span>
      <h2 className="text-xl font-bold text-gray-900 mb-2">
        예상치 못한 오류가 발생했습니다
      </h2>
      <p className="text-gray-500 text-sm mb-6">
        오류가 자동으로 보고되었습니다. 아래 버튼을 눌러 다시 시도해 주세요.
      </p>
      <button
        onClick={resetError}
        className="bg-indigo-600 text-white px-6 py-3 rounded-xl hover:bg-indigo-700"
      >
        다시 시도
      </button>
    </div>
  </div>
);

const App = () => (
  <Sentry.ErrorBoundary
    fallback={({ error, resetError }) => (
      <ErrorFallback error={error as Error} resetError={resetError} />
    )}
    onError={(error, componentStack) => {
      // 추가 컨텍스트와 함께 Sentry에 전송
      Sentry.captureException(error, {
        contexts: { react: { componentStack } },
      });
    }}
  >
```

### 4) 사용자 컨텍스트 연동 — 누가 오류를 겪었는지 파악

```typescript
// src/hooks/useAuth.ts — 로그인 시 Sentry에 사용자 정보 등록

import * as Sentry from '@sentry/react';

export function useAuth() {
  const [user, setUser] = useState<User | null>(null);

  useEffect(() => {
    supabase.auth.onAuthStateChange((event, session) => {
      const currentUser = session?.user ?? null;
      setUser(currentUser);

      if (currentUser) {
        // Sentry에 현재 사용자 등록
        // → Issues 화면에서 "이 오류를 겪은 사용자" 목록 확인 가능
        Sentry.setUser({
          id: currentUser.id,
          email: currentUser.email,
          username: currentUser.user_metadata?.full_name,
        });
      } else {
        // 로그아웃 시 사용자 정보 초기화
        Sentry.setUser(null);
      }
    });
  }, []);

  return { user };
}
```

```typescript
// API 호출 실패 시 수동으로 Sentry에 전송

const fetchUserData = async (userId: string) => {
```

### 5) React Profiler로 느린 컴포넌트 찾기

React의 Profiler 컴포넌트로 렌더링 시간을 측정하고, 16ms(60fps 기준 한 프레임)를 초과하는 컴포넌트를 분석 서비스에 기록할 수 있습니다. 프로덕션에서는 Sentry나 LogRocket 같은 실사용자 모니터링(RUM) 도구를 사용하세요.

```typescript
// src/components/PerformanceProfiler.tsx
// 개발 환경에서 느린 컴포넌트 자동 감지

import { Profiler, ProfilerOnRenderCallback } from 'react';

const onRenderCallback: ProfilerOnRenderCallback = (
  id,           // 컴포넌트 이름
  phase,        // 'mount' | 'update'
  actualDuration // 실제 렌더링 시간 (ms)
) => {
  // 16ms(1프레임) 초과 시 경고
  if (actualDuration > 16) {
    console.warn(`⚠️ 느린 렌더링: ${id} - ${actualDuration.toFixed(1)}ms (${phase})`);
  }
};

// 개발 환경에서만 Profiler 활성화 (프로덕션 성능 영향 없음)
export const WithProfiler = ({ id, children }: { id: string; children: React.ReactNode }) => {
  if (import.meta.env.DEV) {
    return (
      <Profiler id={id} onRender={onRenderCallback}>
        {children}
      </Profiler>
    );
  }
  return <>{children}</>;
};

// 사용 예시
const Dashboard = () => (
  <WithProfiler id="Dashboard">
    <DashboardContent />
  </WithProfiler>
);
```

### 1) 인덱스 설계 원칙

```sql
-- 자주 사용하는 쿼리 패턴에 맞는 인덱스 추가

-- 1. WHERE 조건에 자주 쓰이는 컬럼
CREATE INDEX CONCURRENTLY idx_tasks_user_id ON tasks(assignee_id);

CREATE INDEX CONCURRENTLY idx_tasks_project_column

CREATE INDEX CONCURRENTLY idx_tasks_created_at

CREATE INDEX CONCURRENTLY idx_active_tasks
ON tasks(project_id, updated_at DESC)
WHERE status != 'done';  -- 완료된 태스크 제외
```

### 2) 느린 쿼리 감지 및 최적화

```sql
-- pg_stat_statements로 느린 쿼리 상위 10개 조회
-- Supabase SQL Editor에서 실행

SELECT
  calls,
  total_exec_time / calls AS avg_time_ms,
  rows / calls AS avg_rows,
  query
FROM pg_stat_statements
ORDER BY avg_time_ms DESC
LIMIT 10;

-- EXPLAIN ANALYZE로 특정 쿼리 실행 계획 분석
-- "Seq Scan" 대신 "Index Scan"이 나와야 최적화된 상태
EXPLAIN ANALYZE
SELECT * FROM tasks
WHERE assignee_id = 'user-uuid'
  AND status = 'in_progress'
ORDER BY updated_at DESC
LIMIT 20;
```

> 💡 **TIP**
> 
> Supabase SQL Editor에서 쿼리 앞에 `EXPLAIN ANALYZE`를 붙여 실행하면 실행 계획을 볼 수 있습니다. 결과에서 **"Seq Scan"** 이 보이면 해당 컬럼에 인덱스가 없어 모든 행을 순회하는 것입니다. **"Index Scan"** 이 보이면 인덱스를 올바르게 활용하고 있는 상태입니다. 러버블 채팅창에 "이 쿼리 실행 계획을 보여줘: [쿼리]"라고 요청하면 AI가 최적화 방향을 제안해 줍니다.

### 2) 사용자 데이터 삭제 구현

```typescript
// 사용자 계정 완전 삭제 Edge Function
// supabase/functions/delete-account/index.ts

serve(async (req) => {
  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_ANON_KEY')!,
    { global: { headers: { Authorization: req.headers.get('Authorization')! } } }
  );

  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return new Response('인증 필요', { status: 401 });

  const adminClient = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
  );

  // 1. Storage 파일 삭제
  const { data: files } = await adminClient.storage
    .from('documents')
    .list(user.id);

  if (files?.length) {
    await adminClient.storage
      .from('documents')
      .remove(files.map(f => `${user.id}/${f.name}`));
  }

  // 2. 사용자 데이터 삭제 (CASCADE로 연관 데이터 자동 삭제)
  await adminClient.from('profiles').delete().eq('id', user.id);

  // 3. Auth 계정 삭제
  await adminClient.auth.admin.deleteUser(user.id);

  return new Response(JSON.stringify({ deleted: true }));
});
```

## 🔑 Key Takeaway

> **프로덕션 운영의 3대 원칙: 보안(Security), 관측(Observability), 복원(Resilience).**
> 
> 보안은 모든 테이블의 RLS 활성화와 환경별 API 키 분리로 시작합니다. 관측은 Sentry로 오류를 실시간 감지하고 사용자 컨텍스트와 함께 기록하는 것입니다. 복원은 Vercel 즉시 롤백과 down 마이그레이션 스크립트로 언제든 이전 상태로 돌아갈 수 있는 능력입니다. 러버블은 이 세 가지를 코드 몇 줄과 프롬프트 몇 줄로 구현할 수 있도록 도와줍니다.
