# 제5장. 백엔드 연동 — Supabase 완전 정복

> _"프론트엔드는 보여주는 것이고, 백엔드는 기억하는 것이다. 데이터를 기억하지 못하는 앱은 새로 고침 한 번에 사라지는 신기루다."_

---

## 0) 연결 고리

> 🔗 4장에서는 러버블로 아름다운 UI를 만드는 방법을 익혔습니다. 그러나 UI만으로는 사용자 데이터를 저장하거나 인증을 처리할 수 없습니다. 이 장에서는 러버블의 공식 백엔드 파트너인 **Supabase**를 연동하여 데이터베이스, 인증, 파일 저장, 실시간 업데이트까지 갖춘 **진짜 프로덕션 앱**을 만드는 방법을 다룹니다.

---

## 5.1 Supabase란 무엇인가

### 1) 개념 정의 및 필요성

**Supabase(수파베이스)** 는 PostgreSQL 기반의 오픈소스 백엔드 플랫폼입니다. Google의 Firebase에 대응하는 오픈소스 대안으로 출발하여, 현재는 데이터베이스·인증·파일 저장소·실시간 기능·서버리스 함수를 하나의 플랫폼에서 제공합니다.

러버블이 Supabase를 공식 백엔드로 채택한 이유는 명확합니다. 러버블의 핵심 철학인 "소유 가능한 코드"와 Supabase의 "오픈소스·벤더 종속 없음" 철학이 완벽하게 일치하기 때문입니다.

---

### 2) Supabase의 4대 핵심 기능

```
┌─────────────────────────────────────────────────────────┐
│                   Supabase 플랫폼 구성                    │
├──────────────┬──────────────────────────────────────────┤
│  Database    │ PostgreSQL 14+ 기반 관계형 데이터베이스    │
│  (데이터베이스)│ REST API + GraphQL 자동 생성              │
├──────────────┼──────────────────────────────────────────┤
│  Auth        │ 이메일/비밀번호, OAuth(Google·GitHub 등)  │
│  (인증)       │ JWT 토큰 기반, MFA(다중 인증) 지원         │
├──────────────┼──────────────────────────────────────────┤
│  Storage     │ S3 호환 파일 저장소                        │
│  (스토리지)   │ 이미지·문서·영상 업로드, CDN 자동 제공     │
├──────────────┼──────────────────────────────────────────┤
│  Edge        │ Deno 런타임 기반 서버리스 함수             │
│  Functions   │ API 키 보호, 외부 서비스 연동 로직         │
└──────────────┴──────────────────────────────────────────┘
```

**Firebase vs Supabase 비교**

|구분|Firebase (Google)|Supabase|
|---|---|---|
|**데이터베이스**|NoSQL (Firestore)|SQL (PostgreSQL)|
|**쿼리 방식**|문서 기반 쿼리|SQL + REST API|
|**오픈소스**|❌ 독점|✅ 완전 오픈소스|
|**자체 호스팅**|❌ 불가|✅ 가능|
|**실시간**|✅ 강점|✅ 지원|
|**가격(무료)**|Spark 플랜 제한적|2개 프로젝트 무료|
|**러버블 통합**|❌ 미지원|✅ 네이티브 통합|

> 📝 **NOTE**
> 
> Supabase는 2025년 기준 **$2억 달러 이상의 ARR**을 달성한 고성장 스타트업입니다. 2025년 Series C로 $2억 달러를 추가 유치했으며, 현재 전 세계 150만 개 이상의 프로젝트에서 사용되고 있습니다. 러버블과의 파트너십으로 두 서비스 모두 급성장하는 선순환 구조를 만들고 있습니다.

## 5.2 러버블 × Supabase 연결 설정

### 1) Supabase 프로젝트 생성

**① Supabase 계정 생성**

[https://supabase.com](https://supabase.com/)에서 GitHub 계정으로 가입합니다 (GitHub 계정 사용 권장).

**② 새 프로젝트 생성**

1. 대시보드 → **"New Project"** 클릭
2. 프로젝트 이름 입력 (예: `docsense-prod`)
3. 데이터베이스 비밀번호 설정 (안전한 곳에 저장 필수)
4. 리전(Region) 선택: **Northeast Asia (Seoul)** — 한국 사용자의 경우 지연시간 최소화
5. **"Create new project"** 클릭 → 약 1~2분 소요

> ⚠️ **WARNING**
> 
> 데이터베이스 비밀번호는 **프로젝트 생성 후 변경이 어렵습니다.** 반드시 안전한 비밀번호 관리 도구(1Password, Bitwarden 등)에 저장해 두세요. 이 비밀번호를 잃어버리면 데이터베이스에 직접 접근하는 고급 기능 사용이 불가능합니다.

---

### 2) 러버블에서 Supabase 연결 (Supabase Integration 2.0)

러버블은 2024년 12월부터 **Supabase 자동 프로비저닝(Auto-Provisioning)** 을 지원합니다. 수동으로 API 키를 복사-붙여넣기할 필요 없이 원클릭으로 연결됩니다.

**연결 방법 (자동):**

1. 러버블 프로젝트 에디터에서 **초록색 Supabase 버튼** 클릭
2. Supabase 계정으로 로그인 → 연결할 프로젝트 선택
3. 권한 승인 → 자동으로 API 키·URL 설정 완료
4. 채팅창에 "Supabase 연결 완료" 메시지 표시

**연결 방법 (수동 — 이미 생성된 프로젝트):**

1. Supabase 대시보드 → **Project Settings → API**
2. `Project URL`과 `anon (public) key` 복사
3. 러버블 **Settings → Supabase** 탭에 붙여넣기

> 💡 **TIP**
> 
> **2025년부터 Supabase Integration 2.0이 적용**되어 러버블이 Supabase Edge Function 로그를 자동으로 읽습니다. 백엔드 함수에서 오류가 발생하면 러버블 채팅창에 오류 내용이 자동으로 표시되어 디버깅 시간이 크게 단축됩니다. 이전처럼 Supabase 대시보드를 직접 열어 로그를 확인할 필요가 줄어들었습니다.

### 3) 연결 후 자동으로 생성되는 파일

Supabase 연결 후 러버블은 다음 파일들을 자동으로 프로젝트에 추가합니다:

```
src/
└── integrations/
    └── supabase/
        ├── client.ts     # Supabase 클라이언트 초기화
        └── types.ts      # DB 스키마 기반 TypeScript 타입 자동 생성
```

```typescript
// src/integrations/supabase/client.ts (자동 생성 파일)
// Supabase JS Client v2 기준

import { createClient } from '@supabase/supabase-js';
import type { Database } from './types';

// 환경변수에서 URL과 Key 로드 (소스 코드에 직접 노출 금지)
const SUPABASE_URL = import.meta.env.VITE_SUPABASE_URL;
const SUPABASE_ANON_KEY = import.meta.env.VITE_SUPABASE_ANON_KEY;

// Database 타입을 제네릭으로 전달하여 완전한 타입 안전성 확보
export const supabase = createClient<Database>(
  SUPABASE_URL,
  SUPABASE_ANON_KEY
);
```

> ⚠️ **WARNING**
> 
> `SUPABASE_ANON_KEY`는 공개 키이지만 **서비스 롤 키(service_role key)** 는 절대 프론트엔드 코드에 포함시키면 안 됩니다. 서비스 롤 키는 모든 RLS 정책을 우회하는 관리자 권한을 가집니다. 외부 API 연동 등 민감한 작업은 반드시 **Edge Function** 을 통해 서버 측에서 처리해야 합니다.

## 5.3 데이터베이스 설계와 CRUD 구현

### 1) 자연어로 테이블 생성하기

Supabase 연결 후 러버블 채팅창에서 자연어로 데이터베이스 테이블을 생성할 수 있습니다:

```
다음 테이블들을 Supabase에 생성해 주세요:

1. documents 테이블
   - id: UUID (기본키, 자동 생성)
   - user_id: UUID (auth.users 테이블 외래키)
   - title: TEXT (필수)
   - content: TEXT
   - file_url: TEXT
   - file_size: INTEGER
   - status: TEXT (기본값: 'pending', 'processing', 'completed' 중 하나)
   - created_at: TIMESTAMP WITH TIME ZONE (기본값: NOW())
   - updated_at: TIMESTAMP WITH TIME ZONE (기본값: NOW())

2. analyses 테이블
   - id: UUID (기본키, 자동 생성)
   - document_id: UUID (documents 테이블 외래키)
   - summary: TEXT
   - key_points: JSONB
   - created_at: TIMESTAMP WITH TIME ZONE (기본값: NOW())

각 테이블에 RLS를 활성화하고,
인증된 사용자가 자신의 데이터만 접근할 수 있도록 정책을 설정해 주세요.
```

### 2) CRUD 구현 — TypeScript 완전 예제

**Create (생성)**

```typescript
// 새 문서 생성
// src/hooks/useDocuments.ts (Supabase JS v2 기준)

import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/hooks/useAuth';

export function useDocuments() {
  const { user } = useAuth();

  const createDocument = async (title: string, content: string) => {
    // 로그인된 사용자의 ID를 user_id에 자동 설정
    const { data, error } = await supabase
      .from('documents')
      .insert({
        title,
        content,
        user_id: user!.id,  // 현재 로그인 사용자 ID
        status: 'pending',
      })
      .select()  // 생성된 레코드 반환
      .single(); // 단일 레코드 반환

    if (error) throw error;
    return data;
  };
```

**Read (조회)**

```typescript
  // 현재 사용자의 문서 목록 조회
  const getDocuments = async () => {
    const { data, error } = await supabase
      .from('documents')
      .select(`
        *,
        analyses (
          id,
          summary,
          created_at
        )
      `)                              // JOIN: analyses 테이블 함께 조회
      .eq('user_id', user!.id)       // WHERE user_id = 현재 사용자
      .order('created_at', { ascending: false }) // ORDER BY created_at DESC
      .limit(20);                    // LIMIT 20

    if (error) throw error;
    return data;
  };

  // 단일 문서 조회
  const getDocument = async (documentId: string) => {
    const { data, error } = await supabase
      .from('documents')
      .select('*')
      .eq('id', documentId)
      .single();

    if (error) throw error;
    return data;
  };
```

**Update (수정)**

```typescript
  // 문서 제목 수정
  const updateDocument = async (documentId: string, updates: Partial<Document>) => {
    const { data, error } = await supabase
      .from('documents')
      .update({
        ...updates,
        updated_at: new Date().toISOString(), // 수정 시각 갱신
      })
      .eq('id', documentId)
      .eq('user_id', user!.id)  // 본인 문서만 수정 가능 (이중 보안)
      .select()
      .single();

    if (error) throw error;
    return data;
  };
```

**Delete (삭제)**

```typescript
  // 문서 삭제
  const deleteDocument = async (documentId: string) => {
    const { error } = await supabase
      .from('documents')
      .delete()
      .eq('id', documentId)
      .eq('user_id', user!.id); // 본인 문서만 삭제 가능

    if (error) throw error;
  };

  return { createDocument, getDocuments, getDocument, updateDocument, deleteDocument };
}
```

> 📝 **NOTE**
> 
> Supabase JS 클라이언트의 메서드 체이닝 방식은 SQL을 직접 작성하지 않아도 복잡한 쿼리를 표현할 수 있게 해줍니다. `.from()` → `.select()` → `.eq()` → `.order()` 순으로 이어지는 구조는 SQL의 `SELECT ... FROM ... WHERE ... ORDER BY ...`와 1:1로 대응됩니다. 러버블 AI가 이 패턴으로 코드를 자동 생성하므로, 패턴을 인식하는 것만으로도 코드를 읽고 수정할 수 있습니다.

## 5.4 사용자 인증(Authentication) 완전 구현

### 1) Supabase Auth 개요

Supabase Auth는 JWT(JSON Web Token) 기반 인증 시스템으로 다음 기능을 제공합니다:

- 이메일/비밀번호 로그인
- Magic Link (비밀번호 없는 이메일 로그인)
- OAuth (Google, GitHub, Discord, Twitter 등 18개 이상)
- 전화번호 OTP
- MFA (다중 인증)

---

### 2) 이메일/비밀번호 인증 구현

```typescript
// src/hooks/useAuth.ts — 인증 훅 (러버블 자동 생성 패턴)
// Supabase Auth v2 기준

import { useState, useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';
import type { User } from '@supabase/supabase-js';

export function useAuth() {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // 현재 세션 확인
    supabase.auth.getSession().then(({ data: { session } }) => {
      setUser(session?.user ?? null);
      setLoading(false);
    });

    // 인증 상태 변화 구독 (로그인/로그아웃 이벤트)
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      (_event, session) => {
        setUser(session?.user ?? null);
      }
    );

    return () => subscription.unsubscribe(); // 클린업
  }, []);

  // 이메일/비밀번호 로그인
  const signIn = async (email: string, password: string) => {
    const { error } = await supabase.auth.signInWithPassword({ email, password });
    if (error) throw error;
  };

  // 회원가입
  const signUp = async (email: string, password: string, name: string) => {
    const { error } = await supabase.auth.signUp({
      email,
      password,
      options: {
        data: { full_name: name }, // 추가 사용자 정보
        emailRedirectTo: `${window.location.origin}/auth/callback`,
      },
    });
    if (error) throw error;
  };

  // 로그아웃
  const signOut = async () => {
    const { error } = await supabase.auth.signOut();
    if (error) throw error;
  };

  // 비밀번호 재설정 이메일 발송
  const resetPassword = async (email: string) => {
    const { error } = await supabase.auth.resetPasswordForEmail(email, {
      redirectTo: `${window.location.origin}/auth/reset-password`,
    });
    if (error) throw error;
  };

  return { user, loading, signIn, signUp, signOut, resetPassword };
}
```

### 3) Google OAuth 연동

```typescript
// Google 소셜 로그인 구현
const signInWithGoogle = async () => {
  const { error } = await supabase.auth.signInWithOAuth({
    provider: 'google',
    options: {
      redirectTo: `${window.location.origin}/auth/callback`,
      queryParams: {
        access_type: 'offline', // Refresh Token 요청
        prompt: 'consent',
      },
    },
  });
  if (error) throw error;
};
```

**Google Cloud Console 설정 (필수):**

1. [https://console.cloud.google.com](https://console.cloud.google.com/) → **API 및 서비스 → 사용자 인증 정보**
2. **OAuth 2.0 클라이언트 ID** 생성
3. 승인된 리디렉션 URI에 추가: `https://[프로젝트ID].supabase.co/auth/v1/callback`
4. 클라이언트 ID와 시크릿을 Supabase 대시보드 **Authentication → Providers → Google**에 입력

### 4) 카카오 OAuth 연동 (한국 특화)

카카오 로그인은 Supabase의 기본 Provider 목록에 없으므로 **Custom OIDC Provider** 방식으로 연동합니다.

**① 카카오 개발자 센터 설정**

1. [https://developers.kakao.com](https://developers.kakao.com/) → **내 애플리케이션 → 애플리케이션 추가**
2. 앱 이름, 회사명 입력 → 저장
3. **플랫폼 → Web** 추가 → 사이트 도메인 입력
4. **카카오 로그인 → 활성화**
5. **Redirect URI 등록:** `https://[프로젝트ID].supabase.co/auth/v1/callback`
6. **동의항목**: 닉네임, 프로필 사진, 카카오계정(이메일) 활성화

**② Supabase 설정**

```
Supabase Dashboard → Authentication → Sign In / Up
→ Add provider → Kakao

입력 정보:
- Client ID: 카카오 앱의 REST API 키
- Client Secret: 카카오 앱의 Client Secret (보안 탭에서 활성화 필요)
```

**③ 러버블 프롬프트로 구현:**

```
카카오 로그인 버튼을 로그인 페이지에 추가해 주세요.

- Supabase Auth의 signInWithOAuth({ provider: 'kakao' }) 사용
- 카카오 브랜드 가이드라인에 맞는 노란색(#FEE500) 버튼 스타일
- 버튼 내 카카오 로고 아이콘 포함
- 로그인 성공 시 /dashboard로 리디렉션
- 기존 이메일 로그인 UI는 그대로 유지할 것
```

>

## 5.5 파일 스토리지(Storage) 활용

### 1) 버킷(Bucket) 생성

Supabase Storage는 파일을 버킷 단위로 관리합니다. 버킷은 S3의 버킷과 동일한 개념입니다.

```
러버블 프롬프트:
"Supabase Storage에 'documents' 버킷을 생성해 주세요.
- 인증된 사용자만 업로드 가능
- 누구나 읽기 가능 (공개 버킷)
- 허용 파일 형식: PDF, TXT, DOCX
- 최대 파일 크기: 10MB"
```

### 2) 파일 업로드 구현

```typescript
// src/hooks/useFileUpload.ts — 파일 업로드 훅
// Supabase Storage v2 기준

import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/hooks/useAuth';

export function useFileUpload() {
  const { user } = useAuth();

  const uploadFile = async (file: File): Promise<string> => {
    // 파일 크기 검증 (10MB 이하)
    if (file.size > 10 * 1024 * 1024) {
      throw new Error('파일 크기는 10MB 이하여야 합니다.');
    }

    // 허용 파일 형식 검증
    const allowedTypes = ['application/pdf', 'text/plain',
      'application/vnd.openxmlformats-officedocument.wordprocessingml.document'];
    if (!allowedTypes.includes(file.type)) {
      throw new Error('PDF, TXT, DOCX 파일만 업로드 가능합니다.');
    }

    // 고유 파일명 생성 (충돌 방지)
    const fileExt = file.name.split('.').pop();
    const fileName = `${user!.id}/${Date.now()}-${Math.random().toString(36).slice(2)}.${fileExt}`;

    // Supabase Storage에 업로드
    const { data, error } = await supabase.storage
      .from('documents')        // 버킷 이름
      .upload(fileName, file, {
        cacheControl: '3600',   // CDN 캐시 1시간
        upsert: false,          // 동일 파일명 덮어쓰기 금지
      });

    if (error) throw error;

    // 공개 URL 반환
    const { data: { publicUrl } } = supabase.storage
      .from('documents')
      .getPublicUrl(data.path);

    return publicUrl;
  };

  const deleteFile = async (filePath: string) => {
    const { error } = await supabase.storage
      .from('documents')
      .remove([filePath]);

    if (error) throw error;
  };

  return { uploadFile, deleteFile };
}
```

### 3) 파일 업로드 UI 컴포넌트

```typescript
// src/components/FileUploader.tsx — 드래그 앤 드롭 파일 업로드
import { useState, useCallback } from 'react';
import { useFileUpload } from '@/hooks/useFileUpload';
import { Button } from '@/components/ui/button';
import { useToast } from '@/hooks/use-toast';

const FileUploader = ({ onUploadComplete }: { onUploadComplete: (url: string) => void }) => {
  const [isDragging, setIsDragging] = useState(false);
  const [uploading, setUploading] = useState(false);
  const { uploadFile } = useFileUpload();
  const { toast } = useToast();

  const handleFile = useCallback(async (file: File) => {
    setUploading(true);
    try {
      const url = await uploadFile(file);
      onUploadComplete(url);
      toast({ title: '업로드 완료', description: `${file.name} 이 업로드되었습니다.` });
    } catch (error: any) {
      toast({ title: '업로드 실패', description: error.message, variant: 'destructive' });
    } finally {
      setUploading(false);
    }
  }, [uploadFile, onUploadComplete, toast]);

  return (
    <div
      onDragOver={(e) => { e.preventDefault(); setIsDragging(true); }}
      onDragLeave={() => setIsDragging(false)}
      onDrop={(e) => {
        e.preventDefault();
        setIsDragging(false);
        const file = e.dataTransfer.files[0];
        if (file) handleFile(file);
      }}
      className={`border-2 border-dashed rounded-xl p-10 text-center transition-colors
        ${isDragging ? 'border-indigo-500 bg-indigo-50' : 'border-gray-300 bg-gray-50'}`}
    >
      <p className="text-gray-500 mb-4">
        파일을 여기로 드래그하거나
      </p>
      <label>
        <input
          type="file"
          accept=".pdf,.txt,.docx"
          className="hidden"
          onChange={(e) => { const f = e.target.files?.[0]; if (f) handleFile(f); }}
        />
        <Button variant="outline" disabled={uploading} asChild>
          <span>{uploading ? '업로드 중...' : '파일 선택'}</span>
        </Button>
      </label>
      <p className="text-xs text-gray-400 mt-3">PDF, TXT, DOCX · 최대 10MB</p>
    </div>
  );
};

export default FileUploader;
```

## 5.6 실시간(Realtime) 데이터 업데이트

### 1) 실시간 구독의 동작 원리

Supabase Realtime은 PostgreSQL의 **변경 데이터 캡처(CDC, Change Data Capture)** 기술을 기반으로 합니다. 데이터베이스 테이블에 INSERT·UPDATE·DELETE가 발생하면 즉시 연결된 모든 클라이언트에 변경 사항을 전송합니다.

```
[실시간 동작 흐름]

사용자 A가 메시지 전송
        ↓
Supabase DB에 INSERT 발생
        ↓
Supabase Realtime 서버가 변경 감지
        ↓
채널을 구독 중인 모든 클라이언트에 이벤트 전송
        ↓
사용자 B의 화면이 새로고침 없이 즉시 업데이트
```

---

### 2) 실시간 채팅 구현 예시

```typescript
// src/hooks/useRealtimeChat.ts
// Supabase Realtime v2 기준

import { useState, useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';

interface Message {
  id: string;
  content: string;
  user_id: string;
  user_name: string;
  created_at: string;
}

export function useRealtimeChat(roomId: string) {
  const [messages, setMessages] = useState<Message[]>([]);

  useEffect(() => {
    // 1단계: 기존 메시지 로드
    const fetchMessages = async () => {
      const { data } = await supabase
        .from('messages')
        .select('*')
        .eq('room_id', roomId)
        .order('created_at', { ascending: true });
      if (data) setMessages(data);
    };
    fetchMessages();

    // 2단계: 실시간 채널 구독
    const channel = supabase
      .channel(`chat-room-${roomId}`)  // 채널 이름 (고유해야 함)
      .on(
        'postgres_changes',
        {
          event: 'INSERT',              // INSERT 이벤트만 감지
          schema: 'public',
          table: 'messages',
          filter: `room_id=eq.${roomId}`, // 특정 채팅방만 필터링
        },
        (payload) => {
          // 새 메시지를 상태에 추가
          setMessages((prev) => [...prev, payload.new as Message]);
        }
      )
      .subscribe();

    // 클린업: 컴포넌트 언마운트 시 구독 해제
    return () => {
      supabase.removeChannel(channel);
    };
  }, [roomId]);

  // 메시지 전송
  const sendMessage = async (content: string, userId: string, userName: string) => {
    const { error } = await supabase.from('messages').insert({
      room_id: roomId,
      content,
      user_id: userId,
      user_name: userName,
    });
    if (error) throw error;
  };

  return { messages, sendMessage };
}
```

> 💡 **TIP**
> 
> 실시간 기능은 연결된 클라이언트 수에 따라 Supabase 요금이 증가할 수 있습니다. Supabase 무료 플랜은 **동시 실시간 연결 200개** 까지 지원합니다. 소규모 MVP에서는 충분하지만, 사용자가 늘어나면 Pro 플랜($25/월) 업그레이드를 고려하세요.

## 5.7 Row Level Security(RLS) 완전 가이드

### 1) RLS란 무엇인가?

**Row Level Security(행 단위 보안)** 는 PostgreSQL의 보안 기능으로, 사용자가 **자신에게 허용된 행(Row)만 조회하거나 수정**할 수 있도록 데이터베이스 수준에서 강제하는 정책입니다.

> 📝 **NOTE**
> 
> 2025년 5월, 한 보안 연구에서 러버블로 생성된 앱 중 10%에서 RLS 미설정으로 인한 개인정보 노출 취약점이 발견되었습니다. Supabase와 러버블 양사의 CISO는 공동 보안 가이드를 발표하며 **"RLS를 설정하지 않으면 테이블 전체가 누구에게나 노출된다"** 고 경고했습니다. RLS는 선택이 아니라 필수입니다.

```
[RLS 없는 경우]                    [RLS 있는 경우]
                                   
사용자 A가 쿼리:                   사용자 A가 쿼리:
SELECT * FROM documents           SELECT * FROM documents
↓                                  ↓
모든 사용자의 문서 전체 반환         사용자 A의 문서만 반환
(심각한 보안 취약점!)               (안전)
```

---

### 2) RLS 활성화 및 정책 설정

**러버블 프롬프트로 한 번에 설정:**

```
documents 테이블과 analyses 테이블에 RLS를 설정해 주세요.

documents 테이블 정책:
- SELECT: 자신의 문서만 조회 (user_id = auth.uid())
- INSERT: 로그인한 사용자만 생성 가능, user_id는 자동으로 auth.uid() 설정
- UPDATE: 자신의 문서만 수정 가능
- DELETE: 자신의 문서만 삭제 가능

analyses 테이블 정책:
- SELECT: 자신의 documents에 연결된 analyses만 조회
- INSERT: 로그인한 사용자만 생성 가능
- UPDATE: 자신의 analyses만 수정 가능
- DELETE: 자신의 analyses만 삭제 가능
```

**수동 SQL 설정 (Supabase SQL Editor):**

```sql
-- documents 테이블 RLS 활성화
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

-- SELECT 정책: 자신의 문서만 조회
CREATE POLICY "users_select_own_documents"
ON documents FOR SELECT
USING (auth.uid() = user_id);

-- INSERT 정책: 로그인 사용자만 생성, user_id 자동 설정
CREATE POLICY "users_insert_own_documents"
ON documents FOR INSERT
WITH CHECK (auth.uid() = user_id);

-- UPDATE 정책: 자신의 문서만 수정
CREATE POLICY "users_update_own_documents"
ON documents FOR UPDATE
USING (auth.uid() = user_id)
WITH CHECK (auth.uid() = user_id);

-- DELETE 정책: 자신의 문서만 삭제
CREATE POLICY "users_delete_own_documents"
ON documents FOR DELETE
USING (auth.uid() = user_id);
```

---

### 3) RLS 정책 검증 방법

RLS 설정 후 반드시 다음 방법으로 검증하세요:

```sql
-- Supabase SQL Editor에서 특정 사용자로 가장하여 테스트
-- 실제 사용자 ID로 교체
SET LOCAL role = authenticated;
SET LOCAL request.jwt.claims = '{"sub": "사용자-UUID-입력"}';

-- 이 쿼리는 해당 사용자의 문서만 반환해야 함
SELECT * FROM documents;
```

> ⚠️ **WARNING**
> 
> **RLS 설정 후 Edge Function에서 Supabase 클라이언트를 사용할 때는 주의**가 필요합니다. Edge Function에서 `createClient`를 서비스 롤 키로 초기화하면 RLS를 우회합니다. 사용자 컨텍스트를 유지하려면 요청 헤더에서 JWT 토큰을 추출하여 `createClient`에 전달해야 합니다. 러버블에 "Edge Function에서 RLS를 준수하도록 사용자 컨텍스트를 유지해줘"라고 요청하면 올바른 패턴으로 구현해 줍니다.

## 5.8 Edge Functions(서버리스 함수) 활용

### 1) Edge Functions가 필요한 경우

프론트엔드에서 직접 처리하면 안 되는 작업들이 있습니다:

|작업 유형|프론트엔드 직접 처리|Edge Function 처리|
|---|---|---|
|OpenAI API 호출|❌ API 키 노출 위험|✅ 서버에서 안전하게|
|이메일 발송|❌ 인증 정보 노출|✅ Resend API 사용|
|Stripe 웹훅 처리|❌ 검증 불가|✅ 서버 검증 필수|
|외부 API 키 사용|❌ 클라이언트 노출|✅ 환경변수로 보호|
|복잡한 DB 트랜잭션|❌ 원자성 보장 불가|✅ 단일 트랜잭션 처리|

---

### 2) AI 요약 Edge Function 구현 예시

```typescript
// supabase/functions/analyze-document/index.ts
// Deno 런타임 + Supabase Edge Function 기준

import { serve } from 'https://deno.land/std@0.168.0/http/server.ts';
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';
import OpenAI from 'https://deno.land/x/openai@v4.24.0/mod.ts';

const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type',
};

serve(async (req: Request) => {
  // CORS preflight 처리
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: corsHeaders });
  }

  try {
    // 요청 본문에서 문서 ID 추출
    const { documentId } = await req.json();

    // 사용자 인증 확인 (JWT 토큰에서)
    const supabase = createClient(
      Deno.env.get('SUPABASE_URL')!,
      Deno.env.get('SUPABASE_ANON_KEY')!,
      { global: { headers: { Authorization: req.headers.get('Authorization')! } } }
    );

    // 문서 내용 조회
    const { data: document, error: fetchError } = await supabase
      .from('documents')
      .select('title, content')
      .eq('id', documentId)
      .single();

    if (fetchError) throw fetchError;

    // OpenAI API 호출 (환경변수에서 API 키 로드)
    const openai = new OpenAI({ apiKey: Deno.env.get('OPENAI_API_KEY')! });

    const completion = await openai.chat.completions.create({
      model: 'gpt-4o',
      messages: [
        {
          role: 'system',
          content: '당신은 문서 분석 전문가입니다. 주어진 문서를 300자 이내로 요약하세요.',
        },
        {
          role: 'user',
          content: `제목: ${document.title}\n\n내용: ${document.content}`,
        },
      ],
      max_tokens: 500,
    });

    const summary = completion.choices[0].message.content;

    // 분석 결과 DB 저장
    await supabase.from('analyses').insert({
      document_id: documentId,
      summary,
    });

    return new Response(
      JSON.stringify({ success: true, summary }),
      { headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
    );

  } catch (error) {
    return new Response(
      JSON.stringify({ error: error.message }),
      { status: 500, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
    );
  }
});
```

**러버블에서 Edge Function 배포 프롬프트:**

```
위에서 작성한 analyze-document Edge Function을 Supabase에 배포해 주세요.
필요한 환경변수(Secrets)도 함께 설정 안내를 해주세요:
- OPENAI_API_KEY
Supabase 대시보드 → Settings → Edge Functions → Secrets에서 설정합니다.
```

> 💡 **TIP**
> 
> **Supabase Integration 2.0 덕분에 Edge Function 오류가 러버블 채팅창에 자동 표시**됩니다. 이전에는 Supabase 대시보드 → Functions → Logs를 직접 열어 확인해야 했지만, 이제는 오류 발생 시 러버블 AI가 로그를 자동으로 읽고 수정 제안을 채팅창에 바로 보여줍니다.

## 🔑 Key Takeaway

> **Supabase는 러버블 앱의 백본(Backbone)입니다.** 데이터베이스(PostgreSQL), 인증(Auth), 파일 저장(Storage), 실시간(Realtime), 서버리스 함수(Edge Functions)를 단일 플랫폼에서 제공하며 러버블과 네이티브로 통합되어 있습니다.
> 
> 가장 중요한 것은 **RLS(Row Level Security)** 입니다. "RLS를 설정하지 않으면 테이블 전체가 누구에게나 노출된다"는 원칙을 반드시 기억하세요. 모든 테이블에 RLS를 활성화하고, API 키가 필요한 외부 서비스 연동은 반드시 Edge Function을 통해 처리하는 습관이 안전한 프로덕션 앱의 출발점입니다.
