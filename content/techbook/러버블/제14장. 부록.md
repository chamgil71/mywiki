# 부록 A. 프롬프트 템플릿 50선

## A.1 초기 프로젝트 생성 (10개)

**A-01. SaaS 랜딩 페이지**

```
[서비스명]을 위한 SaaS 랜딩 페이지를 만들어 주세요.

대상 고객: [타겟 사용자]
핵심 가치: [핵심 문구, 예: "10분 만에 보고서 자동 생성"]
디자인: 모던 SaaS 스타일, 메인 컬러 [색상코드]

섹션 구성:
1. 히어로: 큰 헤드라인 + 서브 카피 + CTA 버튼 2개 (무료 시작 / 데모 보기)
2. 사회적 증거: 고객사 로고 5개 (플레이스홀더)
3. 핵심 기능: 아이콘 + 제목 + 설명 3개 카드
4. 작동 방식: 번호 3단계 (업로드 → 분석 → 다운로드)
5. 고객 후기: 3개 카드 (이름·직책·별점 포함)
6. 가격 플랜: Free / Pro / Team 3단 구성
7. FAQ: 아코디언 5개
8. 최하단 CTA + 푸터

반응형 필수. 모바일 우선 설계.
```

```

- 좌측 고정 사이드바 (너비 240px): 로고, 메뉴 항목 [메뉴 목록], 하단 사용자 정보
- 상단 헤더: 검색바, 알림 아이콘, 프로필 드롭다운
- 메인 콘텐츠: 4개 통계 카드 + 차트 영역 + 최근 항목 테이블

디자인: [Linear / Notion / Vercel] 스타일
컬러: 사이드바 다크([색상]), 메인 밝은 배경
```

**A-04. 이커머스 상품 목록**

## D.1 러버블 에디터 문제 (1~8)

**D-01. 미리보기가 흰 화면(White Screen)만 표시된다**

```
원인: JavaScript 런타임 오류
해결:
1. 브라우저 개발자 도구 → Console 탭에서 빨간 오류 확인
2. 오류 메시지 전체를 러버블 채팅창에 붙여넣기
3. "이 오류를 수정해줘"라고 요청
4. 해결 안 될 경우: 최근 변경 사항 롤백 (Versions 탭)
```

**D-02. AI가 같은 오류를 반복적으로 수정한다 (AI 루프)**

```
원인: AI가 문제의 근본 원인을 파악하지 못한 채 증상만 수정
해결:
1. "코드를 수정하지 말고, 왜 이 오류가 발생하는지 설명해줘"
2. 설명을 읽고 근본 원인 파악
3. "원인은 [원인]인 것 같아. 이 방향으로 수정해줘"
4. 5회 이상 루프 시 롤백 후 새 접근 방식으로 재시작
```

**D-03. 크레딧이 생각보다 빨리 소진된다**

```
원인: 큰 변경을 한 번에 요청, 불필요한 재요청
해결:
1. Visual Edit 모드로 텍스트·색상 수정 (크레딧 무소비)
2. 요청 전 명확한 프롬프트 작성 (모호한 요청 = 반복 수정 = 크레딧 낭비)
3. 여러 작은 변경 → 한 번에 묶어서 요청
4. Knowledge 설정으로 반복 지시 줄이기
```

**D-04. 미리보기는 작동하는데 배포하면 안 된다**

```
원인: 환경변수 미설정, 도메인 허용 목록 누락
해결:
1. Supabase → Authentication → URL Configuration → Site URL 확인
2. 배포 도메인을 Supabase Redirect URLs에 추가
3. Google/카카오 OAuth → 배포 URL을 Redirect URI에 추가
4. 러버블 Settings → Custom domain 설정 확인
```

**D-05. 컴포넌트 수정 요청이 다른 부분에 영향을 준다**

```
원인: 전역 CSS 또는 공유 컴포넌트 수정
해결:
1. 컴포넌트 이름을 정확히 지정: "Header 컴포넌트의 로고만 변경해줘"
2. Visual Edit으로 특정 요소 직접 수정
3. 요청 전 "다른 컴포넌트에 영향 없이" 명시
```

**D-06. 이미지가 깨지거나 표시되지 않는다**

```
원인: 잘못된 이미지 경로, CORS 문제, Supabase Storage URL 만료
해결:
1. public/ 폴더 이미지: 경로 앞에 "/" 없이 "이미지명.png"
2. Supabase Storage: 버킷 Public 설정 확인
3. 외부 URL: CORS 허용 여부 확인
4. 이미지 URL을 직접 브라우저 주소창에 입력하여 접근 가능한지 확인
```

**D-07. TypeScript 타입 오류로 빌드가 실패한다**

```
해결 순서:
1. 러버블 채팅창: "npx tsc --noEmit 오류를 수정해줘"
2. 오류 메시지를 채팅창에 직접 붙여넣기
3. Supabase 타입 재생성: 스키마 변경 후
   "Supabase 타입을 최신 스키마 기준으로 재생성해줘"
```

**D-08. 폰트가 적용되지 않는다**

```
원인: Google Fonts CDN 로드 실패, font-family 설정 누락
해결:
1. index.html의 <head>에 Google Fonts link 태그 확인
2. tailwind.config.ts의 fontFamily 설정 확인
3. 러버블 요청: "Pretendard 폰트를 적용해줘 (CDN 방식)"
```

## D.2 Supabase 문제 (9~16)

**D-09. 로그인 후 사용자 정보가 null이다**

```
원인: Supabase Auth 세션 로드 전 컴포넌트 렌더링
해결:
1. useAuth 훅에서 loading 상태 확인
2. loading === true 동안 로딩 스피너 표시
3. user가 null일 때 로그인 페이지로 리디렉션하는 ProtectedRoute 적용
```

**D-10. RLS 정책으로 데이터가 빈 배열로 반환된다**

```
원인: RLS 정책이 현재 사용자에게 데이터 접근을 허용하지 않음
해결:
1. Supabase → Table Editor → 해당 테이블 → RLS 탭 확인
2. SQL Editor에서 확인:
   SELECT * FROM [테이블명]; -- anon으로 실행해서 결과 확인
3. 러버블 요청: "현재 로그인한 사용자가 자신의 [테이블명] 데이터를
   조회할 수 있는 RLS 정책을 추가해줘"
```

**D-11. Supabase Edge Function이 오류를 반환한다**

```
디버깅 순서:
1. Supabase → Edge Functions → 함수명 → Logs 탭에서 오류 확인
2. 환경변수 확인: Settings → Edge Functions → Manage Secrets
3. CORS 오류: corsHeaders 설정 확인
4. 로컬 테스트: supabase functions serve [함수명]
```

**D-12. 파일 업로드 후 이미지가 표시되지 않는다**

```
원인: Storage 버킷 비공개 설정 또는 잘못된 URL 생성
해결:
1. Supabase → Storage → 버킷명 → Policies 탭
2. SELECT 정책 확인 (공개 버킷은 anon 읽기 허용 필요)
3. URL 생성 코드 확인:
   공개 버킷: supabase.storage.from('버킷').getPublicUrl(path)
   비공개 버킷: supabase.storage.from('버킷').createSignedUrl(path, 3600)
```

**D-13. 실시간 구독이 작동하지 않는다**

```
원인: Supabase Realtime 미활성화, 잘못된 채널 설정
해결:
1. Supabase → Database → Replication → 해당 테이블 Realtime 활성화
2. 채널 이름 중복 여부 확인 (같은 채널명 중복 구독 불가)
3. 컴포넌트 언마운트 시 채널 정리 확인:
   return () => { supabase.removeChannel(channel); };
```

**D-14. 카카오 로그인 후 콜백 오류가 발생한다**

```
원인: Redirect URI 불일치
해결:
1. 카카오 개발자 콘솔 → 내 애플리케이션 → 카카오 로그인
   → Redirect URI에 https://[프로젝트ID].supabase.co/auth/v1/callback 추가
2. Supabase → Authentication → URL Configuration
   → Redirect URLs에 앱 도메인 추가
```

**D-15. DB 연결 오류 (connection pool exhausted)**

```
원인: 동시 연결 수 초과 (무료 플랜: 60개 제한)
해결:
1. Supabase → Database → Settings → Connection Pooling 활성화
2. 연결 문자열을 Transaction mode (포트 6543)로 변경
3. Edge Function에서 매 요청마다 새 클라이언트 생성 지양
   → 모듈 레벨에서 한 번만 생성
```

**D-16. 마이그레이션 실행 후 앱이 깨진다**

```
해결 순서:
1. Supabase → SQL Editor에서 down 마이그레이션 실행 (롤백)
2. 오류 내용 확인 후 마이그레이션 스크립트 수정
3. 스테이징 환경에서 먼저 테스트
4. 프로덕션 적용 시 서비스 점검 공지 후 진행
```

## D.4 배포·성능 문제 (22~30)

**D-22. Vercel 빌드가 실패한다**

```
해결 순서:
1. Vercel → 해당 배포 → Build Logs 확인
2. 가장 흔한 원인:
   - 환경변수 누락 → Vercel → Settings → Environment Variables 확인
   - TypeScript 오류 → 로컬에서 npm run build 실행 후 오류 수정
   - 의존성 오류 → package.json의 버전 충돌 확인
3. 로컬 빌드 성공 후 푸시하는 습관 권장
```

**D-23. 페이지 로딩이 3초 이상 걸린다**

```
진단 및 해결:
1. Chrome DevTools → Network 탭 → 가장 큰 파일 확인
2. 번들 분석: npm run build → dist/ 폴더 크기 확인
   vite-bundle-visualizer 설치 후 분석
3. 해결책:
   - 대형 라이브러리 lazy import
   - React.lazy + Suspense로 페이지 분리
   - Supabase 쿼리에 select() 컬럼 제한
```

**D-24. 모바일에서 터치 이벤트가 늦게 반응한다**

```
원인: 300ms 터치 딜레이, 과도한 이벤트 리스너
해결:
1. CSS 추가: html { touch-action: manipulation; }
2. 버튼에 min-height: 44px 보장
3. 드래그 앤 드롭: dnd-kit의 TouchSensor delay 설정 확인
4. 무거운 이벤트 핸들러에 useCallback 적용
```

**D-25. 앱이 로그아웃 없이 사용자를 로그아웃시킨다**

```
원인: JWT 만료, Supabase 세션 갱신 실패
해결:
1. Supabase 클라이언트 초기화 시 autoRefreshToken: true 확인
2. 네트워크 오류로 갱신 실패 → 재로그인 유도 UI 추가
3. JWT 만료 시간 확인: Supabase → Auth → JWT expiry
   기본값 3600초(1시간) → 필요 시 7200초로 변경
```

**D-26. Sentry에 너무 많은 노이즈 오류가 잡힌다**

```
해결:
1. Sentry.init의 ignoreErrors에 노이즈 패턴 추가:
   ignoreErrors: [
     'ResizeObserver loop limit exceeded',
     'Network request failed',
     /ChunkLoadError/,
   ]
2. beforeSend에서 필터링 로직 추가
3. Sentry → Issues → "Mark as Ignored" 처리
4. 샘플링 비율 조정: tracesSampleRate: 0.1 (10%만 수집)
```

**D-27. useEffect가 무한 루프를 일으킨다**

```
원인: 의존성 배열에 매 렌더링마다 새로 생성되는 객체/함수 포함
해결:
1. 의존성 배열 확인: 빈 배열 []이면 마운트 시 1회만 실행
2. 객체/배열을 의존성으로 사용 시 useMemo로 메모이제이션
3. 함수를 의존성으로 사용 시 useCallback으로 메모이제이션
4. 러버블 요청: "useEffect 무한 루프 원인을 찾아서 수정해줘"
```

**D-28. 개발 서버(npm run dev)가 시작되지 않는다**

```
해결 순서:
1. 포트 충돌: 8080 포트가 이미 사용 중인지 확인
   lsof -i :8080 (mac) / netstat -ano | findstr :8080 (Windows)
2. node_modules 재설치:
   rm -rf node_modules && npm install
3. Node.js 버전 확인: node --version (18 이상 필요)
4. .env.local 파일 존재 여부 확인
```

**D-29. GitHub 푸시 후 러버블에 반영이 안 된다**

```
원인: 러버블 GitHub 연동 해제 또는 브랜치 불일치
해결:
1. 러버블 에디터 → GitHub 아이콘 → 연결 상태 확인
2. 러버블는 기본 브랜치(main)만 추적
   → 다른 브랜치 변경은 main에 머지 후 반영
3. 러버블 에디터 새로고침 후 "Pull latest changes" 클릭
4. 연결이 끊긴 경우: Settings → Integrations → GitHub 재연결
```

**D-30. Capacitor 앱이 iOS에서 화면이 잘린다**

```
원인: Safe Area (노치/다이나믹 아일랜드) 미대응
해결:
1. index.html <head>에 추가:
   <meta name="viewport" content="viewport-fit=cover">
2. CSS에 추가:
   html { --sat: env(safe-area-inset-top); }
   .header { padding-top: max(16px, var(--sat)); }
   .bottom-nav { padding-bottom: max(16px, env(safe-area-inset-bottom)); }
3. Capacitor 설정: ios/App/App/Info.plist에서
   UIViewControllerBasedStatusBarAppearance → YES
```
