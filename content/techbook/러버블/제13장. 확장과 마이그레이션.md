# 제13장. 확장과 마이그레이션

> _"러버블은 출발점이다. 비즈니스가 성장하면 코드도 함께 성장해야 한다."_

---

## 0) 연결 고리

> 🔗 12장에서 프로덕션 운영의 기반을 완성했습니다. 마지막 장인 13장에서는 러버블 앱이 성공하여 **더 많은 사용자, 더 복잡한 요구사항, 새로운 플랫폼**으로 확장해야 하는 시점에 무엇을 어떻게 해야 하는지를 다룹니다. SEO가 필요하면 Next.js로 마이그레이션하고, 모바일 앱이 필요하면 Capacitor로 iOS·Android 앱을 만들고, 팀이 커지면 전문 개발자와 함께 작업하는 방법을 완성합니다.

---

## 13.1 확장 시점 판단 — 언제 무엇을 해야 하는가

### 1) 러버블 단독으로 충분한 경우 vs 확장이 필요한 경우

러버블은 놀랍도록 많은 것을 처리할 수 있지만, 특정 임계점을 넘으면 확장을 고려해야 합니다:

|상황|러버블 단독|확장 필요|
|---|---|---|
|**사용자 규모**|수천 명 이하|수만 명 이상 (DB 최적화 필요)|
|**SEO 중요도**|낮음 (로그인 필요 서비스)|높음 (콘텐츠·마케팅 사이트)|
|**모바일 앱**|PWA로 충분|앱스토어 등록, 푸시 알림 필요|
|**팀 규모**|1~3인|4인 이상 (코드 리뷰·CI/CD 필요)|
|**복잡한 로직**|단순 CRUD|복잡한 알고리즘·마이크로서비스|
|**규정 준수**|일반 서비스|금융·의료·공공기관 (특수 인증)|

---

### 2) 확장 로드맵 3단계

```
[러버블 앱 성장 로드맵]

Stage 1: MVP (0~1,000 사용자)
├── 러버블 단독
├── Supabase Free/Pro 플랜
├── Vercel Hobby/Pro
└── lovable.app 기본 도메인 또는 커스텀 도메인

Stage 2: 성장 (1,000~10,000 사용자)
├── GitHub 연동 + 로컬 개발 병행
├── Supabase Pro + 인덱스 최적화
├── Sentry 에러 모니터링
└── Next.js 마이그레이션 검토 (SEO 필요 시)

Stage 3: 스케일 (10,000+ 사용자)
├── Next.js 전환 또는 독립 백엔드
├── Supabase Pro + DB 연결 풀링(PgBouncer)
├── CDN + 엣지 캐싱
├── Capacitor 모바일 앱 출시
└── 전문 개발팀 합류
```

## 13.2 Supabase 스케일링 — 대규모 트래픽 대응

### 1) 연결 풀링 — PgBouncer 활성화

Supabase는 고동시성 트래픽 처리를 위해 PgBouncer 연결 풀링을 제공합니다. 서버리스 함수나 엣지 함수에서 데이터베이스에 연결할 때는 직접 연결(포트 5432) 대신 연결 풀(포트 6543)을 사용하세요.

```typescript
// src/integrations/supabase/client.ts
// 프로덕션 환경에서 연결 풀 URL 사용

import { createClient } from '@supabase/supabase-js';

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY,
  {
    db: {
      schema: 'public',
    },
    auth: {
      persistSession: true,
      autoRefreshToken: true,
    },
    // 실시간 구독 재연결 설정
    realtime: {
      params: {
        eventsPerSecond: 10,  // 초당 이벤트 제한 (기본값)
      },
    },
  }
);

// Edge Function에서는 Supabase Admin Client 사용
// (서비스 롤 키 + 연결 풀 URL)
// Transaction mode: 각 쿼리마다 연결 반환 (서버리스에 최적)
// SUPABASE_DB_URL = postgresql://postgres:[비밀번호]@[프로젝트].pooler.supabase.com:6543/postgres?pgbouncer=true
```

### 2) Supabase 주요 성능 지표 모니터링

```
Supabase 대시보드 → Reports에서 확인:

① Database Health
   - CPU 사용률 (80% 이상 → 플랜 업그레이드)
   - 메모리 사용률 (90% 이상 → 인덱스 최적화 필요)
   - 활성 연결 수 (최대치 근접 → PgBouncer 활성화)

② API Performance
   - 평균 응답 시간 (500ms 이상 → 쿼리 최적화)
   - 초당 요청 수 (RPS)
   - 캐시 히트율 (낮으면 → staleTime 설정 검토)

③ Auth
   - 일일 활성 사용자(DAU)
   - 로그인 실패율 (높으면 → 브루트포스 방어 강화)
```

### 3) 읽기 복제본(Read Replica) 활용

Supabase Pro 플랜에서 읽기 복제본을 사용하면 읽기 전용 쿼리를 분산하여 주 데이터베이스 부하를 줄일 수 있습니다:

```typescript
// 읽기 복제본 클라이언트 (SELECT 전용)
const supabaseReadOnly = createClient(
  import.meta.env.VITE_SUPABASE_READ_REPLICA_URL,  // 읽기 복제본 URL
  import.meta.env.VITE_SUPABASE_ANON_KEY
);

// 사용 패턴: 읽기는 복제본, 쓰기는 주 DB
const fetchDashboardData = async () => {
  // 대시보드 통계 → 읽기 복제본 (다소 오래된 데이터 허용)
  const { data: stats } = await supabaseReadOnly
    .from('analytics_summary')
    .select('*');

  return stats;
};

const createNewRecord = async (data: any) => {
  // 실제 쓰기 → 주 DB (최신 데이터 보장)
  const { data: result } = await supabase
    .from('records')
    .insert(data);

  return result;
};
```

## 13.3 Next.js 마이그레이션 — SEO와 SSR이 필요할 때

### 1) 마이그레이션이 필요한 시점

러버블이 생성하는 React + Vite 앱은 클라이언트 사이드 렌더링(CSR) 기반의 SPA입니다. 다음 상황에서 Next.js로 마이그레이션하는 것을 진지하게 고려하세요:

|상황|설명|Next.js 해결책|
|---|---|---|
|**SEO 필요**|구글 크롤러가 빈 HTML만 인식|SSR/SSG로 완성된 HTML 제공|
|**초기 로딩 속도**|JS 번들 다운로드 전까지 빈 화면|서버에서 HTML 미리 생성|
|**소셜 공유 미리보기**|OG 태그가 동적으로 변경되어야 할 때|페이지별 메타데이터 서버 생성|
|**API 라우트 필요**|서버리스 API를 앱 내에 통합|`/app/api` 라우트|
|**이미지 최적화**|대량 이미지의 자동 WebP 변환|`next/image` 컴포넌트|

> 📝 **NOTE**
> 
> **마이그레이션이 필요 없는 경우도 많습니다.** 로그인이 필수인 SaaS 대시보드, 내부 업무 도구, 인증 후 접근하는 서비스는 SEO가 크게 중요하지 않으므로 React + Vite로도 완전히 충분합니다. Next.js 마이그레이션은 콘텐츠 중심 사이트(블로그, 마케팅 페이지, 이커머스, 디렉토리 서비스 등)에서 가장 큰 효과를 발휘합니다.

---

### 2) 자동화 마이그레이션 도구

러버블 → Next.js 마이그레이션을 자동화하는 여러 도구가 존재합니다. 대표적인 오픈소스 스크립트는 `vite.config.ts` 설정을 `next.config.mjs`로 변환하고, `tsconfig.json`을 Next.js 설정에 맞게 업데이트하며, `src/app/layout.tsx` 루트 레이아웃을 자동 생성합니다.

```bash
# 방법 1: 자동화 마이그레이션 스크립트 (오픈소스)
# https://github.com/sergust/lovable-vite-nextjs-migration

curl -O https://raw.githubusercontent.com/sergust/lovable-vite-nextjs-migration/main/migrate-to-nextjs.js
node migrate-to-nextjs.js

# 방법 2: next-lovable CLI 도구
# https://nextlovable.com (유료, $39~)
npx next-lovable migrate --source ./my-lovable-project

# 방법 3: lovable-nextjs 오픈소스 변환기
# https://github.com/cladjules/lovable-nextjs
npx lovable-nextjs convert ./my-lovable-project
```

### 3) 수동 마이그레이션 — 핵심 변환 포인트

자동화 도구를 사용하더라도 다음 변환 포인트는 반드시 수동으로 확인해야 합니다:

**① React Router → Next.js App Router**

```typescript
// [Before] 러버블 — React Router v6
// src/App.tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';

const App = () => (
  <BrowserRouter>
    <Routes>
      <Route path="/" element={<Index />} />
      <Route path="/about" element={<About />} />
      <Route path="/blog/:slug" element={<BlogPost />} />
    </Routes>
  </BrowserRouter>
);


// [After] Next.js 15 App Router — 파일 기반 라우팅
// src/app/page.tsx          → / 경로
// src/app/about/page.tsx    → /about 경로
// src/app/blog/[slug]/page.tsx → /blog/:slug 경로

// src/app/blog/[slug]/page.tsx
interface Props {
  params: Promise<{ slug: string }>;
}

export default async function BlogPost({ params }: Props) {
  const { slug } = await params;

  // 서버 컴포넌트: 직접 DB 조회 가능 (Supabase Admin 사용)
  const post = await getPostBySlug(slug);

  return (
    <article>
      <h1>{post.title}</h1>
      <div dangerouslySetInnerHTML={{ __html: post.content }} />
    </article>
  );
}

// SEO 메타데이터 동적 생성
export async function generateMetadata({ params }: Props) {
  const { slug } = await params;
  const post = await getPostBySlug(slug);

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      images: [post.thumbnail],
    },
  };
}
```

**② 환경변수 접두사 변경**

```bash
# [Before] Vite — VITE_ 접두사
VITE_SUPABASE_URL=https://...
VITE_SUPABASE_ANON_KEY=eyJ...

# [After] Next.js — NEXT_PUBLIC_ 접두사 (브라우저 노출)
NEXT_PUBLIC_SUPABASE_URL=https://...
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...

# 서버 전용 변수 (브라우저 노출 없음, 접두사 불필요)
SUPABASE_SERVICE_ROLE_KEY=eyJ...
STRIPE_SECRET_KEY=sk_live_...
```

**③ Vite 환경변수 → Next.js 환경변수**

```typescript
// [Before] Vite
const apiUrl = import.meta.env.VITE_API_URL;
const isProd = import.meta.env.PROD;
const isDev = import.meta.env.DEV;

// [After] Next.js
const apiUrl = process.env.NEXT_PUBLIC_API_URL;
const isProd = process.env.NODE_ENV === 'production';
const isDev = process.env.NODE_ENV !== 'production';
```

**④ 'use client' 지시어 — 클라이언트 컴포넌트 표시**

```typescript
// Next.js App Router에서 React 훅을 사용하는 컴포넌트는
// 반드시 'use client' 지시어 추가

'use client';  // ← 이 한 줄이 없으면 useState/useEffect 오류 발생

import { useState, useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';

// 러버블의 모든 컴포넌트는 기본적으로 클라이언트 컴포넌트이므로
// Next.js로 이전 시 'use client'를 추가해야 함
export default function DashboardClient() {
  const [data, setData] = useState(null);
  // ...
}
```

### 4) 마이그레이션 후 배포

Next.js로 마이그레이션한 후에는 Vercel을 통해 배포하는 것이 가장 간단합니다. GitHub 저장소를 Vercel에 연결하고 빌드 설정을 지정하면 `main` 브랜치 푸시 시 자동 배포됩니다.

```bash
# Next.js 빌드 테스트
npm run build  # 오류 없이 완료되어야 함
npm run start  # 프로덕션 서버 로컬 테스트

# Vercel 배포
vercel --prod
```

## 13.4 Capacitor — iOS·Android 앱으로 확장

### 1) Capacitor란?

Capacitor는 기존 웹 프로젝트에 추가하기만 하면 React, Svelte, Vue 등 선호하는 웹 프레임워크로 만든 프로젝트를 네이티브 모바일 앱으로 변환할 수 있는 오픈소스 크로스플랫폼 런타임입니다.

러버블이 생성한 React + Vite 앱은 별도의 코드 재작성 없이 Capacitor를 통해 iOS·Android 앱으로 변환할 수 있습니다.

|항목|Capacitor|React Native|
|---|---|---|
|**기존 코드 재사용**|✅ 웹 코드 그대로|❌ 처음부터 재작성|
|**러버블 호환**|✅ 완벽 호환|❌ 별도 프로젝트 필요|
|**네이티브 성능**|🟡 WebView 기반|✅ 네이티브 컴포넌트|
|**앱스토어 등록**|✅ 가능|✅ 가능|
|**학습 곡선**|🟢 낮음 (웹 지식 그대로)|🔴 높음|
|**2025 추천 용도**|기존 웹앱 → 모바일|네이티브 퍼포먼스 앱|

---

### 2) Capacitor 설치 및 초기 설정

**사전 조건:**

- iOS 빌드: macOS + Xcode 15+
- Android 빌드: Android Studio + JDK 17+

```bash
# 1. 러버블 프로젝트를 GitHub에서 로컬로 클론
git clone https://github.com/[사용자명]/[프로젝트명].git
cd [프로젝트명]
npm install

# 2. Capacitor 코어 및 CLI 설치
npm install @capacitor/core
npm install -D @capacitor/cli

# 3. 플랫폼 패키지 설치
npm install @capacitor/ios @capacitor/android

# 4. Capacitor 초기화
npx cap init

# 대화형 프롬프트:
# App name: WriteFlow           (앱 이름)
# App Package ID: com.writeflow.app  (고유 번들 ID)
# Web asset directory: dist     (빌드 출력 폴더)
```

**`capacitor.config.ts` 생성 확인:**

```typescript
// capacitor.config.ts — 자동 생성됨, 필요 시 수정
import { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.writeflow.app',
  appName: 'WriteFlow',
  webDir: 'dist',              // Vite 빌드 출력 폴더
  server: {
    // 개발 중 핫 리로드 (로컬 개발 서버 URL)
    // 배포 시에는 이 옵션을 제거하세요
    // url: 'http://192.168.1.10:8080',
    // cleartext: true,
  },
  plugins: {
    // 플러그인별 네이티브 설정
    PushNotifications: {
      presentationOptions: ['badge', 'sound', 'alert'],
    },
    SplashScreen: {
      launchShowDuration: 2000,
      backgroundColor: '#4F46E5',
      showSpinner: false,
    },
  },
};

export default config;
```

### 3) iOS·Android 플랫폼 추가 및 첫 빌드

```bash
# 앱 빌드 (반드시 먼저 실행)
npm run build

# iOS 플랫폼 추가 (mac 전용)
npx cap add ios

# Android 플랫폼 추가
npx cap add android

# 빌드 결과물을 네이티브 프로젝트에 동기화
npx cap sync

# iOS 프로젝트 Xcode로 열기
npx cap open ios

# Android 프로젝트 Android Studio로 열기
npx cap open android
```

**코드 변경 후 업데이트 사이클:**

```bash
# 웹 코드 수정 후 → 빌드 → 동기화
npm run build && npx cap sync

# 또는 한 번에
npm run build && npx cap copy && npx cap sync
```

> ⚠️ **WARNING**
> 
> `npx cap sync`는 웹 빌드 결과물을 네이티브 프로젝트에 복사합니다. 빌드 없이 `sync`만 실행하면 이전 빌드 결과물이 복사됩니다. 코드 변경 후에는 반드시 `npm run build` → `npx cap sync` 순서로 실행하세요.

### 4) 네이티브 기능 플러그인 추가

Capacitor 플러그인을 사용하면 카메라, 푸시 알림, 파일 시스템 등 네이티브 기능에 접근할 수 있습니다:

```bash
# 자주 사용하는 공식 플러그인
npm install @capacitor/push-notifications  # 푸시 알림
npm install @capacitor/camera              # 카메라
npm install @capacitor/geolocation         # GPS
npm install @capacitor/haptics             # 진동 피드백
```

```typescript
// src/hooks/usePushNotifications.ts
import { PushNotifications } from '@capacitor/push-notifications';
import { Capacitor } from '@capacitor/core';

export function usePushNotifications() {
  const registerPush = async () => {
    // 웹 환경에서는 건너뜀
    if (!Capacitor.isNativePlatform()) return;

    // 알림 권한 요청
    const permission = await PushNotifications.requestPermissions();
    if (permission.receive !== 'granted') return;

    // FCM/APNs 등록
    await PushNotifications.register();

    // 토큰 수신 → Supabase에 저장
    PushNotifications.addListener('registration', async (token) => {
      await supabase.from('push_tokens').upsert({
        user_id: (await supabase.auth.getUser()).data.user?.id,
        token: token.value,
        platform: Capacitor.getPlatform(),  // 'ios' | 'android'
      });
    });

    // 알림 수신 처리 (앱 실행 중)
    PushNotifications.addListener('pushNotificationReceived', (notification) => {
      console.log('알림 수신:', notification);
      // 인앱 토스트 표시 등
    });

    // 알림 탭 처리 (앱 백그라운드 or 종료 상태)
    PushNotifications.addListener('pushNotificationActionPerformed', (action) => {
      const data = action.notification.data;
      // 딥링크 처리: 특정 페이지로 이동
      if (data.taskId) {
        window.location.href = `/task/${data.taskId}`;
      }
    });
  };

  return { registerPush };
}
```

## 13.5 GitHub Actions — CI/CD 파이프라인 구축

### 1) 자동화 배포 파이프라인 구성

팀이 커지면 코드 리뷰 → 테스트 → 배포를 자동화하는 CI/CD 파이프라인이 필수입니다:

```yaml
# .github/workflows/deploy.yml
# main 브랜치 푸시 시 자동 빌드·배포

name: Build and Deploy

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설정
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: 의존성 설치
        run: npm ci

      - name: TypeScript 타입 검사
        run: npx tsc --noEmit

      - name: 린트 검사
        run: npm run lint

      - name: 프로덕션 빌드
        run: npm run build
        env:
          VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
          VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_ANON_KEY }}

      - name: Vercel 프로덕션 배포 (main 브랜치만)
        if: github.ref == 'refs/heads/main' && github.event_name == 'push'
        run: |
          npm i -g vercel
          vercel --prod --token=${{ secrets.VERCEL_TOKEN }}
        env:
          VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
```

### 2) PR 미리보기 배포

```yaml
# .github/workflows/preview.yml
# PR 생성 시 스테이징 환경 자동 배포

name: Preview Deployment

on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - run: npm ci
      - run: npm run build
        env:
          VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_STAGING_URL }}
          VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_STAGING_KEY }}

      - name: Vercel 프리뷰 배포
        id: deploy
        run: |
          npm i -g vercel
          PREVIEW_URL=$(vercel --token=${{ secrets.VERCEL_TOKEN }} --json | jq -r '.url')
          echo "url=$PREVIEW_URL" >> $GITHUB_OUTPUT

      - name: PR에 미리보기 URL 댓글 추가
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `🚀 **미리보기 배포 완료**\n\n[${context.payload.pull_request.head.sha.slice(0,7)} 버전 미리보기](${{ steps.deploy.outputs.url }})`
            })
```

## 13.7 러버블의 미래 — 바이브 코딩 생태계 전망

### 1) 2025~2026 러버블 발전 방향

러버블은 단순한 코드 생성 도구를 넘어 완전한 풀스택 개발 플랫폼으로 진화하고 있습니다. 2025년에 도입된 주요 기능을 돌아보면:

- **Supabase Integration 2.0**: 원클릭 연결, Edge Function 로그 자동 표시
- **ElevenLabs 공식 통합**: 음성 기능을 코드 없이 연결
- **Lovable AI 네이티브**: API 키 없이 즉시 AI 기능 추가
- **GitHub 양방향 동기화**: 외부 커밋 실시간 반영
- **Security Advisor**: 보안 취약점 자동 감지

---

### 2) 바이브 코딩의 본질적 가치

이 책 전체를 관통하는 핵심 메시지를 정리합니다:

```
[바이브 코딩이 바꾸는 것]

기존 개발 패러다임:
아이디어 → 기획 → 디자인 → 개발(수개월) → 테스트 → 출시

바이브 코딩 패러다임:
아이디어 → 러버블 프롬프트 → 작동하는 프로토타입(수시간)
         → 사용자 피드백 → 반복 개선 → 출시

변화의 핵심:
- "개발할 수 있느냐"가 아니라 "무엇을 만드느냐"가 경쟁력
- 기술 장벽이 낮아진 만큼 아이디어·도메인 지식이 더 중요해짐
- 전문 개발자는 사라지는 것이 아니라 더 고차원적인 문제에 집중
- 1인 창업자, 비개발자, 도메인 전문가가 직접 제품을 만드는 시대
```

## 🔑 Key Takeaway

> **확장은 두려운 것이 아니라 성공의 증거입니다.**
> 
> 러버블로 MVP를 검증하고, 사용자가 늘면 GitHub CI/CD로 안정성을 높이고, SEO가 필요하면 Next.js로 전환하고, 모바일이 필요하면 Capacitor로 확장하면 됩니다. 이 모든 경로는 러버블이 생성한 표준 React + TypeScript 코드 위에서 자연스럽게 이어집니다. 특정 플랫폼에 종속되지 않는 코드 소유권, 이것이 러버블을 선택해야 하는 가장 강력한 이유입니다.
