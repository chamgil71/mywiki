# 제4장. 프론트엔드 개발 — UI 구성의 모든 것

> _"훌륭한 UI는 사용자가 눈치채지 못하는 것이다. 그냥 작동할 뿐이다."_ — 조나단 아이브(Jony Ive), 전 Apple 수석 디자이너

---

## 0) 연결 고리

> 🔗 3장에서 러버블과 효과적으로 대화하는 방법을 익혔습니다. 이제 그 대화로 만들어지는 결과물, 즉 **프론트엔드(Front-End)** 의 구조와 동작 원리를 이해할 차례입니다. 내부 원리를 알아야 더 정확한 프롬프트를 쓸 수 있고, 생성된 코드를 직접 수정하는 힘도 생깁니다.

---

## 4.1 컴포넌트 기반 사고방식 — React 핵심 개념 속성 코스

### 1) 개념 정의 및 필요성

**컴포넌트(Component)** 는 React 앱을 구성하는 **재사용 가능한 UI 조각**입니다. 레고 블록에 비유하면, 각각의 레고 조각이 컴포넌트이고 완성된 레고 작품이 하나의 페이지입니다.

러버블이 생성하는 모든 코드는 컴포넌트 기반으로 구성됩니다. 이 개념을 이해하면 생성된 코드를 읽고 수정하는 것이 훨씬 쉬워집니다.

---

### 2) 핵심 원리 — 컴포넌트 트리

하나의 페이지는 여러 컴포넌트가 중첩된 **트리(Tree) 구조**로 이루어져 있습니다.

```
App (루트)
├── Header (헤더)
│   ├── Logo
│   └── Navigation
│       ├── NavLink ("홈")
│       ├── NavLink ("서비스")
│       └── NavLink ("문의")
├── MainContent (메인 콘텐츠)
│   ├── HeroBanner (히어로 배너)
│   ├── FeatureList (기능 목록)
│   │   ├── FeatureCard (카드 1)
│   │   ├── FeatureCard (카드 2)
│   │   └── FeatureCard (카드 3)
│   └── CallToAction (행동 유도 버튼)
└── Footer (푸터)
```

위 구조에서 `FeatureCard`는 동일한 컴포넌트를 데이터만 바꿔 3번 재사용하고 있습니다. 이것이 컴포넌트 기반 개발의 핵심 이점입니다.

---

### 3) React 핵심 개념 3가지

러버블 코드를 이해하기 위해 반드시 알아야 할 개념 세 가지입니다.

**① Props — 컴포넌트에 데이터 전달**

Props(Properties)는 부모 컴포넌트가 자식 컴포넌트에게 데이터를 전달하는 방법입니다. HTML의 속성(attribute)과 유사합니다.

```typescript
// FeatureCard 컴포넌트 정의 (자식)
// React 18 + TypeScript 기준
interface FeatureCardProps {
  icon: string;      // 아이콘 이름
  title: string;     // 카드 제목
  description: string; // 설명 텍스트
}

const FeatureCard = ({ icon, title, description }: FeatureCardProps) => {
  return (
    <div className="p-6 bg-white rounded-xl shadow-sm border">
      <span className="text-3xl">{icon}</span>
      <h3 className="text-lg font-bold mt-3">{title}</h3>
      <p className="text-gray-600 mt-2">{description}</p>
    </div>
  );
};

// FeatureList 컴포넌트 (부모) — Props로 데이터 전달
const FeatureList = () => {
  return (
    <div className="grid grid-cols-3 gap-6">
      <FeatureCard icon="⚡" title="빠른 속도" description="밀리초 단위 응답" />
      <FeatureCard icon="🔒" title="강력한 보안" description="엔터프라이즈급 암호화" />
      <FeatureCard icon="📊" title="실시간 분석" description="대시보드 실시간 업데이트" />
    </div>
  );
};
```

**② State — 변하는 데이터 관리**

State(상태)는 컴포넌트 내부에서 **변할 수 있는 데이터**입니다. State가 변하면 React는 해당 컴포넌트를 자동으로 다시 렌더링합니다.

```typescript
// useState 훅으로 상태 관리 예시
import { useState } from "react";

const Counter = () => {
  // count: 현재 값 | setCount: 값을 변경하는 함수
  const [count, setCount] = useState(0); // 초기값: 0

  return (
    <div className="flex items-center gap-4">
      <button
        onClick={() => setCount(count - 1)}
        className="px-4 py-2 bg-red-100 rounded-lg"
      >
        -
      </button>
      <span className="text-2xl font-bold">{count}</span>
      <button
        onClick={() => setCount(count + 1)}
        className="px-4 py-2 bg-green-100 rounded-lg"
      >
        +
      </button>
    </div>
  );
};
```

**③ useEffect — 사이드 이펙트 처리**

useEffect는 컴포넌트가 화면에 표시될 때 실행할 동작(API 호출, 타이머 등)을 정의합니다.

```typescript
// useEffect로 컴포넌트 마운트 시 데이터 불러오기
import { useState, useEffect } from "react";

const UserProfile = ({ userId }: { userId: string }) => {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // userId가 변경될 때마다 실행
    const fetchUser = async () => {
      setLoading(true);
      const response = await fetch(`/api/users/${userId}`);
      const data = await response.json();
      setUser(data);
      setLoading(false);
    };
    fetchUser();
  }, [userId]); // 의존성 배열: userId가 변할 때만 재실행

  if (loading) return <p>로딩 중...</p>;
  return <p>{user?.name}</p>;
};
```

> 📝 **NOTE**
> 
> 러버블 AI는 이 세 가지 개념을 자동으로 적용하여 코드를 생성합니다. 코드를 읽을 때 `useState`가 보이면 "이건 변하는 데이터구나", `useEffect`가 보이면 "이건 외부 데이터를 불러오는 동작이구나"라고 파악하면 됩니다. 깊이 이해하지 못해도 패턴을 인식하는 것으로 충분합니다.

## 4.2 레이아웃 시스템 — Flexbox, Grid, 반응형 디자인

### 1) Tailwind CSS의 레이아웃 핵심 클래스

러버블이 생성하는 모든 레이아웃은 Tailwind CSS의 유틸리티 클래스로 구성됩니다. 자주 쓰이는 핵심 클래스를 이해하면 Visual Edit이나 Code Mode에서 수정이 훨씬 쉬워집니다.

**Flexbox 핵심 클래스**

```
flex          → display: flex (자식 요소를 수평/수직으로 배치)
flex-col      → 세로(수직) 방향으로 배치
items-center  → 수직 방향 가운데 정렬
justify-center→ 수평 방향 가운데 정렬
justify-between → 양 끝에 배치 (헤더 레이아웃에 자주 사용)
gap-4         → 자식 요소 사이 간격 1rem(16px)
flex-1        → 남은 공간 모두 차지
flex-wrap     → 공간 부족 시 다음 줄로 이동
```

**Grid 핵심 클래스**

```
grid          → display: grid
grid-cols-3   → 3열 그리드
grid-cols-1   → 1열 (모바일 기본값으로 자주 사용)
col-span-2    → 2열을 합쳐서 차지
gap-6         → 그리드 셀 사이 간격 1.5rem(24px)
```

**간격·크기 클래스**

```
p-4   → padding: 1rem (내부 여백 모든 방향)
px-6  → padding-left/right: 1.5rem (좌우 여백)
py-3  → padding-top/bottom: 0.75rem (상하 여백)
m-4   → margin: 1rem (외부 여백)
mt-8  → margin-top: 2rem
w-full→ width: 100%
max-w-7xl → max-width: 80rem (페이지 최대 너비 제한)
h-screen  → height: 100vh
```

---

### 2) 반응형 디자인 — Tailwind 브레이크포인트

Tailwind CSS는 접두어(Prefix)로 화면 크기별 스타일을 지정합니다:

|접두어|최소 너비|대상 기기|
|---|---|---|
|(없음)|0px~|모바일 (기본값)|
|`sm:`|640px~|대형 스마트폰|
|`md:`|768px~|태블릿|
|`lg:`|1024px~|노트북|
|`xl:`|1280px~|데스크톱|
|`2xl:`|1536px~|대형 모니터|

```typescript
// 반응형 그리드 레이아웃 예시
// 모바일: 1열 → 태블릿: 2열 → 데스크톱: 3열
<div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6">
  <FeatureCard ... />
  <FeatureCard ... />
  <FeatureCard ... />
</div>

// 반응형 텍스트 크기
// 모바일: 1.5rem → 데스크톱: 3rem
<h1 className="text-2xl lg:text-5xl font-bold">
  안녕하세요
</h1>

// 반응형 표시/숨김
<nav className="hidden md:flex gap-6">  {/* 모바일에서 숨김, 태블릿부터 표시 */}
  <a href="/">홈</a>
  <a href="/about">소개</a>
</nav>
<button className="md:hidden">  {/* 모바일에서만 표시 */}
  ☰ 메뉴
</button>
```

> 💡 **TIP**
> 
> 러버블에 반응형 수정을 요청할 때는 **구체적인 브레이크포인트와 변경 내용을 명시**하면 훨씬 정확한 결과를 얻을 수 있습니다. "모바일에서 잘 보이게 해줘" 대신 "모바일(768px 이하)에서 3열 그리드를 1열로 변경하고, 사이드바는 숨기고 햄버거 버튼을 추가해줘"처럼 구체적으로 작성하세요.

### 3) 자주 쓰이는 레이아웃 패턴

**① 페이지 최대 너비 제한 + 가운데 정렬 (거의 모든 페이지에 사용)**

**② 좌측 사이드바 + 메인 콘텐츠 레이아웃**

```typescript
    <div key={item.id} className="bg-white rounded-xl shadow-sm p-5 border border-gray-100">
      {/* 카드 내용 */}
    </div>
  ))}
</div>
```

## 4.3 Tailwind CSS 완전 활용 — 스타일 커스터마이징

### 1) 색상 시스템 이해

Tailwind의 색상은 `색상이름-숫자` 형식으로 구성됩니다. 숫자가 클수록 어두운 색입니다.

```
bg-blue-50    → 매우 연한 파랑 (배경)
bg-blue-100   → 연한 파랑 (호버 배경)
bg-blue-500   → 중간 파랑
bg-blue-600   → 진한 파랑 (기본 버튼 색)
bg-blue-700   → 더 진한 파랑 (버튼 호버 색)
bg-blue-900   → 매우 진한 파랑 (사이드바 등)

text-gray-400 → 연한 회색 텍스트 (플레이스홀더)
text-gray-600 → 중간 회색 텍스트 (보조 설명)
text-gray-900 → 거의 검정 (본문 텍스트)
```

### 2) 브랜드 색상 커스터마이징 (`tailwind.config.ts`)

러버블 앱에서 브랜드 전용 색상을 설정하려면 `tailwind.config.ts`를 수정합니다:

```typescript
// tailwind.config.ts
import type { Config } from "tailwindcss";

export default {
  content: ["./index.html", "./src/**/*.{ts,tsx}"],
  theme: {
    extend: {
      colors: {
        // 브랜드 전용 색상 정의
        brand: {
          50:  "#EFF6FF",
          100: "#DBEAFE",
          500: "#2563EB",  // 기본 브랜드 색
          600: "#1D4ED8",  // 버튼 호버
          900: "#1E3A5F",  // 다크 배경
        },
        // CSS 변수 연동 (다크 모드 지원)
        primary: "hsl(var(--primary))",
        secondary: "hsl(var(--secondary))",
      },
      fontFamily: {
        // 한국어 폰트 추가
        sans: ["Pretendard", "system-ui", "sans-serif"],
      },
      borderRadius: {
        "4xl": "2rem",
      }
    },
  },
  plugins: [],
} satisfies Config;
```

> 💡 **TIP**
> 
> 러버블에 색상 커스터마이징을 요청할 때는 **Hex 코드를 직접 명시**하세요. "파란색 버튼으로 바꿔줘" 대신 "기본 버튼 색상을 `#2563EB`로, 호버 색상을 `#1D4ED8`로 변경하고, `tailwind.config.ts`의 brand 색상도 함께 업데이트해줘"처럼 구체적으로 요청하면 일관된 색상 시스템이 만들어집니다.

## 4.4 shadcn/ui 컴포넌트 라이브러리 활용

### 1) shadcn/ui란?

러버블, Bolt.new, Vercel의 v0 모두 shadcn/ui를 기반으로 앱을 생성합니다. shadcn/ui는 Radix UI 프리미티브와 Tailwind CSS로 제작된 아름다운 React 컴포넌트 모음으로, 전통적인 의존성 패키지를 설치하는 대신 실제 TypeScript 소스 코드를 프로젝트에 직접 복사하는 혁신적인 방식을 채택했습니다. 덕분에 사용자가 컴포넌트를 완전히 소유하고 마음대로 수정할 수 있습니다.

> 📝 **NOTE**
> 
> **shadcn/ui의 핵심 철학: "소유권(Ownership)"** 일반적인 컴포넌트 라이브러리(Material UI, Ant Design)는 npm 패키지로 설치하여 내부 코드를 직접 수정할 수 없습니다. shadcn/ui는 컴포넌트의 소스 코드 자체를 프로젝트 안에 복사합니다. 러버블이 shadcn/ui를 기본 UI로 채택한 이유도 동일합니다. 생성된 코드를 사용자가 완전히 소유하고 자유롭게 수정할 수 있어야 하기 때문입니다.

---

### 2) 러버블에서 자주 쓰이는 shadcn/ui 컴포넌트

**① Button — 버튼**

```typescript
import { Button } from "@/components/ui/button";

// variant(모양)와 size(크기) props로 다양한 스타일 지원
<Button variant="default">기본 버튼</Button>
<Button variant="destructive">삭제 버튼</Button>   // 빨간색
<Button variant="outline">아웃라인 버튼</Button>
<Button variant="ghost">고스트 버튼</Button>       // 배경 없음
<Button variant="link">링크 버튼</Button>

<Button size="sm">작은 버튼</Button>
<Button size="lg">큰 버튼</Button>
<Button disabled>비활성화</Button>
```

**② Input + Label + Form — 입력 폼**

```typescript
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

<div className="space-y-2">
  <Label htmlFor="email">이메일</Label>
  <Input
    id="email"
    type="email"
    placeholder="name@example.com"
  />
</div>
```

**③ Dialog — 모달 팝업**

```typescript
import {
  Dialog, DialogContent, DialogDescription,
  DialogHeader, DialogTitle, DialogTrigger,
} from "@/components/ui/dialog";
```

## 4.5 Visual Edit 모드 심화 — 클릭으로 UI를 직접 수정하기

### 1) Visual Edit 작동 원리

Visual Edit 모드는 러버블의 독보적인 기능입니다. 텍스트, Tailwind 클래스, 이미지를 쉽게 수정할 수 있어 CSS를 직접 작성할 필요 없이 빠른 디자인 조정이 가능합니다. 단, 데이터베이스에서 동적으로 불러오는 콘텐츠는 시각 편집이 불가능하며, 일부 서드파티 컴포넌트도 직접 수정이 제한될 수 있습니다.

---

### 2) Visual Edit 실전 활용 순서

**① 모드 진입**

채팅 입력창 하단의 **연필 아이콘(✏️)** 을 클릭하면 Visual Edit 모드로 전환됩니다. 미리보기 영역의 요소 위로 마우스를 이동하면 파란색 테두리와 함께 요소가 하이라이트됩니다.

**② 요소 선택 및 수정 패널**

요소를 클릭하면 좌측에 수정 패널이 나타납니다:

|수정 옵션|설명|
|---|---|
|**Text**|텍스트 내용 직접 수정|
|**Classes**|Tailwind 클래스 추가/삭제|
|**Image**|이미지 URL 변경 또는 파일 업로드|
|**Ask AI**|선택한 요소에 대해 AI에게 수정 요청|

**③ 저장**

수정 후 **Save** 버튼 클릭 → 코드에 즉시 반영 (크레딧 소비 없음)

---

### 3) Visual Edit 활용 체크리스트

- [ ] 텍스트 수정 (타이틀, 설명, 버튼 레이블)
- [ ] 색상 변경 (`bg-blue-600` → `bg-indigo-600`)
- [ ] 여백 조정 (`p-4` → `p-6`, `mt-2` → `mt-4`)
- [ ] 폰트 크기 변경 (`text-sm` → `text-base`)
- [ ] 정렬 변경 (`text-left` → `text-center`)
- [ ] 이미지 교체 (URL 직접 입력)
- [ ] 테두리 반경 변경 (`rounded-lg` → `rounded-full`)

> ⚠️ **WARNING**
> 
> Visual Edit으로 Tailwind 클래스를 **직접 수정할 때는 주의**하세요. 예를 들어 `grid-cols-3`을 `grid-cols-4`로 바꾸면 하위 항목 개수에 따라 레이아웃이 깨질 수 있습니다. 레이아웃 관련 클래스 수정은 미리보기에서 결과를 반드시 확인한 후 저장하세요.

### 1) Tailwind CSS 기본 애니메이션

### 2) 페이지 전환 애니메이션 (Framer Motion 없이)

```typescript
// CSS 클래스 조건부 적용으로 슬라이드 인 효과
import { useState, useEffect } from "react";

const AnimatedCard = ({ children }: { children: React.ReactNode }) => {
  const [visible, setVisible] = useState(false);

  useEffect(() => {
    // 컴포넌트 마운트 직후 visible을 true로 변경
    const timer = setTimeout(() => setVisible(true), 50);
    return () => clearTimeout(timer);
  }, []);

  return (
    <div
      className={`transform transition-all duration-500
        ${visible
          ? "opacity-100 translate-y-0"     // 표시 상태
          : "opacity-0 translate-y-4"       // 초기(숨김) 상태
        }`}
    >
      {children}
    </div>
  );
};
```

> 📝 **NOTE**
> 
> 더 복잡한 애니메이션이 필요하다면 **Framer Motion** 라이브러리를 요청할 수 있습니다. 러버블에 "Framer Motion을 사용해서 카드가 아래에서 위로 올라오며 나타나는 애니메이션을 추가해줘"라고 요청하면 자동으로 라이브러리를 추가하고 구현해 줍니다.

## 4.7 실전 사례 3종 — 랜딩 페이지, 대시보드, 포트폴리오

### 사례 1: SaaS 랜딩 페이지

SaaS 서비스의 랜딩 페이지는 다음 섹션 구조로 구성하는 것이 검증된 패턴입니다:

```
[SaaS 랜딩 페이지 표준 구조]

① 헤더 (Header)
   로고 + 네비게이션 + CTA 버튼

② 히어로 섹션 (Hero Section)
   핵심 가치 제안(Value Proposition) + 이미지/데모 + CTA

③ 신뢰 지표 (Social Proof)
   고객사 로고 배열 또는 숫자 통계 (사용자 수, 평점 등)

④ 핵심 기능 소개 (Features)
   3~6개 기능 카드 그리드

⑤ 동작 방식 (How It Works)
   단계별(1→2→3) 프로세스 설명

⑥ 고객 후기 (Testimonials)
   인용문 + 사진 + 이름/직책

⑦ 가격 플랜 (Pricing)
   무료/기본/프로 3단계 비교 카드

⑧ CTA 섹션
   최종 행동 유도

⑨ 푸터 (Footer)
   링크 + 저작권
```

## 4.8 트러블슈팅 & 주의사항

### 흔한 프론트엔드 오류와 해결법

|오류 상황|원인|해결 프롬프트|
|---|---|---|
|화면이 하얗게 비어있음|컴포넌트 렌더링 오류|"콘솔 오류 메시지를 확인하고 수정해줘. 빈 화면이 나타납니다."|
|이미지가 표시 안 됨|잘못된 경로 또는 CORS|"이미지가 표시되지 않습니다. public 폴더의 이미지 경로를 확인해줘."|
|모바일에서 레이아웃 깨짐|반응형 미적용|"375px 모바일 화면에서 레이아웃이 깨집니다. 반응형을 수정해줘."|
|버튼 클릭 이벤트 없음|이벤트 핸들러 누락|"버튼을 클릭해도 아무 반응이 없습니다. onClick 핸들러를 추가해줘."|
|폰트가 적용 안 됨|폰트 로드 실패|"Pretendard 폰트가 적용되지 않습니다. CDN 방식으로 로드해줘."|
|스크롤이 작동 안 함|overflow 설정 문제|"페이지 스크롤이 되지 않습니다. overflow 설정을 확인해줘."|

> ⚠️ **WARNING**
> 
> 러버블에서 `useEffect` 내부에 비동기 함수를 직접 사용하면 **경고(Warning)** 가 발생할 수 있습니다. `useEffect(() => { async function fetch() {...} fetch(); }, [])` 패턴을 사용하거나, 별도의 async 함수를 정의 후 호출하는 방식을 사용하세요. 러버블에 "useEffect 안의 비동기 처리 방식을 올바르게 수정해줘"라고 요청하면 자동으로 수정해 줍니다.
