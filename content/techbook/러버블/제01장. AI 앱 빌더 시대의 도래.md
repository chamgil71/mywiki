---

> 💬 _"소프트웨어는 세계를 집어삼키고 있다. 이제는 AI가 그 소프트웨어를 집어삼키려 한다."_ — Menlo Ventures, 러버블 Series B 투자자 보고서, 2025

---

2023년 여름, 스웨덴의 한 스타트업 CTO가 주말 동안 혼자 만든 오픈소스 도구가 며칠 만에 **GitHub 역대 가장 빠르게 성장하는 저장소**가 되었습니다. "GPT Engineer"라는 이름의 그 도구는 단순한 프롬프트 하나로 전체 소프트웨어 코드를 생성해 내는 실험이었습니다. 그 CTO가 바로 **안톤 오시카(Anton Osika)** 이고, 그 실험이 지금 우리가 배울 **러버블(Lovable)** 의 시작이었습니다.

이 장에서는 러버블의 역사와 철학, 기술적 배경, 그리고 경쟁 도구와의 차이점을 살펴봅니다. 단순히 "어떻게 쓰는지"를 넘어 **"왜 이런 도구가 지금 필요한가"** 를 이해하는 것이 목표입니다.

## 1.1 바이브 코딩(Vibe Coding)이란 무엇인가

### 0) 연결 고리

> 🔗 이 장은 책 전체의 도입부입니다. 러버블이 어떤 맥락에서 등장했는지, 왜 지금 이 도구가 필요한지를 이해하면 이후 실습의 흐름이 훨씬 자연스럽게 이어집니다.

---

### 1) 개념 정의 및 필요성

**바이브 코딩(Vibe Coding)** 은 개발자가 코드를 직접 작성하는 대신, **자연어(Natural Language)** 로 원하는 것을 설명하면 AI 대형 언어 모델(LLM, Large Language Model)이 코드를 자동으로 생성해 주는 소프트웨어 개발 방식입니다.

> 📝 **NOTE**
> 
> 바이브 코딩(Vibe Coding)은 2025년 2월 2일, OpenAI 공동창업자이자 전 Tesla AI 책임자인 **안드레이 카파시(Andrej Karpathy)** 가 X(트위터)에 올린 게시물에서 처음 소개된 용어입니다. 이 게시물은 4,500만 회 이상 조회되며 전 세계 개발자 커뮤니티의 뜨거운 논쟁을 촉발했습니다. 이후 **Collins English Dictionary**는 2025년 올해의 단어로 선정했습니다.

카파시는 당시 게시물에서 이렇게 설명했습니다:

> _"나는 코드가 존재한다는 사실조차 잊은 채, 그냥 '바이브'에 완전히 몸을 맡기는 새로운 코딩 방식을 발견했다. (…) AI에게 말하고, 결과를 보고, 에러 메시지를 그냥 붙여넣으면 대부분 해결된다."_

이 말이 의미하는 것은 간단합니다. 더 이상 Python 문법이나 React 컴포넌트 구조를 외울 필요가 없다는 것입니다. **원하는 결과를 설명하는 것만으로 AI가 코드를 만들어 줍니다.**

---

### 2) 바이브 코딩의 3단계 진화

바이브 코딩은 단순한 유행어가 아닙니다. 소프트웨어 개발의 접근 방식이 다음과 같이 진화하는 흐름의 일부입니다.

|단계|시대|개발 방식|진입 장벽|
|---|---|---|---|
|1단계|~2020|**직접 코딩**: 모든 코드를 개발자가 직접 작성|매우 높음 (5~10년 학습)|
|2단계|2021~2024|**AI 보조 코딩**: GitHub Copilot 등 자동완성|중간 (코드 이해 필요)|
|3단계|2025~|**바이브 코딩**: 자연어 설명만으로 전체 앱 생성|낮음 (아이디어만으로 가능)|

> 💡 **TIP**
> 
> 2026년 기준, 카파시 본인은 "바이브 코딩"이 더욱 발전한 개념인 **"에이전틱 엔지니어링(Agentic Engineering)"** 으로 진화하고 있다고 설명합니다. AI 에이전트가 99%의 코드를 작성하고 인간은 감독과 방향 설정만 담당하는 방식입니다. 러버블의 **Agent Mode**가 바로 이 방향을 향해 진화하고 있습니다.

---

### 3) 바이브 코딩의 한계와 올바른 활용

바이브 코딩이 모든 문제를 해결해 주지는 않습니다. 프로덕션 환경에서의 활용 시 다음과 같은 한계를 반드시 인지해야 합니다.

- 생성된 코드에 **보안 취약점(Security Vulnerability)** 이 포함될 수 있습니다.
- 복잡한 아키텍처 설계나 성능 최적화는 여전히 인간 개발자의 판단이 필요합니다.
- 코드 내부 구조를 이해하지 못한 채 배포하면 유지보수가 어려워집니다.
- AI가 잘못된 방향으로 코드를 생성할 경우, 이를 바로잡으려면 기본적인 개발 지식이 필요합니다.

> ⚠️ **WARNING**
> 
> 2025년 5월, 한 보안 연구에서 러버블로 생성된 1,645개의 웹 애플리케이션 중 170개에서 개인정보 무단 접근을 허용하는 보안 취약점이 발견되었습니다. 이는 Supabase의 **Row Level Security(RLS)** 설정이 누락된 경우가 대부분이었습니다. 이 책에서는 보안 설정을 매우 중요하게 다루며, 해당 내용은 **5.7절**에서 자세히 설명합니다.

### 3) 왜 "GPT Engineer"에서 "Lovable"로 바꿨나?

"GPT"라는 이름은 특정 AI 모델(GPT)에 종속된 유틸리티 도구라는 인상을 주었습니다. 창업자들의 비전은 더 컸습니다. **"누구나 사람들이 사랑하는 소프트웨어를 만들 수 있다(Anyone can create software people love)"** 는 사명을 브랜드 이름에 직접 담고자 했습니다. 리브랜딩 직후 성장이 폭발적으로 가속된 것은 우연이 아닙니다.

## 1.3 러버블이 해결하는 문제 — 기존 개발 방식의 한계

### 0) 연결 고리

> 🔗 러버블의 역사를 알았다면, 이제 이 도구가 구체적으로 어떤 문제를 해결하는지 살펴봅니다.

---

### 1) 기존 개발 방식의 한계

좋은 아이디어를 가진 창업자, 기획자, 디자이너, 마케터가 소프트웨어를 직접 만들지 못하는 이유는 하나입니다. **코드를 모르기 때문입니다.** 기존 방식에서 발생하는 대표적인 고통(Pain Point)은 다음과 같습니다.

- **개발자 채용 비용**: 국내 기준 주니어 개발자 연봉 4,000만~6,000만 원 이상
- **프리랜서 의존성**: 외주 개발 후 수정이 필요할 때마다 추가 비용과 시간 소요
- **MVP 검증 속도**: 아이디어를 테스트하기까지 평균 3~6개월 소요
- **기술 부채(Technical Debt)**: 비전문가가 만든 코드는 확장 시 전면 재개발이 필요한 경우가 많음

러버블은 이 문제를 다음과 같이 해결합니다: **"아이디어를 설명하는 것만으로 프로덕션 수준의 풀스택 앱을 몇 분 안에 생성."**

> 💡 **TIP**
> 
> One Love Foundation은 러버블로 모금 웹사이트를 제작하여 개발 외주 비용 없이 목표액 150%인 $15만 달러를 모금했습니다. "코드 한 줄도 몰라도 됐다"는 담당자의 말이 러버블의 가치를 잘 요약합니다.

## 1.4 경쟁 도구 비교: Bolt.new, Cursor, Replit, v0과의 차별점

### 0) 연결 고리

> 🔗 러버블이 해결하는 문제를 알았으니, 이제 유사 도구들과 무엇이 다른지 비교합니다. 도구를 선택할 때 이 비교표가 기준이 됩니다.

---

### 1) 주요 AI 앱 빌더 비교표

|구분|**Lovable**|**Bolt.new**|**Cursor**|**v0 (Vercel)**|**Replit**|
|---|---|---|---|---|---|
|**주요 대상**|창업자·비개발자·개발자|창업자·비개발자|개발자|디자이너·개발자|개발자·학습자|

|**백엔드**|Supabase 완전 통합|제한적|직접 구성|Vercel 종속|자체 호스팅|
|**코드 소유권**|✅ GitHub 연동|✅ 제한적|✅ 완전 소유|✅ 제한적|✅ 가능|

|**추천 상황**|MVP·SaaS·풀스택 앱|빠른 프로토타입|코드 보조·리팩토링|UI 컴포넌트 생성|학습·실험|

---

### 2) 러버블의 핵심 차별점 3가지

**① 프로덕션 수준의 풀스택 생성**

러버블은 단순히 UI 컴포넌트를 만드는 것이 아닙니다. 인증(Auth), 데이터베이스(DB), 파일 스토리지(Storage), 서버리스 함수(Edge Functions)까지 포함한 **완전한 풀스택 앱**을 즉시 생성합니다.

**② Visual Edit 모드**

코드 없이 클릭만으로 UI를 수정할 수 있는 비주얼 편집 기능은 러버블의 독보적인 특징입니다. 디자이너나 기획자가 개발자 없이도 인터페이스를 직접 조정할 수 있습니다.

**③ 완전한 코드 소유권**

노코드(No-Code) 도구들과 달리, 러버블이 생성한 코드는 사용자가 완전히 소유합니다. GitHub에 동기화하고 로컬에서 직접 수정하고 어떤 호스팅 서비스에도 배포할 수 있습니다. **플랫폼 종속성(Vendor Lock-in)이 없습니다.**

> 📝 **NOTE**
> 
> **노코드(No-Code) vs 바이브 코딩의 차이** Bubble, Webflow 같은 노코드 도구는 플랫폼 안에 갇힌 앱을 만듭니다. 플랫폼이 종료되거나 요금을 올리면 이전이 어렵습니다. 반면 러버블이 생성하는 것은 **표준 React + TypeScript 코드**입니다. 언제든지 꺼내 다른 환경에서 실행할 수 있습니다.

## 1.5 러버블의 기술 스택: React, TypeScript, Supabase, Vite

### 0) 연결 고리

> 🔗 러버블을 제대로 활용하려면 내부에서 어떤 기술이 사용되는지 개략적으로 이해해야 합니다. 깊은 지식이 필요하지 않으며, 각 기술의 역할을 파악하는 것으로 충분합니다.

---

### 1) 기술 스택 개요

러버블이 생성하는 앱은 모두 다음 기술 스택을 기반으로 합니다:

```
┌─────────────────────────────────────────────┐
│             러버블 생성 앱 스택               │
├─────────────────────────────────────────────┤
│  프론트엔드  React 18 + TypeScript + Vite    │
│  UI 스타일   Tailwind CSS + shadcn/ui        │
│  백엔드      Supabase (PostgreSQL 기반)       │
│  인증        Supabase Auth                   │
│  스토리지    Supabase Storage                │
│  서버리스    Supabase Edge Functions (Deno)  │
│  배포        lovable.app / Vercel / Netlify  │
└─────────────────────────────────────────────┘
```

---

### 2) 각 기술의 역할

**React 18 (리액트)** 메타(Meta)가 개발한 UI 라이브러리로, 전 세계에서 가장 많이 사용되는 프론트엔드(Front-End) 프레임워크입니다. 화면을 "컴포넌트(Component)"라는 재사용 가능한 조각으로 나눠 관리합니다.

**TypeScript (타입스크립트)** JavaScript에 타입(Type) 시스템을 추가한 언어입니다. 코드 작성 시 오류를 미리 잡아주어 안정성이 높습니다. 러버블은 기본적으로 TypeScript로 코드를 생성합니다.

**Vite (비트)** 차세대 빌드 도구로, 개발 서버 시작 속도가 기존 Create React App 대비 10~100배 빠릅니다. 러버블 앱의 개발 환경은 Vite 기반으로 구성됩니다.

**Tailwind CSS (테일윈드 CSS)** 유틸리티 클래스(Utility Class) 기반의 CSS 프레임워크입니다. `className="flex items-center gap-4 p-6"` 과 같이 HTML 안에 직접 스타일을 지정합니다. 별도의 CSS 파일 없이 빠르게 UI를 구성할 수 있습니다.

**shadcn/ui** 재사용 가능한 React UI 컴포넌트 모음입니다. 버튼, 폼, 다이얼로그, 테이블 등 프로덕션에서 바로 사용할 수 있는 고품질 컴포넌트를 제공합니다.

**Supabase (수파베이스)** 오픈소스 Firebase 대안으로, PostgreSQL 기반의 데이터베이스와 인증, 파일 스토리지, 실시간(Realtime) 기능, 서버리스 함수를 한 번에 제공하는 백엔드 플랫폼입니다. 러버블과 가장 긴밀하게 통합되어 있습니다.

> 💡 **TIP**
> 
> 이 기술들을 지금 당장 모두 공부할 필요는 없습니다. 이 책의 실습을 따라가다 보면 자연스럽게 각 기술의 역할을 체득하게 됩니다. 지금은 "러버블이 이런 믿을 수 있는 기술들 위에서 동작한다"는 사실만 기억해 두세요.

## 1.6 2025년 러버블 주요 업데이트 — Agent Mode, Visual Edit, RAG 디버깅

### 1) Agent Mode (에이전트 모드)

2025년 출시된 Agent Mode는 러버블의 AI가 단순히 코드를 한 번 생성하는 것을 넘어, **여러 단계의 작업을 자율적으로 계획하고 실행**하는 모드입니다. 기능 구현부터 버그 수정, 테스트까지 AI가 스스로 반복하며 처리합니다.

- 복잡한 기능 구현 시 Chat Mode보다 훨씬 완성도 높은 결과 제공
- 단, 크레딧(Credit) 소비가 Chat Mode보다 많음

### 2) Visual Edit 모드

코드 수정 없이 **클릭으로 UI 요소를 직접 선택하여 수정**하는 모드입니다. 텍스트 변경, 색상 수정, 여백 조정 등 디자인 수정에 특화되어 있습니다.

- 디자이너·기획자가 독립적으로 UI를 수정할 수 있음
- AI 크레딧 소비 없이 비주얼 편집 가능

### 3) GitHub 양방향(Bi-directional) 연동

2025년 3월 출시. 러버블 ↔ GitHub 간 코드를 양방향으로 동기화합니다.

- 로컬 VS Code에서 수정한 코드를 러버블에 반영 가능
- 러버블에서 생성한 코드를 GitHub에 자동 커밋

> ⚠️ **WARNING**
> 
> GitHub 연동 후 러버블과 로컬 환경에서 **동시에 같은 파일을 수정**하면 충돌(Conflict)이 발생할 수 있습니다. 양방향 연동 사용 시에는 어느 환경에서 수정할지 명확하게 구분하는 것이 좋습니다. 자세한 내용은 **6.2절**에서 다룹니다.

## 🔑 Key Takeaway

> **러버블은 "노코드 도구"가 아니라 "소유 가능한 프로덕션 코드를 생성하는 AI 풀스택 엔지니어"입니다.** 바이브 코딩의 철학을 기반으로, 아이디어를 자연어로 설명하면 React + TypeScript + Supabase 기반의 완전한 풀스택 앱을 수분 내에 생성합니다. 생성된 코드는 완전히 사용자의 소유이며, 언제든 GitHub으로 내보내거나 직접 수정할 수 있습니다.
