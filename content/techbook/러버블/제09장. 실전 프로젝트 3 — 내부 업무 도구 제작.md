### 2) 내부 도구 vs SaaS — 개발 방식의 차이

내부 도구는 SaaS와 개발 방식이 다릅니다. 이 차이를 이해하면 더 효율적으로 만들 수 있습니다.

|구분|SaaS|내부 도구|
|---|---|---|
|**사용자**|불특정 다수|팀원만 (관리자가 초대)|
|**가입 방식**|누구나 자유 가입|초대 전용 또는 도메인 제한|
|**결제**|필수|불필요 (비용은 회사 부담)|
|**UI 완성도**|높은 기준|기능 중심, 약간의 투박함 허용|
|**보안**|퍼블릭|사내망·IP 제한 가능|
|**배포 속도**|신중|빠른 이터레이션 가능|

> 📝 **NOTE**
> 
> 내부 도구는 **Notion, Jira, Asana 같은 기성 SaaS 도구를 구매하는 대신** 팀의 정확한 워크플로우에 맞게 직접 제작하는 도구입니다. 러버블로 내부 도구를 만드는 가장 큰 이점은 "우리 팀의 용어, 우리 팀의 프로세스, 우리 팀의 데이터 구조"를 그대로 반영할 수 있다는 것입니다. 월 $10~50/인 SaaS 구독료 대신 러버블 구독 하나로 여러 내부 도구를 만들 수 있어 규모가 커질수록 비용 효율이 높아집니다.

```sql

CREATE TABLE teams (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  description TEXT,
  created_by  UUID REFERENCES auth.users NOT NULL,
  created_at  TIMESTAMPTZ DEFAULT NOW()

-- 팀원 테이블 (역할 포함)
CREATE TABLE team_members (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  team_id    UUID REFERENCES teams ON DELETE CASCADE,
  user_id    UUID REFERENCES auth.users ON DELETE CASCADE,
  role       TEXT NOT NULL DEFAULT 'member',  -- 'owner'|'admin'|'member'|'viewer'
  joined_at  TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (team_id, user_id)
);

-- 프로젝트 테이블
CREATE TABLE projects (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  team_id     UUID REFERENCES teams ON DELETE CASCADE,
  name        TEXT NOT NULL,
  description TEXT,
  color       TEXT DEFAULT '#4F46E5',  -- 프로젝트 구분 색상
  status      TEXT DEFAULT 'active',  -- 'active'|'archived'
  created_by  UUID REFERENCES auth.users,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 칸반 컬럼 테이블
CREATE TABLE board_columns (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID REFERENCES projects ON DELETE CASCADE,
  name       TEXT NOT NULL,   -- '할 일', '진행 중', '검토', '완료'
  position   INTEGER NOT NULL, -- 컬럼 순서
  color      TEXT DEFAULT '#94A3B8',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 태스크 테이블
CREATE TABLE tasks (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id    UUID REFERENCES projects ON DELETE CASCADE,
  column_id     UUID REFERENCES board_columns ON DELETE SET NULL,
  title         TEXT NOT NULL,
  description   TEXT,
  assignee_id   UUID REFERENCES auth.users,  -- 담당자
  priority      TEXT DEFAULT 'medium',        -- 'low'|'medium'|'high'|'urgent'
  due_date      DATE,
  position      INTEGER NOT NULL DEFAULT 0,  -- 컬럼 내 순서
  labels        TEXT[],                       -- 태그 배열
  created_by    UUID REFERENCES auth.users,
  created_at    TIMESTAMPTZ DEFAULT NOW(),
  updated_at    TIMESTAMPTZ DEFAULT NOW()
);

-- 댓글 테이블
CREATE TABLE task_comments (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id    UUID REFERENCES tasks ON DELETE CASCADE,
  user_id    UUID REFERENCES auth.users NOT NULL,
  content    TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 활동 로그 테이블 (누가 무엇을 했는지 추적)
CREATE TABLE activity_logs (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  team_id     UUID REFERENCES teams ON DELETE CASCADE,
  user_id     UUID REFERENCES auth.users,
  entity_type TEXT,  -- 'task'|'project'|'member'
  entity_id   UUID,
  action      TEXT,  -- 'created'|'moved'|'assigned'|'completed'
  metadata    JSONB,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);
```

## 9.2 [한국어 특화] 카카오 로그인 완전 구현

### 1) 카카오 로그인이 필요한 이유

국내 팀 내부 도구에서 카카오 로그인을 지원하면 팀원 입장에서 별도 계정 생성 없이 기존 카카오 계정으로 바로 접속할 수 있어 **온보딩 마찰을 크게 줄일 수 있습니다.** 특히 비개발자 팀원이 많은 경우에 효과적입니다.

카카오 로그인 설정은 제5장 5.4절에서 상세히 다뤘습니다. 이 절에서는 TeamBoard에 특화된 UI와 추가 설정에 집중합니다.

### 2) 이메일 도메인 제한 설정 (사내 도구 보안)

팀 내부 도구는 특정 회사 도메인 이메일만 가입할 수 있도록 제한하는 것이 보안상 중요합니다:

```typescript
// src/hooks/useRestrictedAuth.ts
// 특정 도메인만 허용하는 이메일 검증 로직

const ALLOWED_DOMAINS = ['mycompany.com', 'mycompany.co.kr'];

export function useRestrictedAuth() {
  const validateEmailDomain = (email: string): boolean => {
    const domain = email.split('@')[1];
    return ALLOWED_DOMAINS.includes(domain);
  };

  const signUpWithEmailRestriction = async (
    email: string,
    password: string,
    name: string
  ) => {
    // 1차 검증: 프론트엔드
    if (!validateEmailDomain(email)) {
      throw new Error(
        `${ALLOWED_DOMAINS.join(', ')} 도메인 이메일만 가입할 수 있습니다.`
      );
    }

    // 2차 검증은 Supabase Auth Hook (서버 측)에서 수행
    const { error } = await supabase.auth.signUp({
      email,
      password,
      options: { data: { full_name: name } },
    });

    if (error) throw error;
  };

  return { validateEmailDomain, signUpWithEmailRestriction };
}
```

**Supabase 서버 측 도메인 제한 (Auth Hook — 추가 보안):**

```sql
-- Supabase SQL Editor에서 실행
-- 이메일 도메인 화이트리스트 검증 함수

CREATE OR REPLACE FUNCTION public.validate_email_domain()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.email NOT LIKE '%@mycompany.com'
     AND NEW.email NOT LIKE '%@mycompany.co.kr' THEN
    RAISE EXCEPTION '허용되지 않은 이메일 도메인입니다.';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

### 3) 카카오 로그인 후 팀 자동 배정

카카오 로그인 성공 후 팀에 자동으로 배정하는 로직을 구현합니다. 소규모 팀에서는 초대 링크 없이 도메인만 확인한 후 자동 배정하는 방식이 편리합니다:

```typescript
// src/hooks/useOnboarding.ts
// 로그인 후 팀 배정 자동화

import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/hooks/useAuth';
import { useNavigate } from 'react-router-dom';

export function useOnboarding() {
  const { user } = useAuth();
  const navigate = useNavigate();

  const checkAndAssignTeam = async () => {
    if (!user) return;

    // 이미 팀에 속해 있는지 확인
    const { data: membership } = await supabase
      .from('team_members')
      .select('team_id')
      .eq('user_id', user.id)
      .single();

    if (membership) {
      // 이미 팀원 → 대시보드로 바로 이동
      navigate('/dashboard');
      return;
    }

    // 팀이 없으면 온보딩 페이지로
    navigate('/onboarding');
  };

  const joinTeamByInviteCode = async (inviteCode: string) => {
    // 초대 코드로 팀 조회
    const { data: team, error } = await supabase
      .from('teams')
      .select('id, name')
      .eq('invite_code', inviteCode)
      .single();

    if (error || !team) {
      throw new Error('유효하지 않은 초대 코드입니다.');
    }

    // 팀원으로 추가
    await supabase.from('team_members').insert({
      team_id: team.id,
      user_id: user!.id,
      role: 'member',
    });

    navigate('/dashboard');
    return team;
  };

  return { checkAndAssignTeam, joinTeamByInviteCode };
}
```

## 9.3 칸반 보드 — dnd-kit 드래그 앤 드롭 구현

### 1) dnd-kit 선택 이유

드래그 앤 드롭 React 라이브러리의 오랜 선택지였던 `react-beautiful-dnd`는 더 이상 유지보수되지 않으며 향후 개발 계획도 없습니다. 이에 따라 현재 가장 안정적인 대안은 **dnd-kit**입니다.

|항목|dnd-kit|react-beautiful-dnd|
|---|---|---|
|**유지보수**|✅ 활발히 진행 중|❌ 중단(Atlassian)|
|**번들 크기**|~10KB (경량)|~30KB|
|**접근성**|✅ 키보드·스크린 리더 지원|✅ 지원|
|**터치 지원**|✅ 네이티브|제한적|
|**TypeScript**|✅ 완전 지원|✅ 지원|
|**러버블 생성**|자동 사용|더 이상 미권장|

### 3) 칸반 보드 핵심 구조 코드

**① 보드 컨텍스트 설정**

```typescript
// src/components/KanbanBoard.tsx
// dnd-kit v6 기준 칸반 보드 최상위 컴포넌트

import {
  DndContext,
  DragEndEvent,
  DragOverEvent,
  DragOverlay,
  DragStartEvent,
  PointerSensor,
  TouchSensor,
  useSensor,
  useSensors,
} from '@dnd-kit/core';
import { useState, useCallback } from 'react';
import KanbanColumn from './KanbanColumn';
import TaskCard from './TaskCard';
import { useKanbanState } from '@/hooks/useKanbanState';

const KanbanBoard = ({ projectId }: { projectId: string }) => {
  const { columns, tasks, moveTask } = useKanbanState(projectId);
  const [activeTaskId, setActiveTaskId] = useState<string | null>(null);

  // 포인터(마우스) + 터치(모바일) 센서 동시 지원
  const sensors = useSensors(
    useSensor(PointerSensor, {
      activationConstraint: {
        distance: 8,  // 8px 이상 이동해야 드래그 시작 (클릭과 구분)
      },
    }),
    useSensor(TouchSensor, {
      activationConstraint: {
        delay: 200,       // 200ms 길게 누르면 드래그 시작
        tolerance: 5,
      },
    })
  );

  const handleDragStart = useCallback((event: DragStartEvent) => {
    setActiveTaskId(event.active.id as string);
  }, []);

  const handleDragOver = useCallback((event: DragOverEvent) => {
    const { active, over } = event;
    if (!over) return;

    const activeId = active.id as string;
    const overId = over.id as string;

    // 같은 위치면 무시
    if (activeId === overId) return;

    // 드래그 중 다른 컬럼 위로 이동 시 즉시 UI 업데이트 (낙관적 업데이트)
    moveTask(activeId, overId, false);
  }, [moveTask]);

  const handleDragEnd = useCallback(async (event: DragEndEvent) => {
    const { active, over } = event;
    setActiveTaskId(null);

    if (!over) return;

    const activeId = active.id as string;
    const overId = over.id as string;

    // 최종 위치 확정 + DB 저장
    await moveTask(activeId, overId, true);
  }, [moveTask]);

  const activeTask = tasks.find((t) => t.id === activeTaskId);

  return (
    <DndContext
      sensors={sensors}
      onDragStart={handleDragStart}
      onDragOver={handleDragOver}
      onDragEnd={handleDragEnd}
    >
      <div className="flex gap-4 h-full overflow-x-auto pb-4 px-6">
        {columns.map((column) => (
          <KanbanColumn
            key={column.id}
            column={column}
            tasks={tasks.filter((t) => t.column_id === column.id)}
          />
        ))}
      </div>

      {/* 드래그 중인 카드의 고스트(Ghost) 미리보기 */}
      <DragOverlay>
        {activeTask && (
          <TaskCard task={activeTask} isOverlay />
        )}
      </DragOverlay>
    </DndContext>
  );
};
```

### 4) 칸반 상태 관리 훅 — Optimistic Update 포함

```typescript
// src/hooks/useKanbanState.ts
// 낙관적 업데이트(Optimistic Update)로 드래그 시 즉각적인 UI 반응 구현

import { useState, useEffect, useCallback } from 'react';
import { supabase } from '@/integrations/supabase/client';

export function useKanbanState(projectId: string) {
  const [columns, setColumns] = useState<any[]>([]);
  const [tasks, setTasks] = useState<any[]>([]);

  useEffect(() => {
    // 초기 데이터 로드
    const loadBoard = async () => {
      const [{ data: cols }, { data: taskData }] = await Promise.all([
        supabase.from('board_columns')
          .select('*').eq('project_id', projectId).order('position'),
        supabase.from('tasks')
          .select('*, profiles(full_name, avatar_url)')
          .eq('project_id', projectId).order('position'),
      ]);
      if (cols) setColumns(cols);
      if (taskData) setTasks(taskData);
    };
    loadBoard();
  }, [projectId]);

  const moveTask = useCallback(async (
    taskId: string,
    targetId: string,   // 컬럼 ID 또는 다른 태스크 ID
    persist: boolean    // true: DB 저장, false: UI만 업데이트(드래그 중)
  ) => {
    // 대상이 컬럼인지 태스크인지 판별
    const targetColumn = columns.find((c) => c.id === targetId);
    const targetTask = tasks.find((t) => t.id === targetId);

    const newColumnId = targetColumn?.id ?? targetTask?.column_id;

    if (!newColumnId) return;

    // 낙관적 UI 업데이트 (즉시 반영)
    setTasks((prev) => prev.map((t) =>
      t.id === taskId ? { ...t, column_id: newColumnId } : t
    ));

    // DB 저장 (드래그 완료 시만)
    if (persist) {
      const { error } = await supabase.from('tasks')
        .update({ column_id: newColumnId, updated_at: new Date().toISOString() })
        .eq('id', taskId);

      if (error) {
        // DB 저장 실패 시 원래 상태로 복원
        console.error('태스크 이동 저장 실패:', error);
        // 원래 데이터 다시 로드하여 복원
        const { data } = await supabase.from('tasks')
          .select('*').eq('project_id', projectId);
        if (data) setTasks(data);
      }
    }
  }, [columns, tasks, projectId]);

  return { columns, tasks, moveTask };
}
```

> 
> **`react-beautiful-dnd`는 러버블에 사용 요청 시 AI가 자동으로 `dnd-kit`으로 대체하거나 함께 제안합니다.** 직접 `react-beautiful-dnd`를 지정하면 AI가 경고 메시지를 표시할 수 있습니다. 2025년 기준 신규 프로젝트에는 `dnd-kit`을 사용하는 것이 올바른 선택입니다.

## 9.4 실시간 협업 — Supabase Realtime 적용

### 1) 실시간 기능 설계

TeamBoard의 핵심 가치 중 하나는 **팀원이 카드를 이동하면 다른 팀원의 화면에 즉시 반영**되는 실시간 협업입니다. 5장에서 배운 Supabase Realtime을 TeamBoard에 적용합니다.

```typescript
// src/hooks/useRealtimeBoard.ts
// 칸반 보드 실시간 동기화

import { useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';

export function useRealtimeBoard(
  projectId: string,
  onTaskChange: (payload: any) => void
) {
  useEffect(() => {
    const channel = supabase
      .channel(`board-${projectId}`)
      // 태스크 변경 구독 (INSERT, UPDATE, DELETE 모두)
      .on('postgres_changes', {
        event: '*',
        schema: 'public',
        table: 'tasks',
        filter: `project_id=eq.${projectId}`,
      }, (payload) => {
        onTaskChange(payload);
      })
      // 댓글 구독
      .on('postgres_changes', {
        event: 'INSERT',
        schema: 'public',
        table: 'task_comments',
      }, (payload) => {
        onTaskChange({ ...payload, type: 'comment' });
      })
      .subscribe();

    return () => { supabase.removeChannel(channel); };
  }, [projectId, onTaskChange]);
}
```

### 2) 실시간 팀원 현황 — "지금 누가 접속 중"

Supabase의 **Presence(프레즌스)** 기능을 사용하면 현재 접속 중인 팀원 목록을 실시간으로 표시할 수 있습니다:

```typescript
// src/hooks/useTeamPresence.ts
// 실시간 팀원 접속 현황 (Supabase Presence API)

import { useState, useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/hooks/useAuth';

interface OnlineMember {
  user_id: string;
  name: string;
  avatar_url?: string;
  current_page?: string;  // 현재 보고 있는 프로젝트
  online_at: string;
}

export function useTeamPresence(teamId: string) {
  const [onlineMembers, setOnlineMembers] = useState<OnlineMember[]>([]);
  const { user } = useAuth();

  useEffect(() => {
    if (!user) return;

    const channel = supabase.channel(`team-presence-${teamId}`, {
      config: { presence: { key: user.id } },
    });

    channel
      // 내 상태 브로드캐스트
      .on('presence', { event: 'sync' }, () => {
        const state = channel.presenceState<OnlineMember>();
        const members = Object.values(state).flat();
        setOnlineMembers(members);
      })
      .subscribe(async (status) => {
        if (status === 'SUBSCRIBED') {
          // 접속 시 내 정보 전송
          await channel.track({
            user_id: user.id,
            name: user.user_metadata?.full_name || '익명',
            avatar_url: user.user_metadata?.avatar_url,
            online_at: new Date().toISOString(),
          });
        }
      });

    return () => { supabase.removeChannel(channel); };
  }, [teamId, user]);

  return { onlineMembers };
}
```

```typescript
import { useState, useEffect } from 'react';
import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/hooks/useAuth';

type TeamRole = 'owner' | 'admin' | 'member' | 'viewer' | null;

export function useTeamRole(teamId: string) {
  const [role, setRole] = useState<TeamRole>(null);
  const { user } = useAuth();

  useEffect(() => {
    if (!user || !teamId) return;

    supabase
      .from('team_members')
      .select('role')
      .eq('team_id', teamId)
      .eq('user_id', user.id)
      .single()
      .then(({ data }) => setRole(data?.role as TeamRole ?? null));
  }, [teamId, user]);

  // 편의 메서드
  const canManageMembers = role === 'owner' || role === 'admin';
  const canEditTasks = role === 'owner' || role === 'admin' || role === 'member';
  const canDeleteProject = role === 'owner';
  const isViewer = role === 'viewer';

  return { role, canManageMembers, canEditTasks, canDeleteProject, isViewer };
}
```

## 9.7 활동 로그와 알림 시스템

### 1) 활동 로그 자동 기록 (Supabase Trigger)

```sql
-- 태스크 상태 변경 시 자동으로 activity_logs에 기록하는 트리거

CREATE OR REPLACE FUNCTION log_task_activity()
RETURNS TRIGGER AS $$
BEGIN
  -- 컬럼이 변경된 경우 (태스크 이동)
  IF OLD.column_id IS DISTINCT FROM NEW.column_id THEN
    INSERT INTO activity_logs (team_id, user_id, entity_type, entity_id, action, metadata)
    SELECT
      p.team_id,
      auth.uid(),
      'task',
      NEW.id,
      'moved',
      jsonb_build_object(
        'task_title', NEW.title,
        'from_column', (SELECT name FROM board_columns WHERE id = OLD.column_id),
        'to_column',   (SELECT name FROM board_columns WHERE id = NEW.column_id)
      )
    FROM projects p WHERE p.id = NEW.project_id;
  END IF;

  -- 담당자 변경
  IF OLD.assignee_id IS DISTINCT FROM NEW.assignee_id THEN
    INSERT INTO activity_logs (team_id, user_id, entity_type, entity_id, action, metadata)
    SELECT
      p.team_id, auth.uid(), 'task', NEW.id, 'assigned',
      jsonb_build_object('task_title', NEW.title)
    FROM projects p WHERE p.id = NEW.project_id;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_task_update
AFTER UPDATE ON tasks
FOR EACH ROW EXECUTE FUNCTION log_task_activity();
```

> 💡 **TIP**
> 
> **PostgreSQL 트리거는 러버블 AI에게 직접 요청**할 수 있습니다. "태스크 컬럼이 변경될 때마다 activity_logs에 자동 기록하는 PostgreSQL 트리거를 작성하고 Supabase에 적용해줘"라고 요청하면 SQL을 자동 생성하고 Supabase SQL Editor에서 실행할 준비를 해줍니다. 트리거는 애플리케이션 코드 없이 DB 수준에서 보장되므로 어떤 클라이언트가 데이터를 변경하더라도 반드시 기록됩니다.

## 🔑 Key Takeaway

> **TeamBoard는 러버블로 내부 도구를 만드는 정석 패턴을 보여줍니다.**
> 
> SaaS와 달리 내부 도구는 완성도보다 팀의 실제 워크플로우에 맞는 기능이 우선입니다. dnd-kit으로 직관적인 칸반 드래그 앤 드롭을, Supabase Realtime으로 "지금 누구와 같은 보드를 보고 있는지"를 표현하고, PostgreSQL 트리거로 활동 로그를 자동화하면 기성 SaaS가 따라오지 못하는 맞춤형 경험을 만들 수 있습니다. 카카오 로그인과 이메일 도메인 제한으로 국내 팀에 최적화된 인증 경험도 완성됩니다.
