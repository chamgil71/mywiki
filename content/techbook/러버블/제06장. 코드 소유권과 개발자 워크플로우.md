## 0) 연결 고리

> 🔗 5장에서 Supabase로 백엔드를 완성했습니다. 이제 러버블 안에만 머물지 않고 **코드를 직접 소유하고, 외부 도구와 함께 사용하며, 어디에든 배포**하는 방법을 다룹니다. 러버블이 생성한 코드는 진짜 React + TypeScript 코드입니다. GitHub, VS Code, Cursor, Vercel 등 프로 개발자가 사용하는 모든 도구와 완벽하게 연동됩니다.

## 6.1 생성된 TypeScript/React 코드 구조 완전 이해

### 1) 코드 소유권이란?

**코드 소유권(Code Ownership)** 이란 러버블이 생성한 코드를 플랫폼과 무관하게 자유롭게 꺼내고, 수정하고, 배포할 수 있는 권리입니다. 이것이 러버블을 Webflow, Bubble 같은 노코드 도구와 구분하는 핵심 철학입니다.

|구분|노코드 도구 (Webflow, Bubble)|러버블|
|---|---|---|
|**코드 접근**|❌ 소스 코드 비공개|✅ 완전 공개|
|**외부 편집**|❌ 플랫폼 안에서만 수정|✅ VS Code, Cursor 등 사용 가능|
|**자체 배포**|❌ 플랫폼 호스팅 의존|✅ Vercel, AWS, Netlify 등 자유롭게 배포|
|**플랫폼 이탈**|❌ 이탈 시 서비스 중단|✅ 언제든 독립 운영 가능|
|**기술 스택**|독점 프레임워크|React + TypeScript (표준)|

### 3) 핵심 설정 파일 해설

**`vite.config.ts` — 빌드 도구 설정**

```typescript
// vite.config.ts — 러버블 기본 생성 파일
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react-swc";
import path from "path";

export default defineConfig({
  plugins: [react()],   // React + Fast Refresh 지원
  resolve: {
    alias: {
      // '@/components/...' 형태로 절대 경로 임포트 가능
      "@": path.resolve(__dirname, "./src"),
    },
  },
  server: {
    port: 8080,         // 로컬 개발 서버 포트 (기본 5173 대신 8080)
    host: true,         // 네트워크에서 접근 가능 (모바일 테스트용)
  },
});
```

**`App.tsx` — 라우터 구조 이해**

```typescript
// App.tsx — 페이지 라우팅 구조 (React Router v6)
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { Toaster } from "@/components/ui/toaster";

// 페이지 임포트
import Index from "@/pages/Index";
import Dashboard from "@/pages/Dashboard";
import Login from "@/pages/Login";
import NotFound from "@/pages/NotFound";
import ProtectedRoute from "@/components/ProtectedRoute";

const queryClient = new QueryClient();

const App = () => (
  // TanStack Query: 서버 상태 캐싱·동기화
  <QueryClientProvider client={queryClient}>
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Index />} />
        <Route path="/login" element={<Login />} />
        {/* 보호된 라우트: 로그인 사용자만 접근 */}
        <Route path="/dashboard" element={
          <ProtectedRoute><Dashboard /></ProtectedRoute>
        } />
        {/* 404 페이지 */}
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
    {/* 전역 토스트 알림 */}
    <Toaster />
  </QueryClientProvider>
);

export default App;
```

> 📝 **NOTE**
> 
> 러버블은 서버 상태 관리를 위해 **TanStack Query(React Query)** 를 기본으로 사용합니다. 이 라이브러리는 API 호출 결과를 자동으로 캐싱하고, 동일한 데이터를 여러 컴포넌트에서 요청해도 실제 API 호출은 한 번만 합니다. Supabase 쿼리 결과가 즉시 화면에 반영되는 것도 TanStack Query 덕분입니다.

## 6.2 GitHub 저장소 연결 — 양방향(Bi-directional) 동기화

### 1) 연결의 핵심 원칙

러버블의 GitHub 연결은 단순한 코드 백업이 아닙니다. 연결 후 러버블 에디터와 GitHub 저장소 사이의 코드 변경 사항이 완전히 동기화됩니다. 핵심 규칙은 다음과 같습니다:

- **단일 진실 공급원(Single Source of Truth)**: 연결 후 코드는 러버블이 아닌 GitHub에 저장됩니다.
- **기본 브랜치만 동기화**: 러버블은 현재 저장소의 기본 브랜치(보통 `main`)만 추적합니다. 다른 브랜치에 푸시한 변경 사항은 기본 브랜치에 병합될 때까지 러버블에 나타나지 않습니다.

---

### 2) GitHub 연결 단계별 가이드

**① GitHub 계정 연결 (최초 1회)**

1. 러버블 대시보드 → 우측 상단 **사용자 아이콘 → Settings**
2. **Connectors → GitHub** 탭
3. **"Connect GitHub"** 클릭 → GitHub OAuth 팝업 승인

> ⚠️ **WARNING**
> 
> GitHub 로그인 팝업이 아무 반응 없이 닫힌다면 브라우저가 팝업을 차단한 것입니다. 러버블에 대해 팝업을 허용하도록 브라우저 설정을 변경한 후 다시 시도하세요.

**② 프로젝트를 GitHub에 연결**

1. 러버블 프로젝트 에디터 → 상단 **GitHub 아이콘** 클릭
2. **"Connect to GitHub"** 선택
3. 저장소 이름 입력 (예: `docsense-app`) → **Create Repository**
4. 러버블이 자동으로 저장소를 생성하고 현재 코드를 첫 커밋으로 푸시

---

### 3) 양방향 동기화 동작 방식

```
[러버블 → GitHub]

러버블에서 AI로 코드 생성 / Dev Mode 수정
           ↓
자동으로 GitHub main 브랜치에 커밋·푸시
           ↓
GitHub 커밋 히스토리에 변경 이력 기록
(커밋 메시지: "feat: Add user authentication" 등 자동 생성)


[GitHub → 러버블]

로컬 VS Code / Cursor에서 코드 수정
           ↓
git push origin main
           ↓
수 초 내에 러버블 에디터에 "External Commit" 알림
           ↓
러버블 미리보기가 자동으로 새 코드로 업데이트
```

> 💡 **TIP**
> 
> 프로덕션 환경을 보호하려면 러버블에서 `dev` 브랜치를 생성하여 개발하고, 테스트 완료 후 `main`으로 병합하는 브랜칭 전략을 사용하세요. 러버블 에디터에서 GitHub 아이콘 → 현재 브랜치명 클릭 → "Create new branch"로 `dev` 브랜치를 만들 수 있습니다. 이렇게 하면 개발 중인 코드가 프로덕션에 즉시 반영되지 않습니다.

---

### 4) 기존 GitHub 저장소를 러버블에 가져오기

러버블은 기존 GitHub 저장소를 직접 임포트하는 공식 기능을 제공하지 않습니다. 러버블에서 GitHub로의 내보내기(Export)만 지원합니다. 그러나 다음 우회 방법으로 기존 코드를 러버블에서 사용할 수 있습니다:

```bash
# 방법: 러버블 프로젝트를 GitHub에 연결 후
# 로컬에서 기존 코드로 강제 덮어쓰기

# 1. 러버블 프로젝트를 GitHub에 연결 (위 방법대로)
# 2. 연결된 러버블 저장소를 로컬에 클론
git clone https://github.com/[사용자명]/[러버블-저장소명].git
cd [러버블-저장소명]

# 3. 기존 코드 파일을 이 폴더에 복사 (node_modules 제외)

# 4. 변경사항 커밋·푸시
git add .
git commit -m "Import existing codebase"
git push origin main

# 5. 러버블 에디터 새로고침 → 기존 코드로 업데이트됨
```

## 6.3 Dev Mode 심화 — 러버블 에디터에서 직접 코드 수정

### 1) Dev Mode란?

**Dev Mode(개발자 모드)** 는 러버블 에디터 내에서 AI의 도움 없이 **소스 코드를 직접 수정**할 수 있는 모드입니다. 유료 플랜(Pro 이상)에서 사용 가능하며, 크레딧을 소비하지 않습니다.

---

### 2) Dev Mode 진입 및 사용법

1. 러버블 에디터 우측 미리보기 패널 상단 → **"Code"** 탭 클릭
2. 좌측에 파일 트리가 나타나며 파일 선택 시 에디터에서 직접 수정 가능
3. 수정 후 **자동 저장** → 미리보기 즉시 반영
4. GitHub 연결 시 수정 내용이 자동으로 커밋·푸시됨

---

### 3) Dev Mode에서 자주 하는 작업

**환경변수(.env) 설정**

```bash
# .env.local 파일 (Git에 포함되지 않음 — .gitignore에 등록됨)
# Supabase 연결 정보 (자동 설정됨)
VITE_SUPABASE_URL=https://[프로젝트ID].supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...

# 추가 API 키 (필요 시 직접 추가)
# ⚠️ 프론트엔드 환경변수는 브라우저에 노출됨 — 비밀 키는 Edge Function 사용!
VITE_GOOGLE_MAPS_API_KEY=AIza...
```

**새 npm 패키지 추가 (package.json 수정)**

```json
// package.json에 의존성 추가 후 저장
// 러버블이 자동으로 npm install 실행
{
  "dependencies": {
    "framer-motion": "^11.0.0",  // 애니메이션 라이브러리 추가
    "react-pdf": "^9.0.0",       // PDF 뷰어 추가
    "date-fns": "^3.0.0"         // 날짜 처리 라이브러리
  }
}
```

> 📝 **NOTE**
> 
> Dev Mode에서 `package.json`에 패키지를 추가하면 러버블이 자동으로 설치를 시도합니다. 단, 일부 Node.js 전용 패키지(서버 환경이 필요한 패키지)는 브라우저 환경에서 동작하지 않을 수 있습니다. 패키지 추가 후 미리보기에서 오류가 발생하면 AI 채팅창에 "방금 추가한 [패키지명] 설치 후 오류가 발생했습니다. 브라우저 환경에 맞는 대안을 찾아 수정해줘"라고 요청하세요.

## 6.4 로컬 개발 환경 구축 — VS Code / Cursor 병행 워크플로우

### 1) 로컬 개발이 필요한 상황

다음 상황에서는 로컬 개발 환경을 구축하는 것이 효율적입니다:

- AI 루프가 반복되어 복잡한 버그를 수동으로 수정해야 할 때
- Git 브랜칭·PR(풀 리퀘스트) 기반 팀 협업이 필요할 때
- 러버블이 지원하지 않는 복잡한 npm 패키지 설정이 필요할 때
- CI/CD(지속적 통합/배포) 파이프라인을 구성할 때

---

### 2) 로컬 환경 설정 단계별 가이드

**① 필수 도구 설치**

```bash
# Node.js 18+ 설치 확인
node --version  # v18.0.0 이상이어야 함

# 아직 설치 안 됐다면 → https://nodejs.org (LTS 버전 다운로드)

# Git 설치 확인
git --version

# 선택: VS Code
# 다운로드: https://code.visualstudio.com

# 선택: Cursor (AI 코딩 어시스턴트 내장 VS Code)
# 다운로드: https://cursor.sh
```

**② 러버블 프로젝트를 로컬에 클론**

```bash
# GitHub 저장소 클론
git clone https://github.com/[사용자명]/[프로젝트명].git
cd [프로젝트명]

# 의존성 설치
npm install

# 환경변수 파일 생성 (.env.local은 .gitignore에 포함됨)
cp .env.example .env.local  # 예제 파일이 있는 경우
# 또는 직접 생성:
cat > .env.local << EOF
VITE_SUPABASE_URL=https://[프로젝트ID].supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...
EOF

# 개발 서버 실행
npm run dev
# → http://localhost:8080 에서 앱 실행
```

**③ VS Code 추천 익스텐션 설치**

```
필수 익스텐션:
├── ESLint               → 코드 품질 검사
├── Prettier             → 코드 자동 포맷
├── Tailwind CSS IntelliSense → Tailwind 자동완성
├── TypeScript Hero      → TS 임포트 자동 정리
└── Supabase             → Supabase 연동 지원

선택 익스텐션:
├── GitLens              → Git 히스토리 시각화
├── Error Lens           → 코드 라인에 오류 표시
└── Auto Rename Tag      → HTML/JSX 태그 자동 변경
```

### 3) 러버블 + Cursor 병행 워크플로우

러버블과 Cursor AI를 함께 사용하는 워크플로우는 강력한 개발 경험을 제공합니다. 러버블에서 초기 프로토타입을 빠르게 생성하고, Cursor에서 복잡한 기능을 추가한 뒤, 변경사항을 GitHub에 푸시하면 러버블이 자동으로 동기화합니다.

```
[러버블 + Cursor 최적 워크플로우]

① 러버블에서 빠른 프로토타입 생성
   "랜딩 페이지 + 인증 + 기본 대시보드 레이아웃 만들어줘"
           ↓
② GitHub 연결 → 로컬에 클론
   git clone [저장소 URL]
   npm install && npm run dev
           ↓
③ Cursor에서 복잡한 기능 구현
   - 복잡한 알고리즘 로직
   - 서드파티 라이브러리 세밀한 설정
   - AI 루프로 해결 안 되는 버그 수동 수정
           ↓
④ 변경사항 GitHub에 푸시
   git add . && git commit -m "feat: Add complex feature"
   git push origin main
           ↓
⑤ 러버블 에디터에 "External Commit" 알림 → 자동 동기화
           ↓
⑥ 다시 러버블에서 AI로 UI 개선 반복
```

> 💡 **TIP**
> 
> **Cursor에서 러버블 프로젝트를 임포트하는 가장 빠른 방법**: Cursor를 열고 채팅창에 "이 GitHub 저장소를 임포트하고 로컬에서 실행해줘: [GitHub URL]"을 입력하세요. Cursor Agent가 `git clone`, `npm install`, `npm run dev`까지 자동으로 실행합니다. 이후 변경사항을 푸시하면 러버블에 즉시 반영됩니다.

### 4) 로컬 개발 시 자주 쓰는 npm 명령어

```bash
# 개발 서버 실행 (핫 리로드 포함)
npm run dev

# 프로덕션 빌드 생성 (dist/ 폴더에 생성됨)
npm run build

# 빌드 결과물 로컬에서 미리보기
npm run preview

# TypeScript 타입 오류 검사
npx tsc --noEmit

# 코드 스타일 검사
npm run lint

# 패키지 취약점 검사
npm audit

# Supabase 타입 자동 생성 (스키마 변경 후 실행)
npx supabase gen types typescript --project-id [프로젝트ID] \
  > src/integrations/supabase/types.ts
```

> ⚠️ **WARNING**

## 6.5 Vercel / Netlify 직접 배포

### 1) 왜 자체 배포가 필요한가?

러버블의 기본 `lovable.app` 배포로도 충분한 경우가 많습니다. 그러나 다음 상황에서는 Vercel이나 Netlify로 직접 배포하는 것이 유리합니다:

|상황|이유|
|---|---|
|커스텀 도메인을 Free 플랜에서 사용|러버블 커스텀 도메인은 유료 플랜 전용|
|환경별 배포(dev/staging/prod)|러버블은 단일 환경만 지원|
|고급 CI/CD 파이프라인 구성|GitHub Actions 연동 필요|
|CDN 엣지 최적화|Vercel의 전 세계 엣지 네트워크 활용|
|서버사이드 렌더링(SSR) 필요|Next.js 마이그레이션 시|

---

### 2) Vercel 배포 — 가장 빠른 방법

**① GitHub 저장소 연결로 자동 배포 설정**

1. [https://vercel.com](https://vercel.com/) → GitHub 계정으로 로그인
2. **"New Project"** → 러버블 GitHub 저장소 선택
3. **프레임워크 프리셋**: `Vite` 자동 감지됨
4. **환경변수 설정** (Build Settings → Environment Variables):
    
    ```
    VITE_SUPABASE_URL = https://[프로젝트ID].supabase.coVITE_SUPABASE_ANON_KEY = eyJhbGci...
    ```
    
5. **"Deploy"** 클릭 → 1~2분 후 배포 완료

**② 이후 자동 배포**

```
GitHub main 브랜치에 코드 푸시 (러버블에서 수정 또는 로컬에서 push)
           ↓
Vercel이 자동으로 빌드·배포 감지
           ↓
수 분 내에 새 버전이 프로덕션에 반영
```

---

### 3) Netlify 배포

```bash
# Netlify CLI를 사용한 배포 (선택)
npm install -g netlify-cli

# 로그인
netlify login

# 프로젝트 초기화 (최초 1회)
netlify init

# 수동 배포
npm run build
netlify deploy --prod --dir=dist
```

**또는 GitHub 연동 자동 배포 (권장):**

1. [https://netlify.com](https://netlify.com/) → **"New site from Git"**
2. GitHub 저장소 연결
3. **Build command**: `npm run build`
4. **Publish directory**: `dist`
5. 환경변수 설정 → **"Deploy site"**

---

### 4) `_redirects` 파일 — SPA 라우팅 설정

Netlify에 React Router를 사용하는 SPA를 배포하면 페이지 새로고침 시 404 오류가 발생합니다. 이를 방지하기 위해 `public/_redirects` 파일을 추가합니다:

```bash
# public/_redirects
/*    /index.html   200
```

> 📝 **NOTE**
> 
> Vercel은 Vite 프로젝트의 SPA 라우팅을 자동으로 처리하지만, Netlify는 `_redirects` 파일이 필요합니다. 러버블에 "Netlify 배포를 위한 SPA 라우팅 설정을 추가해줘"라고 요청하면 자동으로 `public/_redirects` 파일을 생성해 줍니다.

## 6.6 팀 협업 워크플로우

### 1) 러버블 팀 워크스페이스 설정

러버블은 모든 플랜에서 무제한 팀원을 초대할 수 있습니다. Business 플랜 이상에서는 역할별 권한 관리가 추가됩니다.

**팀원 초대:**

1. 러버블 대시보드 → **Settings → Workspace → Members**
2. **"Invite Member"** → 이메일 입력 → 초대 발송
3. 초대받은 팀원이 수락하면 동일한 워크스페이스에서 협업 가능

---

### 2) GitHub + 러버블 팀 브랜칭 전략

```
[추천 브랜칭 전략 — 소규모 팀(2~5명)]

main (프로덕션)
  └── dev (개발 통합)
        ├── feature/user-auth (팀원 A)
        ├── feature/payment (팀원 B)
        └── fix/dashboard-bug (팀원 C)

규칙:
1. 러버블 에디터: dev 브랜치에서 작업
2. 로컬 개발: feature/* 브랜치에서 작업 후 dev로 PR
3. dev → main: 테스트 완료 후 PR & 머지
4. main 머지 시: Vercel/Netlify 자동 프로덕션 배포 트리거
```

---

### 3) 협업 시 충돌 방지 규칙

|규칙|설명|
|---|---|
|역할 분리|러버블(AI 작업) vs 로컬(복잡한 로직) 담당자를 구분|
|동시 편집 금지|같은 파일을 러버블과 로컬에서 동시에 수정하면 충돌 발생|
|커밋 전 pull|로컬 작업 시작 전 항상 `git pull origin main` 실행|
|작은 단위 커밋|큰 기능을 한 번에 커밋하지 말고 기능 단위로 분리|
|PR 리뷰|main 브랜치 직접 푸시 금지, PR을 통한 코드 리뷰 필수|

> 💡 **TIP**
> 
> 팀 프로젝트에서 러버블을 사용할 때는 **역할을 명확히 분리**하는 것이 핵심입니다. 기획자·디자이너는 러버블에서 UI 수정과 간단한 기능 추가를 담당하고, 개발자는 로컬에서 복잡한 로직·인프라를 담당하는 방식이 가장 원활하게 작동합니다. 두 역할이 같은 파일을 동시에 수정하면 병합 충돌이 발생합니다.

---

## 🔑 Key Takeaway

> **러버블의 코드 소유권은 선택이 아니라 핵심 가치입니다.** GitHub 양방향 동기화를 통해 러버블은 AI 코드 생성 도구인 동시에 완전한 Git 기반 개발 환경이 됩니다.
> 
> 최적의 워크플로우는 **러버블(속도) + GitHub(협업·버전관리) + Cursor(복잡한 기능) + Vercel(배포)** 의 조합입니다. 각 도구의 강점을 살려 역할을 분담하면 혼자서도, 팀으로도 프로덕션 수준의 앱을 빠르게 만들고 운영할 수 있습니다.
