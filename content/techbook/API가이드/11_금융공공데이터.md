# 11장. 금융공공데이터

> 공공 Open API 가이드북 — 5부. 금융·기업(공공)
> 확인 상태: 추진경과 연혁을 금융위원회 공식 페이지에서 연도별로 직접 확인(2019~2025), 대표 API(금융회사기본정보) 파라미터 공식 확인

| 항목 | 내용 |
|---|---|
| 제공기관 | 금융위원회(총괄), 금융감독원·예금보험공사·산업은행 등 금융공공기관 다수 |
| 접근 경로 | 공공데이터포털(data.go.kr)을 통한 개별 API 활용신청 |
| 별도 포털 | 금융감독원 자체(finlife.fss.or.kr, "금융상품 통합비교공시") |
| 인증 방식 | data.go.kr serviceKey (API마다 개별 신청) |
| 비용 | 무료 |
| 현재 규모(2025.11 기준) | 약 110개 API, 349개 테이블(연혁 누적 합산) |
| 활용 우선순위 | 투자·기업분석 프로젝트의 핵심 축 |

### 0) 연결 고리 (Bridge)

4부가 국가 전체·거시경제 통계였다면, 5부는 금융·기업 개별 데이터입니다. 그 첫 장인 이 장에서, 지난 조사에서 미확인으로 남겨뒀던 문제 하나를 이번에 실제로 풀었습니다 — "왜 '102개 API·335개 테이블'이라는 수치가 문서마다 기준일이 다르게 인용되는가"입니다. 답은 간단했습니다. **이 시스템은 2020년 개방 이후 매년 데이터를 추가해온, 계속 자라는 시스템**이라 어느 시점에 인용했느냐에 따라 수치가 다른 게 당연했습니다.

## 1) 개념 정의 및 필요성

### 1.1 연도별로 정확히 추적되는 확장 역사

**핵심 정의**: 금융위원회는 금융감독원 등 금융공공기관으로부터 데이터를 수집(수집DB) → 표준화·중복제거(개방DB 변환) → 공공데이터포털을 통해 API별 개별 개방하는 절차로 금융공공데이터를 제공합니다.

금융위원회 공식 페이지가 이 확장 과정을 연도별로 정확히 공개하고 있어, 이번에는 추정이 아니라 **실제 누적 수치를 직접 계산**할 수 있었습니다.

| 시점 | 내용 | 추가분(API/테이블) |
|---|---|---|
| 2019년 4월 | 금융공공데이터 개방이 **국가중점데이터사업**으로 선정(행정안전부) | — |
| **2020년 6월 9일** | 금융공공데이터 **최초 개방** — 9개 금융공공기관(금감원·예보·산은·기은·신보·캠코·주금공·예탁원·거래소 등) 참여, 총 4,450만 건 데이터 | 69 API / 250 테이블 |
| 2021년 11월 22일 | 특수법인(거래소·금융협회 등) 데이터 추가 개방 | +18 API / +40 테이블 |
| 2022년 12월 9일 | 개인사업자정보 최초 개방(개요·재무·금융·평가 정보) | +4 API / +8 테이블 |
| 2023년 11월 15일 | 침수차량 진위확인 서비스 등 추가 개방 | +7 API / +14 테이블 |
| 2024년 11월 27일 | 자금조달 공시정보 등 추가 개방 | +4 API / +23 테이블 |
| 2025년 11월 27일 | 주식발행 공시정보, ESG 지수정보 등 추가 개방 | +8 API / +14 테이블 |
| **누적 합계** | | **약 110 API / 349 테이블** |

즉 앞서 다른 조사에서 봤던 "102개 API·335개 테이블"이라는 수치는 **2024년 추가분 반영 직후, 2025년 11월 추가분 반영 직전 시점의 스냅샷**이었을 가능성이 높습니다 — 실제로 위 표의 2024년까지 누적(69+18+4+7+4=102 API, 250+40+8+14+23=335 테이블)이 정확히 그 숫자와 일치합니다. 즉 이건 **오류가 아니라 서로 다른 시점의 정확한 스냅샷**이었던 겁니다.

> **NOTE**: 매년 11월 하순 무렵 새 데이터가 추가되는 패턴이 보입니다(2021.11.22, 2023.11.15, 2024.11.27, 2025.11.27). 정확한 규칙이라고 단정할 근거는 없지만, 연말 즈음 금융위 공공데이터 페이지를 한 번씩 재확인하는 습관을 들이면 새로 열린 API를 놓치지 않을 수 있습니다.

### 1.2 왜 2020년에 갑자기 개방이 시작됐는가

1.1절의 "2019년 4월 국가중점데이터사업 선정"이 직접적인 계기지만, 더 큰 배경도 있습니다. 2020년 6월 문재인 대통령의 디지털 뉴딜 현장방문 발언에서 "디지털 뉴딜은 디지털 경제의 기반이 되는 '데이터 댐'을 만드는 것"이라는 표현이 나온 것으로 확인됩니다 — 7장(국세청 API)에서도 같은 "디지털 뉴딜" 정책이 도입 배경으로 언급됐는데, **2020년 한 해에 국세청 사업자정보 API(7월)와 금융공공데이터(6월)가 거의 동시에 출범**한 것도 이 정책의 일환이었다는 게 확인됩니다.

### 1.3 데이터 품질 개선 사례 — 규모만큼 관리도 중요해진 시스템

2023년 3주년 보도자료에 흥미로운 사례가 있습니다. 기업개요정보가 "기준일자만 다른 동일 데이터가 중복 개방"되어 불필요하게 많아지고 조회시간이 길어지는 문제가 있었는데, 기준일자 기준을 "최초개방일자·최종수정일자"로 바꿔 **1,638만 건 → 90만 건**으로 중복을 제거했습니다. 이건 이 시스템이 단순히 규모만 키운 게 아니라, 실사용 피드백을 받아 품질을 관리하고 있다는 증거입니다 — 다만 반대로 읽으면, **오래된 코드가 "예전엔 1,638만 건이었는데 지금은 90만 건"이라는 걸 모르고 그대로 돌아가면 이상한 결과가 나올 수 있다**는 뜻이기도 합니다.

### 1.4 왜 필요한가

기업의 금융회사 여부·기본정보, 각종 금융 상품·시장 정보를 흩어진 여러 기관 사이트를 돌지 않고 표준화된 API로 조회할 수 있습니다.

## 2) 핵심 원리 및 구조

### 2.1 개방 절차 (공식 확인)

```mermaid
flowchart LR
    A["금융공공기관 데이터"] --> B["수집DB"]
    B --> C["표준화·중복제거"]
    C --> D["개방DB"]
    D --> E["공공데이터포털<br/>개별 API 등재"]
    E --> F["이용자 활용신청 및 호출"]
```

### 2.2 대표 API 예시 — 3장 공통 패턴 재사용 확인

| 항목 | 내용 |
|---|---|
| API명 | 금융위원회_금융회사기본정보 |
| 서비스URL | `http://apis.data.go.kr/1160100/service/GetFnCoBasiInfoService` |
| 오퍼레이션(실제 요청 경로) | `/getFnCoOutl` — 즉 최종 요청 URL은 `.../GetFnCoBasiInfoService/getFnCoOutl` |
| 요청변수 | ServiceKey(필수), pageNo(필수), numOfRows(필수), resultType(필수, xml/json), basDt(기준일자, 선택), crno(법인등록번호, 선택), fncoNm(금융회사명, 선택) |

**실제 확인된 요청 URL 형태**
```
http://apis.data.go.kr/1160100/service/GetFnCoBasiInfoService/getFnCoOutl
  ?serviceKey={키}&pageNo=1&numOfRows=10&resultType=json&basDt=20200408&crno=
```

> **TIP**: 3장에서 정리한 data.go.kr 공통 패턴(`serviceKey`/`pageNo`/`numOfRows`)이 그대로 적용됩니다. 이 API 하나만 배우면 나머지 금융공공데이터 API도 비슷한 방식으로 접근할 수 있습니다.

> **WARNING(구조적 함정)**: data.go.kr 계열 API는 "서비스URL"만으로는 호출이 안 되고, **그 뒤에 실제 기능을 가리키는 오퍼레이션 경로(이 예에서는 `/getFnCoOutl`)를 반드시 붙여야** 합니다. 서비스URL만 복사해서 호출하면 404가 나는 흔한 실수입니다. 같은 `GetFnCoBasiInfoService`라도 기업개요조회(`getFnCoOutl`) 외에 다른 조회 기능이 있다면 별도 오퍼레이션 경로를 쓴다는 것도 함께 기억해두십시오 — 이건 12장(OpenDART)의 "엔드포인트별로 URL이 다르다"는 구조와 본질적으로 같은 패턴입니다.

### 2.3 성격이 다른 "제한적 접근" 시스템 — 혼동 주의

| 시스템 | 성격 | 접근성 | 시작 시점 |
|---|---|---|---|
| 금융공공데이터(data.go.kr 경유) | 표준 Open API | 누구나 셀프서비스 | 2020.6.9 |
| 금융감독원 finlife.fss.or.kr(금융상품 통합비교공시) | 별도 포털, 개인/단체 구분 인증키 | 셀프서비스이나 별도 가입 필요 | — |
| 신용정보원 CreDB(빅데이터 개방시스템) | 비식별화된 대용량 신용정보(약 4,000만 명, 5,000여 금융회사 데이터) | 금융회사·상거래기업·연구소 등 승인 절차 필요 | 2019.6.3 |
| 금융결제원 빅데이터 개방시스템 | 계좌이체 등 결제정보 비식별화 개방 | 분석→개방→결합 3단계 로드맵으로 점진 추진 | 2020년 이후 단계적 |

> **WARNING**: "금융공공데이터"라는 이름만 보고 CreDB·금융결제원 빅데이터까지 셀프서비스로 접근할 수 있다고 가정하면 안 됩니다. 이 둘은 별도 심사·계약이 필요한 시스템입니다. 흥미롭게도 CreDB(2019.6)가 금융공공데이터(2020.6)보다 1년 먼저 시작됐는데, 이건 CreDB가 개인 신용정보라는 훨씬 민감한 데이터를 다루기 때문에 셀프서비스 개방보다 심사 기반 개방을 먼저 시범적으로 시작한 것으로 추정됩니다.

## 3) 코드 예제 및 실행 환경

```python
# fsc_open_data_client.py — 금융공공데이터(data.go.kr 경유) 클라이언트
# v1.0, Python 3.11+, requests 2.x
import requests

BASE_URL = "http://apis.data.go.kr/1160100/service/GetFnCoBasiInfoService/getFnCoOutl"
SERVICE_KEY = "여기에_발급받은_serviceKey"


def get_financial_company_info(fnco_nm: str | None = None, crno: str | None = None) -> dict:
    """금융회사기본정보 조회."""
    params = {
        "ServiceKey": SERVICE_KEY,
        "pageNo": 1,
        "numOfRows": 10,
        "resultType": "json",
    }
    if fnco_nm:
        params["fncoNm"] = fnco_nm
    if crno:
        params["crno"] = crno
    resp = requests.get(BASE_URL, params=params, timeout=10)
    resp.raise_for_status()
    return resp.json()


if __name__ == "__main__":
    print(get_financial_company_info(fnco_nm="한국투자증권"))
```

## 4) 실무 시나리오

- **기업 실체 확인**: 12장(OpenDART) 기업 데이터와 결합해, 상장사가 아닌 금융회사도 기본정보를 확인.
- **개인사업자 신용 분석**: 2022년 12월 개방된 개인사업자정보(개요·재무·금융·평가) API를 활용해, 법인보다 정보가 부족했던 개인사업자의 신용도를 분석하는 서비스에 활용 — 1.1절에서 본 것처럼 이건 "법인에 비해 정보가 부족한 개인사업자에 대한 시장의 데이터 개방 요구"에 대응해 만들어진 것입니다.
- **최신 개방 항목 확인**: 매년 11월 하순 무렵(1.1절 NOTE) 금융위 공공데이터 페이지를 재확인해 새로 열린 API가 있는지 점검.
- **투자 상품 비교**: finlife.fss.or.kr의 금융상품 비교공시 API로 예적금·대출 상품을 자동 비교하는 서비스에 활용.

## 6) 한 줄 요약

> 💡 **Key Takeaway**: "금융공공데이터"는 단일 포털이 아니라 **2020년 6월부터 매년 11월 무렵 꾸준히 확장돼온 API 묶음**입니다. 서로 다른 문서에서 "102개"와 "110개"처럼 다른 숫자가 나온다면, 그건 오류가 아니라 서로 다른 연도의 스냅샷일 가능성이 높습니다.
