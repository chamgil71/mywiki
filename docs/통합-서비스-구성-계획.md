## 1. 현재 상황 분석

### 현재 운영 중인 세 개의 프로젝트

| 프로젝트 | 경로 | 기술 스택 | 현재 배포 |
|---------|------|----------|---------|
| **mywiki** | `C:\ai\mywiki` | Quartz (TypeScript) | Vercel (https://mywiki-khaki.vercel.app/) |
| **dailynews** | `C:\ai\dailynews` | Python + 정적 HTML | 별도 Vercel 배포 |
| **creative-spark** | `C:\ai\creative-spark` | React 18 + Vite | 별도 배포 |

### 각 프로젝트 상세

**mywiki**
- Obsidian(`C:\obsidian`)에서 작성한 노트를 content 폴더로 복사 후 Quartz로 빌드
- GitHub Actions가 자동으로 빌드 → Vercel 배포
- `public/` 폴더가 최종 빌드 결과물

**dailynews**
- Python 스크립트가 매일 자동 실행되어 AI 뉴스 리포트 생성
- 두 가지 출력물 존재:
  - `reports/` 폴더: Markdown 원본 리포트
  - `docs/` 폴더: 변환된 HTML 파일 (app.html, archive.html, YYYY-MM-DD.html)
- GitHub Actions가 매일 02:00 UTC에 자동 실행 후 커밋

**creative-spark**
- React 18 + Vite + Shadcn UI로 만든 웹 앱
- 라우트: `/` (메인), `/guide/:slug` (가이드 상세)
- `bun build` 또는 `vite build` 명령으로 `dist/` 폴더에 빌드

## 3. 통합 방법론 비교

두 가지 통합 방법이 있습니다. 각각의 장단점을 비교합니다.

### 방법 A: Vercel Rewrites (가장 빠른 방법)

```
사용자 브라우저 → mywiki Vercel → 내부적으로 → dailynews Vercel
                               → 내부적으로 → creative-spark Vercel
```

- **장점**: 코드 변경 없이 빠르게 적용 가능
- **단점**: 세 개의 Vercel 프로젝트를 각각 유지해야 함, 성능 저하 가능

### 방법 B: 빌드 타임 통합 (권장 방법)

```
GitHub Actions → 세 프로젝트 모두 빌드 → 하나의 public/ 폴더 → Vercel 배포
```

- **장점**: 단일 배포, 빠른 로딩, 관리 편의성
- **단점**: 초기 설정이 다소 복잡

**이 문서는 방법 B(빌드 타임 통합)를 기준으로 상세 가이드를 제공합니다.**

## 4. dailynews 통합 실행 가이드

### 4.1 통합 방식 선택

dailynews 통합에는 두 가지 세부 방법이 있습니다:

**방법 B-1: HTML 파일 직접 복사 (빠름)**
- dailynews의 `docs/` 폴더(HTML 파일)를 mywiki의 `public/news/` 폴더로 복사
- dailynews의 기존 HTML 디자인이 그대로 유지됨

**방법 B-2: Quartz 콘텐츠로 통합 (권장)**
- dailynews의 Markdown 리포트를 mywiki의 `content/news/` 폴더에 저장
- Quartz의 검색, 백링크, 그래프 뷰 등 모든 기능 사용 가능

아래에서는 두 방법 모두 설명합니다.

---

### 방법 B-1: HTML 파일 직접 복사

**1단계: mywiki의 GitHub Actions 워크플로우 수정**

`C:\ai\mywiki\.github\workflows\deploy.yaml` 파일을 아래 내용으로 교체합니다:

```yaml
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      # 1. mywiki 소스 코드 다운로드
      - name: mywiki 체크아웃
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      # 2. Node.js 설치
      - uses: actions/setup-node@v4
        with:
          node-version: 22

      # 3. mywiki (Quartz) 빌드
      - name: 의존성 설치
        run: npm ci

      - name: Quartz 빌드
        run: npm run build
        # 빌드 결과물이 public/ 폴더에 생성됨

      # 4. dailynews HTML 파일 복사
      - name: dailynews 소스 다운로드
        uses: actions/checkout@v4
        with:
          repository: chamgil71/dailynews   # ← 실제 GitHub 저장소 이름으로 변경
          path: dailynews-source            # 임시 폴더에 다운로드

      - name: dailynews 파일 복사
        run: |
          mkdir -p public/news
          cp -r dailynews-source/docs/* public/news/

      # 5. Vercel 또는 GitHub Pages에 배포
      - uses: actions/upload-pages-artifact@v4
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/deploy-pages@v4
        id: deployment
```

> **주의**: `repository: chamgil71/dailynews` 부분을 실제 GitHub 사용자명/저장소명으로 변경하세요.  
> dailynews 저장소가 **private(비공개)**인 경우 아래 "비공개 저장소 접근 설정" 섹션을 참고하세요.

**2단계: Vercel 라우팅 설정**

`C:\ai\mywiki\vercel.json` 파일을 다음과 같이 수정합니다:

```json
{
  "cleanUrls": true,
  "trailingSlash": false,
  "rewrites": [
    { "source": "/news", "destination": "/news/app.html" },
    { "source": "/news/archive", "destination": "/news/archive.html" },
    { "source": "/news/:date(\\d{4}-\\d{2}-\\d{2})", "destination": "/news/:date.html" }
  ]
}
```

### 방법 B-2: Quartz 콘텐츠로 통합 (권장)

이 방법은 dailynews의 Markdown 리포트를 mywiki의 위키 콘텐츠로 직접 통합합니다.  
검색, 태그, 그래프 뷰 등 Quartz의 모든 기능을 뉴스 리포트에서도 사용할 수 있습니다.

**1단계: dailynews 리포트 템플릿 수정**

`C:\ai\dailynews\templates\daily_report.md` 파일의 상단에 다음 Frontmatter를 추가합니다:

```markdown
---
title: "뉴스 브리핑 - {{ date[:10] }}"
date: {{ date[:10] }}
tags:
  - news
  - daily-brief
draft: false
---
```

> **Frontmatter란?** Markdown 파일 최상단의 `---`로 감싸진 메타데이터 영역입니다.  
> Quartz가 이 정보를 읽어 제목, 날짜, 태그 등을 표시합니다.

**2단계: dailynews GitHub Actions 워크플로우 수정**

`C:\ai\dailynews\.github\workflows\news.yml` 파일에 mywiki 저장소로 파일을 전송하는 단계를 추가합니다:

```yaml
      # 기존 "리포트 + 사이트 + DB 커밋" 단계 이후에 추가
      - name: mywiki에 뉴스 리포트 전송
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.MYWIKI_DEPLOY_TOKEN }}  # 아래 설명 참고
          script: |
            const fs = require('fs');
            const path = require('path');
            
            // 오늘 날짜 리포트 파일 읽기
            const today = new Date().toISOString().slice(0, 10);
            const reportPath = `reports/${today}.md`;
            
            if (!fs.existsSync(reportPath)) {
              console.log('리포트 파일을 찾을 수 없습니다:', reportPath);
              return;
            }
            
            const content = fs.readFileSync(reportPath, 'utf8');
            const encoded = Buffer.from(content).toString('base64');
            
            // mywiki 저장소의 content/news/ 폴더에 파일 생성/업데이트
            const targetPath = `content/news/${today}.md`;
            
            try {
              // 기존 파일이 있으면 SHA 가져오기
              const existing = await github.rest.repos.getContent({
                owner: 'chamgil71',         // ← 실제 GitHub 사용자명으로 변경
                repo: 'mywiki',             // ← 실제 mywiki 저장소명으로 변경
                path: targetPath,
              });
              
              await github.rest.repos.createOrUpdateFileContents({
                owner: 'chamgil71',
                repo: 'mywiki',
                path: targetPath,
                message: `📰 뉴스 리포트 업데이트: ${today}`,
                content: encoded,
                sha: existing.data.sha,
              });
            } catch (e) {
              // 파일이 없으면 새로 생성
              await github.rest.repos.createOrUpdateFileContents({
                owner: 'chamgil71',
                repo: 'mywiki',
                path: targetPath,
                message: `📰 뉴스 리포트 추가: ${today}`,
                content: encoded,
              });
            }
            
            console.log('mywiki에 리포트 전송 완료:', targetPath);
```

**3단계: GitHub Personal Access Token 생성**

방법 B-2에서는 dailynews가 mywiki 저장소에 파일을 직접 쓰기 때문에 권한 토큰이 필요합니다.

1. GitHub 웹사이트 → 우측 상단 프로필 클릭 → **Settings**
2. 좌측 하단 **Developer settings** 클릭
3. **Personal access tokens** → **Tokens (classic)** 클릭
4. **Generate new token (classic)** 클릭
5. 설정:
   - Note: `mywiki-deploy`
   - Expiration: `No expiration` 또는 원하는 기간
   - Scopes: `repo` 체크 (전체 저장소 접근)
6. **Generate token** 클릭 후 토큰 값 복사 (한 번만 표시됨!)

**4단계: GitHub Secrets에 토큰 등록**

1. dailynews 저장소 → **Settings** 탭
2. 좌측 **Secrets and variables** → **Actions** 클릭
3. **New repository secret** 클릭
4. Name: `MYWIKI_DEPLOY_TOKEN`, Value: 3단계에서 복사한 토큰
5. **Add secret** 클릭

**5단계: mywiki에 news 폴더 인덱스 파일 생성**

`C:\ai\mywiki\content\news\index.md` 파일을 새로 만듭니다:

```markdown
---
title: 뉴스 브리핑
tags:
  - news
---

# 뉴스 브리핑

매일 자동으로 수집·분석된 AI/기술 뉴스 리포트입니다.
```

## 5. creative-spark 통합 실행 가이드

### 5.1 creative-spark 코드 수정

creative-spark는 React 앱으로, `/spark/` 경로 아래에서 동작하도록 두 파일을 수정해야 합니다.

**1단계: vite.config.ts 수정**

`C:\ai\creative-spark\vite.config.ts` 파일을 수정합니다:

```typescript
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react-swc";
import path from "path";

export default defineConfig(({ mode }) => ({
  // ↓ 이 줄 추가: /spark/ 경로 아래에서 동작하도록 설정
  base: mode === "production" ? "/spark/" : "/",
  server: {
    host: "::",
    port: 8080,
    hmr: {
      overlay: false,
    },
  },
  plugins: [react()].filter(Boolean),
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "./src"),
    },
    dedupe: ["react", "react-dom", "react/jsx-runtime", "react/jsx-dev-runtime", "@tanstack/react-query", "@tanstack/query-core"],
  },
}));
```

> **base 옵션이란?** Vite에서 앱의 최상위 URL 경로를 설정합니다.  
> `"/spark/"`로 설정하면 모든 JS/CSS 파일 경로가 `/spark/...`로 생성됩니다.

**2단계: App.tsx의 BrowserRouter 수정**

`C:\ai\creative-spark\src\App.tsx` 파일에서 BrowserRouter에 `basename` 추가:

```tsx
// 변경 전
<BrowserRouter>

// 변경 후
<BrowserRouter basename="/spark">
```

> **basename이란?** React Router에게 "내 앱의 기본 URL이 /spark/야"라고 알려줍니다.  
> 이 설정이 없으면 /spark/guide/xxx 같은 링크가 올바르게 동작하지 않습니다.

**3단계: index.html 수정 (선택사항)**

`C:\ai\creative-spark\index.html`에서 타이틀을 변경합니다:

```html
<title>Creative Spark</title>
```

### 5.2 mywiki GitHub Actions 워크플로우에 creative-spark 빌드 추가

`C:\ai\mywiki\.github\workflows\deploy.yaml`에 다음 단계를 추가합니다 (dailynews 복사 이후):

### 5.3 Vercel 라우팅에 creative-spark 추가

`C:\ai\mywiki\vercel.json` 파일을 최종 버전으로 업데이트:

```json

  "rewrites": [
```

## 7. 비공개(Private) 저장소 접근 설정

dailynews 또는 creative-spark 저장소가 GitHub에서 비공개(Private)로 설정되어 있다면  
추가 설정이 필요합니다.

**Personal Access Token을 이용한 방법:**

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. **Generate new token** 클릭
3. Scopes: `repo` 선택 (비공개 저장소 읽기 권한 포함)
4. 생성된 토큰을 복사

5. mywiki 저장소 → Settings → Secrets and variables → Actions
6. **New repository secret** 추가:
   - Name: `REPOS_ACCESS_TOKEN`
   - Value: 복사한 토큰

7. `deploy.yaml`의 `actions/checkout` 단계에 토큰 추가:

```yaml
      - name: dailynews 체크아웃
        uses: actions/checkout@v4
        with:
          repository: chamgil71/dailynews
          path: _dailynews
          token: ${{ secrets.REPOS_ACCESS_TOKEN }}  # ← 추가
```

## 8. Vercel 배포 설정 확인

현재 mywiki는 Vercel을 통해 배포됩니다. GitHub Actions로 빌드된 결과물이  
자동으로 Vercel에 반영되려면 Vercel 프로젝트 설정을 확인해야 합니다.

**Vercel 대시보드에서 확인할 항목:**

1. https://vercel.com 접속 → mywiki 프로젝트 선택
2. **Settings** 탭 → **Build & Development Settings**
3. Framework Preset: `Other` 또는 직접 설정
4. Output Directory: `public`
5. **Git** 탭에서 연결된 저장소 확인

> **Vercel이 GitHub Actions 결과를 사용하는 방법**  
> 현재 `deploy.yaml`은 GitHub Pages에 배포하도록 되어 있습니다.  
> Vercel로만 배포하려면 Vercel의 자체 빌드 파이프라인을 사용하거나  
> GitHub Actions에서 Vercel CLI로 직접 배포할 수 있습니다.

**Vercel CLI를 이용한 직접 배포 방법 (GitHub Actions에서):**

`deploy.yaml`의 deploy 잡을 다음으로 교체:

```yaml
  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: 빌드 결과물 다운로드
        uses: actions/download-artifact@v4
        with:
          name: github-pages
          path: public-extracted

      - name: 압축 해제
        run: |
          cd public-extracted
          tar -xf artifact.tar
          ls -la

      - name: Vercel CLI 설치
        run: npm install -g vercel

      - name: Vercel 배포
        run: vercel --prod --yes
        env:
          VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
          VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
```

**Vercel Secrets 등록 방법:**

1. Vercel 대시보드 → 계정 Settings → Tokens → **Create Token**
2. 생성된 토큰을 mywiki GitHub 저장소의 Secrets에 `VERCEL_TOKEN`으로 등록
3. `VERCEL_ORG_ID`: Vercel Settings → General → Your ID
4. `VERCEL_PROJECT_ID`: mywiki 프로젝트 Settings → General → Project ID

## 11. 트러블슈팅

### Q: GitHub Actions에서 "Repository not found" 오류

저장소 이름이 잘못되었거나 접근 권한이 없는 경우입니다.
- `repository:` 값이 `사용자명/저장소명` 형태인지 확인
- 비공개 저장소인 경우 7번 섹션의 PAT 설정 확인

### Q: creative-spark에서 페이지 새로고침 시 404 오류

`vercel.json`의 SPA 라우팅 설정이 누락된 경우입니다.
```json
{ "source": "/spark/:path*", "destination": "/spark/index.html" }
```
위 줄이 `vercel.json`의 `rewrites`에 포함되어 있는지 확인하세요.

### Q: creative-spark의 이미지/스타일이 깨져 보임

`vite.config.ts`에 `base: "/spark/"` 설정이 없는 경우입니다.  
5.1 섹션을 다시 확인하세요.

### Q: dailynews 페이지에서 CSS/JS가 로드되지 않음

dailynews의 HTML 파일이 절대 경로(`/`)로 리소스를 참조하는 경우 발생합니다.  
`docs/app.html` 파일에서 `href="/"`, `src="/"` 등으로 시작하는 경로가 있다면  
`href="/news/"`, `src="/news/"` 형태로 수정해야 합니다.
